# 祈求身份知晓专项

本目录由独立 QA 维护。当前任务只接身份知晓、指定告知及一次求告的来源合同；详细/后台自然候选调度属于后续 TASK-PRAYER-ORIGINS。准备来源、固定请求或读取 call 的测试不证明自然新局可达。

本轮以事件规则 §14、权能与教团规则 §11、Slice14 的 TASK-PRAYER-KNOWLEDGE 为验收标准；运行必须使用正式 CSV，不替换旧数据或放宽 Catalog 以使测试通过。产物保存在本目录，不覆盖旧 docs/qa 证据。

使用 Python 3.10 以上运行：

```powershell
python -X utf8 tools/prayer-knowledge/verify.py --godot "E:\Program Files\Godot\Godot_v4.7.2-stable_win64.exe"
```

`--probe`只核正式Catalog装载；`--development`将本次诊断独立归档，不覆盖正式`results.json`。正式验收须在实现、测试及所绑定规则冻结后实际运行。受限沙盒无法读取Windows根证书库时，按本项目已获准方式在沙盒外运行同一Godot命令；不更改TLS、不过滤错误。无需`--editor`或`--import`。

| 测试族 | 实际生产/消费 | 必须拒绝或保持的反例 |
| --- | --- | --- |
| Powers DREAM / ORACLE | 实际 Turn 权能成功及深成授原接收人身份取得 | 失败、灾变、取消预览、他人围观、无辨认旧成功/异常标签不授知晓 |
| Prayers PR08 | 实际成功结果完成成员转换后授原求告者知晓 | 生成无向请求不授知晓；失败/准入被拒无成员或身份取得 |
| 指定身份告知 | 既存知情发送人、同域 active 接收人、support/cooperation 及实际通路 | 无原知识、关系、通路、跨域、失能或匿名群体拒绝；普通材料不授神祇身份 |
| 求告来源消费 | 未知仅无向；知情非信徒可定向且仍可无向；每个 occurrence 意向稳定 | 知晓不等于忠诚/信仰；知识更新不升级旧无向卡；未来取得不能补旧 snapshot |
| 当前生命周期 | 切 F、离团、迁移不抹历史；当前 active/域/联系重查 | 死亡保历史但不再有活跃求告；发送者死亡/关系断裂不撤接收知识 |
| 事务与续存 | 真事务失败回滚；当前版本保存恢复保留原身份、call、取得位置及流 | 篡改 identity、knowledge、取得切点、方向、源或索引的脱离坏档拒绝且当前局不变 |

本批Catalog接入新表的有限语法和版本指纹，只证明正式CSV可装载。PlayerSources对尚未接入的CULT schema2消费者继续明确拒绝。专项检查新的空Session不能被失败初始化留下的半成品替换，另有根工程两帧解析/菜单冒烟；两者不证明新局可玩。

测试证据分四层读取：

- **业务知晓生产**：实际Powers DREAM/ORACLE及Prayers PR08的成功/深成/失败/灾变。高阶段世界、实际联系与指定处境是明确夹具，知晓结果由正式业务产生。
- **告知处理者**：实际安装的Events实例核定指定选择，真实World/Turn演化事务授权、接收并去重；共享机会的选中对象由测试明确提供。自动抽样/推进与自然告知可达属于ORIGINS。
- **call消费**：测试World子类在真实演化事务中、首次快照之后调用正式模块，以既存contact验证方向/同源复用/缺前提与采样边界。它不实现自然来源调度；未固定call的复用只证明本模块存储语义，不等于完整候选容量流程或EVENT12B整链通过。
- **保存审计**：实际模块Turn快照往返，以及同时重算封套校验和、同步篡改重复采样证明的坏档。原CULT世界条件为既存夹具；不声称完整新版本Session、跨模块存档迁移或发行耐久性通过。

`verify.py`核完整唯一检查ID、当前源文件前后SHA256、全新输出、实际退出码、进程及Godot日志中的全部ERROR，并实际运行根工程菜单冒烟。顶层`checks`保留raw检查和wrapper检查；`raw`原样留存。每轮在`runs/<唯一目录>`保存原始JSON/日志及字节指纹；开发失败不会被新结果重签。可重生的坏Catalog副本及临时档案放在`.godot/prayer-knowledge/<本轮隔离目录>`。

本专项不跑旧报告回归链、不重写旧QA证据，也不证明完整自然生产、首团/经济平衡、性能预算或真人体验。环境失败与游戏断言失败分别记录，不能把Godot证书错误从失败计数中删除，也不能将它混写成游戏逻辑缺陷。
