# Material transfer component gate

Run from the repository root in host context (the sandbox certificate store emits
an engine ERROR and is not a valid pass):

```powershell
python tools/material-transfer/verify.py --godot 'E:/Program Files/Godot/Godot_v4.7.2-stable_win64.exe' --output tools/material-transfer/runs/<new-unique-directory>
```

Each new directory preserves exact source snapshots, SHA256 input hashes, commands,
exit codes, timing, JSON assertions and raw console/engine logs. Existing failed
runs are historical evidence and must not be edited. The wrapper fails on any
engine ERROR, nonzero exit, failed/missing group or changed input. It runs one
material parse and the existing four material groups, followed by the existing
`tools/anchor-routes/verify.py --shared-core` gate (four anchor groups, seventeen
source core checks and entry menu smoke). It does not run the 166-case graph suite.

The four material groups cover actual dreams, endpoint/possession, current/private
selection, and atomic payment/reception/replay/basis plus existing economy controls.
The fourth also runs production Prayers learn effects against the actual paid
receipt wrapper in a managed component transaction. Only its outer PR04 plan is
controlled; material receipt validation is checked, then the candidate is rolled
back. This is not a full generated prayer-response or full Turn restore claim.
The separate original paid transfer still exercises actual Turn snapshot restore.

Cult, membership, contact, funding, successful RNG and display projection are
explicit prerequisites. The projection includes the real menu `slot` and economy
`awakening_sources` fields; actual Session selectors/actions and GameRoot controls
remain production. Full Session/new-game installation is still rejected by the
PlayerSources schema2 guard. Natural campaign reachability/balance, complete 09A,
future raw producers, full Session saves and visual acceptance are not certified.
There is no package.json/TypeScript/npm dev gate in this Godot project; GDScript
check-only, business assertions and headless runtime smoke are the applicable gates.

Runtime capability descriptions are finite: current eight material families are
`implemented`, twelve future route families `design_only`, four non-transferable
objects `unsupported_material`; 09A is `core_only`, internal transfer and the
limited existing original-learn adapter are `implemented`. No CSV threshold changed.
