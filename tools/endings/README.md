# 正式终局验收协议

入口计划为 `python -X utf8 tools/endings/verify.py --godot "E:\Program Files\Godot\Godot_v4.7.2-stable_win64.exe"`。`--smoke` 只执行当前专项，不写正式证据。正式证据必须在生产源码冻结后实际重跑 Resistance → Events → Anchors → Prayers → Powers → Cults → Fidelity 及九套基础回归，禁止只刷新旧报告来源哈希。

标准来自 `docs/specs/system-progression.md` 第 7–11 节，尤其是当前接触资格、三轮断联边界、第三轮概率锁定，以及死亡/断联/失锚先于终局检定。没有游戏界面，不代替真人策略、叙事或发行验收。

有限验收矩阵（实现中的条目不表示已通过）：

| 组 | 可否证后果 |
| --- | --- |
| 仪式四档 | 真实玩家开始、两次继续并支付；前两轮零终骰；第三轮唯一骰实际产生深成/成功/失败/灾变 |
| 锁定与关注 | 第三轮锁定的概率保持原值；宇宙与星系两端同时占 F，不能轮流关注借资格 |
| 结算优先 | 主体死亡、绑定锚失效、轮末归零或断联期限到达均先于骰；失败/灾变后重新判寂灭 |
| 中断 | 漏付、主动取消、供奉拒付使仪式停止；不退款、不额外附赠创伤 |
| 当前接触 | 活人旧认识、失效/不可达线索、随机未固化 proposal 不续命；正式可执行零信仰接触和有真实对象期限的计划才有效 |
| 断联边界 | 连续第 1/2 轮仍可继续，第 3 轮寂灭；有效恢复清零；后台/撤关注不停止时钟 |
| 封存 | 主动自弃有独立原因；ended 后所有普通操作拒绝且状态不变；回顾纯读并保留原种子、事实与身份 |
| 持久化 | 活动仪式与已结束世界存读一致；重算 checksum 的语义伪造拒绝；阶段故障无半结局/重复骰 |

夹具必须明确区分既存中局条件和本项真实生产结果。当前苏醒由原公式计算，洞见不超过 CSV 上限；正式 Anchors 已安装，不靠旧未证明锚、改门槛或手填仪式完成取得通过。每个随机场景只在首条权威命令前选择一次初始流，之后不重置随机数。

`high_fixture.gd` 使用固定合法蓝本组合及三个域的九个既存锚点，每个都有明确的记忆/契约、人物、机构承认、曾支付锚定和当前绑定来源合同。这些历史记录是披露的中局初态，不称为本项从开局实际玩出的九锚。完整生产校验仍开启；当前 A 由 10 初生 + 20 洞见 + 63 锚贡献 = 93 计算。新的降临开始、两次继续、支付、概率锁定、最终骰和结局均从真实玩家入口执行。

两个不伪造的边界：当前表要求终骰前 A≥90，失败扣 10，灾变扣 20 并损失所选宇宙锚 10，因而同一终骰直接寂灭在本表不可达。实跑失败/灾变后复算并存续；通用二次寂灭分支由静态规则核对。有效仪式锚又要求教团，而活跃/休眠教团排除彻底断联，故不手填断联计数来假造“第三次断联且仍满足仪式条件”；独立验证真实断联期限和第三轮死亡/失锚/归零优先。

包装器单独统计新增 `END-*`、完整 Endings 安装下继承复跑的 22 项 `RES-*`，以及独立父回归链的 660 项。计数不相互冒充。故障用例在真实 Endings commit 完成后注入失败返回，以检验终骰 RNG、断联评估、封存事实与阶段状态全部回滚，而不只是测试空阶段拒绝。

断联基线用正式 assigned 演化。明确初态为全域屏障零、无教团，并以有源 population convert 把既有人口转为无团信众；总人口和活人历史保留。这样既无屏障困境可生成逃离候选，也无无名非信众可提名献身候选，不关闭随机生产者、不删除实际已固化机会。带真实祈求的反例单独加入一个具体背景人物和有效记录；该人物死亡后只能撤掉自己的联系，其他世界继续正常演化。

`END-CONTACT-004` 的拘禁是首条玩家 receipt 前的有源初态合同，通过正式身份命令和事务审计建立；对照释放时刻在原祈求窗口内、晚于窗口、状态来源不匹配，验证预览纯读及资格判断。它不冒称已实跑从拘禁至释放的完整后续链。`END-PRIORITY/upkeep` 在第三轮实际调用经济计划拒付所选宇宙锚，检查休眠、中断及零终骰。

审核边界：机会接收人资格与满 N 后退休释放 N→P 的修复已静态复核；本专项尚无隔离这两个条件的独立端到端反例，不计作已实跑通过。现有高阶初态教团会先提供联系，不能用它掩盖这两个分支。
