# 邪神苏醒 · 制作工作台

这是制作人与设计/开发者共同使用的游戏机制阅读和讨论工具。它不参与正式游戏运行，不改变 Godot 技术选型，也不作为玩法验收门槛。

## 打开

在项目根目录执行：

```sh
python3 tools/producer-console/server.py
```

浏览器打开 `http://127.0.0.1:8765`。只有 Python 3.9+ 标准库和浏览器原生能力，无 npm 安装、外部字体、远端服务或账号。端口冲突时加 `--port 8766`。停止服务用终端 `Ctrl-C`。

离线阅读版位于 [terminal.html](../../docs/game-state/terminal.html)，可在浏览器中直接打开。重新生成：

```sh
python3 tools/producer-console/build.py
```

离线版包含生成时的策划原文与 CSV 快照；阅读无需服务器。离线讨论只存在当前浏览器的本地存储，需主动备份 JSON，再导入项目版。浏览器清理数据或隐私模式可能丢失这些本地记录。项目版的已保存讨论不依赖浏览器存储。

## 七种阅读方式

- **机制全景**：点节点读能力、前置、影响和得失，点箭头读关系；按资源、条件、风险、因果、时序筛选。可平移、缩放、适应窗口。
- **回合时序**：逐阶段查看谁先结算、什么能预支、什么到期仍要发生。
- **因果路线**：沿具体关系读一次介入怎样产生后果。它是规则阅读路径，不是已跑通的游戏录像。
- **内容图鉴**：搜索真实 CSV 行，显示原始字段、稳定编号与相关机制。
- **数值试算**：改变有效锚点、洞见、创伤和教团假设，看当前公式的变化；不修改 CSV，不模拟完整游戏。
- **实施追踪**：按关键行为、结算约定、开发任务和验收场景阅读；按机制、状态或关键词筛选，区分规则覆盖、任务接入和实际通过证据。
- **讨论簿**：对机制、关系、内容条目或追踪编号留下问题、建议、顾虑；筛选处理状态，导出 Markdown 或备份 JSON。

桌面宽窗口显示双栏，窄窗口将详情放在下方；点击对象直接定位详情，“返回当前视图”回到图面。窄窗口下所有导航仍保留文字。

## 与协作者接续

1. 在具体对象上点“在此讨论”，写下期望和判断，保存。保存成功后，项目版立即写入 [feedback.json](../../docs/game-state/feedback.json)。
2. 下次聊天直接说“请处理 DISC-…”，或使用“复制给协作者”。上下文带对象编号、来源路径、记录时版本和当前版本。
3. 协作者先读对应记录与权威规则，检查关联影响，再回应或修改。`open` 是待讨论，`answered` 是已回应，`planned` 是待落实，`archived` 是归档；这些状态不自动授予设计决策或执行权限。
4. 新增或修改方案必须在当轮更新正式任务、依赖、责任与验收，记录 `planBindings` 的版本和具体影响；只做方案也不能把编计划延后（DEC-017）。规则原地维护 spec/CSV，需要时更新决策；复核索引摘要后重建基线。工作台不会把“已回应”或“已编计划”冒充“已实现”。

追踪编号 `REQ-*`（关键行为）、`SET-*`（跨系统结算）、`TASK-*`（开发任务）、`ACC-*`（验收场景）同样可以记录讨论、复制上下文和 URL 定位。机制详情中的“实施追踪”可直接进入相关行为与约定。追踪记录只读；正式修改仍应更新项目中的规则、任务或运行证据。

实施追踪消费 [traceability.json](../../docs/implementation/traceability.json)，由 `tools/implementation/tracking.py` 统一核对引用、任务前置和证据来源。工作台不另算一份“完成度”，也不因为讨论被标为待落实就改变任务状态。报告的“来源指纹匹配”只说明证据绑定文件没有变化，具体检查是否通过仍看场景记录。来源修改后，旧证据会显示过期；离线页面保留生成时的判定，无法自动发现之后的变化。

方案新增未登记、修改后未同步计划、绑定任务没有真实要求／验收连接时，追踪器会报错，并由现有实施视图显示。完整规则及扫描边界见 [方案同步约定](../../docs/implementation/README.md#方案与计划同步约定)。当前分层模拟已登记为七项 planned 任务；教团及相关下游按新增依赖等待，不会因方案文档写完就显示可开工。

当前不含内置聊天模型、自动发信或后台任务。给协作者复制上下文属于用户主动转交；项目内记录可由后续会话直接读取。协作者应保留原议题，追加自己的答复记录并引用原编号，避免覆盖作者原话。编号使用随机 UUID 前缀，跨离线窗口导入不依赖顺序分配；真正的同编号内容冲突会拒绝导入。

## 来源与维护

来源职责、更新协议见 [游戏全貌索引说明](../../docs/game-state/README.md)。摘要维护在 JSON 中，界面不另存游戏规则。点击“更新来源”重新读取当前文件，**不会**替维护者自动确认摘要已同步。

保存采用文件原子替换和版本比较。两个页面同时修改时，后提交者收到冲突提示，当前表单草稿仍留在浏览器；刷新取得最新记录后再保存。导入先验证整批，冲突时不部分写入。只监听 `127.0.0.1`，明确写入还要求同源与当前服务令牌；不会开放读取任意项目文件的路径。

## 校验

```sh
python3 tools/producer-console/verify.py
# 单独检查：
python3 tools/producer-console/test_server.py
node --test tools/producer-console/test_logic.mjs
node --check tools/producer-console/web/app.js
```

`verify.py` 执行 Python 与 JavaScript 测试、语法和编译检查，生成带源码指纹的 [自动验收报告](../../docs/qa/implementation-workbench-results.json)。它不会把浏览器操作或视觉可读性标为已通过，也不将可变任务清单及报告自身纳入工具源码指纹。修改源码后需重新运行才能获得当前证据。

自动检查覆盖目标引用、路径连接、CSV 映射、公式边界、讨论持久化、冲突、错误导入、来源漂移、四类追踪目标、关联筛选、追踪讨论与离线证据封装。运行记录见 [工作台验收](../../docs/qa/producer-console.md)。它们不证明游戏的平衡性、可玩性或美术质量。
