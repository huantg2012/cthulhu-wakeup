# Current Rule Version Save Compatibility

One unmodified formal Session starts with seed 1. Its real bootstrap request is retained over one actual round, answered through `execute_action`, and the same real member produces a successful original dream in the next action window. RNG success is controlled; no material, relationship, request, waiting counter or saved state is injected. The dream's actual miracle and its original person's knowledge represent the minimal material carrier, not a full anchor chain.

The actual `save_game` envelope is restored by a new Session's `continue_game`. Complete original Turn and Session campaign/sequence/knowledge/input fields must match. The original durable dream is retried without any change or second fee; the restored Session then advances to the real next action window. Nonempty relations, material, fixed requests/deadlines and opportunity ledger are included in the legal save.

The rejection group uses three checksum-correct copies: old Session schema, missing knowledge reference, and corrupted cached authoritative response outcome. Each rejection must preserve current complete state, original save, candidate and latest pointer bytes. This is not exhaustive re-signing resistance, old-save migration, full display-history authentication or power-loss durability.

Session cached responses contain four authoritative base fields `{ok, phase, turn, result}` plus historical display `facts`/`changes`. All current check producers append only numeric probability/roll and scalar outcome, so base comparison against original Turn receipts requires no current-knowledge re-projection. Historical display fields remain outside that comparison. Signature validation checks its canonical structure and existing power/prayer action correspondence; it does not claim authentication of redundant historical UI selections.

The fixed batch is parse, one same-process core and native startup, with a total 300-second ceiling. First unexpected failure stops; two stop this implementation. Raw errors are never ignored because process exit is zero. Existing mature fixture snapshots cannot be wrapped as Session saves: their test-only participant capabilities differ from `Session._build`; no capability or snapshot adaptation is performed.
