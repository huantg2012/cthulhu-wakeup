# UI 机器验收

运行：`python -X utf8 tools/ui/verify.py --godot "E:\Program Files\Godot\Godot_v4.7.2-stable_win64.exe"`。`--smoke` 只做本轮23项，不写正式证据。正式运行要求先实际执行 `tools/endings/verify.py` 完整链，并逐项核对其当前源码指纹，不能手工刷新旧结果。GUI部分需图形会话，以实际Godot视口生成19／28字号截图，不能用headless截图冒充渲染。

`run.gd` 从真实 `Session` 入口执行，存档仅写入 `.godot/ui-test-saves` 下独立目录，不访问正式玩家存档。固定种子 7919 的首轮可能没有事件；`UI-EVENT-001` 明确记录空事件边界，不把它称为执行了事件分支。实际存在的可执行事件才使用相同的重复请求验收路径。

Session 检查包括完整新局安装与首轮、脱离副本和只读预览、未知域保密、祈求的真实执行、同一 durable ID 重试及读档后重试、异内容重复拒绝、知识保存恢复、坏档不覆盖当前局、终局只读、正式来源不超出已知原始事实。

`UI-REST-001` 与 `UI-ZERO-001` 使用明确的高级初态：在首条正式 receipt 前配置信仰 12／创伤 3，或信仰 0／创伤 0。它们验证真实敛息支付、恢复与行动阶段关闭，以及无钱仍能推进到轮间；不声称玩家从新局自然取得该状态。没有修改收费、资格或 RNG。

`input_cases.gd` 与包装器由主执行者负责，分别提供实际场景输入检查和来源哈希、日志错误闸门。运行记录必须明确区分 Session 调用、合成输入、实际人工键鼠与审美；本工具不把机器通过当作两个人工 ACC 通过，也不证明发行性能、长期策略或视觉风格已被认可。

对应规范为 `docs/specs/ui-interaction.md`；DEC-011 当前授权功能优先，DEC-018 的提交由主执行者统一处理。新局首团来源、十二权能及全部高阶玩法不能仅靠按钮存在判定可达；未实际执行的范围必须在最终 QA 报告保留。

`development/bootstrap_probe.gd/.json` 保留最后一次有界策略探索的原始输出，不由正式wrapper运行，也不计入PASS数量。它没有找到首团，详见 `docs/qa/ui-bootstrap.md`。原生OS工具采集超时已单列，不算输入通过；人工ACC保持人工待验。
