## 给后续AI的读图规则

1. 图与F5/G正文一起读。六问是内容阅读顺序，不是六个页面；箭头旁是用户动作，不代表自动发生。
2. 中央是R3，左右及上下是R1/R2/R4/R5的语义定位。外壳以当前样板为基础；窄边栏只是压缩表示，不能据此照抄宽度。正式1280画幅仍按原工程配置。
3. 中央最多两组高密度阅读内容。列表＋详情、情境＋判断、宽清单＋解释按任务变化；世界场景是共同空间，不必额外占第三列。图中等高盒子只是解释内容归属。
4. 所有框线是线框标注，**不要制作成游戏里的清晰细线**。底部区域仍用同一空间和背景；游戏承托、雾、粗纹理边界及图标状态继续遵守视觉规范。
5. “当前任务内的入口／执行／返回”一排汇总可达动作，不锁定统一横条组件。只在当前行动中保留其费用和执行，离开后收起。浏览期间没有原行动执行按钮。
6. 一次返回恢复具体成员／记录、原栏目与仍有效位置；仅恢复主页面标题不算完成。列表换人更新详情，不叠窗口；无关追链必须明确开始新任务。
7. 图中出现关联、候选、概率、期限均受正式投影限制。无关联、未知、失效、无资格时按F4处理，不为了填满布局造数据；选择恢复不付款、不自动执行、不预占资源。
8. 美术落地使用 [D4的S1–S5](../visual-system.md#flow-delivery)，正式接入使用同处J1–J5。优先在当前典型场景实现S1/S2；图的存在不等于实机已实现、操作已通过或视觉已验收。

## 编辑与同步

每张图有同名JSON（文字、状态与转移）、SVG（可编辑矢量）、PNG（预览）。JSON只用于绘图，不属于策划或运行数据。生成器为 [build_flow_wireframes.py](../../../../tools/echoes-art-master/build_flow_wireframes.py)，依赖Python 3、Pillow、中文字体；本机使用macOS宋体。换环境用 `--font` 与 `--font-index` 指定中文字体；字形差异会使PNG指纹不同。

```sh
python3 tools/echoes-art-master/build_flow_wireframes.py
python3 tools/echoes-art-master/build_flow_wireframes.py --check
node tools/echoes-art-master/design_sync.mjs --record --note '写明本轮修改和验证范围' --sections 'F5,G1-G7,D4'
node tools/echoes-art-master/design_sync.mjs --check
```

修改流程先原地更新F5/G对应条目和JSON，再生成并查看PNG。几何变化更新生成器；不单独修改导出图而留过期数据。生成检查只证明导出一致，同步检查只证明文件已登记，两者都不能判断设计或审美通过。以后改变任何相关样板行为时，同一批交付必须更新受影响图、文字、实机证据；没有信息流变化时在同步说明中记录理由。
