## 控件家族与信息层级

1. **教团索引：**整体采用向海面渐隐的半透明暗面；普通项降低底面和边界，选中项保留浅暖象牙实体、深字和对象符号。十二项是展示夹具而非正式 Session；滚动条可拖动，也支持滚轮、搜索及键盘焦点。
2. **操作与摘要：**除顶部及底栏边界外不使用清晰细线，主体、查阅与风险用承托、文字和明暗区分；主动作使用可辨的实体。风险仍由文字共同说明。
3. **图标先行：**资源、四维、祈求类别、权能、圣物由图形先识别，名称和状态补充事实。四维保留青、橙红、淡紫、淡青色差，数值与观察轮次分列。
4. **文字：**当前标题/对象名约24–30px，正文/资源/操作约19–24px，日期/范围/状态约16–18px。标题和正文均为真正的宋体 Regular。骨白 `#e6ddc8` 承载主体文字；暖金 `#e5c98d`、亮金 `#f2dba8` 强调标题/重点；灰绿 `#a9afa5` 用于辅助信息；青 `#92c2c5` 识别世界；橙红 `#ed9b81` 提示期限/风险。这是待人审的实机参数，不是统一大金字或永久色板。
5. **状态：**原稿可观察普通与选中；hover、pressed、focus、disabled 是沿家族补足的制作推导。底栏权能、圣物悬停作用在图标自身，其他区域的焦点通过色块表现；选中与执行分开。执行中、已完成、全量空/长/多状态尚未据此验证。

## 素材方法与真实节点

尺寸、SHA-256、prompt、Atlas区域及复用来源见 [restoration-assets/manifest.json](restoration-assets/manifest.json)，两张新 PNG 的指令见 [restoration-prompts.json](restoration-prompts.json)。

- `World/Background`：新生成 `sea-mist.png`，1672×941 RGB，无界面与建筑。home是主要依据，overflow只约束浪与雾的连续关系。这是环境底，不是交付整屏图。
- `World/Sanctuary`：**直接引用 home 无UI原画区域 `(480,270,610,264)`，以同位置、同尺寸显示。** 当前不使用旧透明再生成圣所。GPU把完整图集UV转换为局部UV后羽化，`feather=0.12`、`strength=1.0`，保留原场所笔触和局部环境光照。
- `World/DistantFragments`：4个独立 TextureRect，同源区域为 `(335,192,149,113)`、`(1113,274,143,88)`、`(1345,465,179,108)`、`(267,464,121,88)`。各自局部羽化0.30、透明强度0.78，不另造文化片段。
- `World/Atmosphere`：独立远雾/前雾shader。远雾范围 `(245,125,1427,430)`、opacity0.08；前雾 `(245,450,1427,355)`、opacity0.055。关闭这些层不会移除环境底或原画片段中已画入的雾。
- `Interface/ReadingSupport`：左侧、顶部局部渐变遮暗。界面与文字不画入背景；顶部及底栏以外不使用清晰细线围框。
- `Interface`：TopBar、CultIndex、WorldContext、Prayers、Chronicle、Dock分别组合原生 Panel、Button、Label、LineEdit、TextureRect；预览和图层检查位于独立 PreviewLayer / FeedbackLayer。
- `control-skins.png`：新生成1374×1145 RGBA无字皮肤，普通石片、选中象牙面、主动作浅面分别取 `(70,80,1240,275)`、`(70,420,1235,308)`、`(80,797,1220,280)`。运行时先采样至0.2倍显示密度，再以左右18px、上下9px九宫格使用，避免大角饰挤入小按钮。生成内容只有皮肤，文字、图标、输入独立。
- 原稿图标采用 AtlasTexture；多数暗底图标在GPU使用 `smoothstep(0.04,0.16,max(rgb))` 去暗底，`cult_selected`不应用此处理。这不是逐个手工抠出的完美alpha，暗色细节与边缘仍需检查。四个圣物也是home独立原画区域，不拿带字整行充当控件。
- 源图为不透明截图，外框及部分组框/动作边缘从 home 对应区提取暖色边缘、以透明纹理九宫格绘制；承字面、图标和文字另行组合。此法去掉部分源背景，同时会损失暗色和中性细节，不等于重绘完整透明装饰；右外缘剔除与原图警告相交的残留。权能与圣物按钮独立处理普通、悬停、按下和焦点状态，减少源截图底块显露。
- 前8权能来自home；后4项 `anchor / veil / transfer / manifest` 未在home展示，复用旧 `assets/power-sigils.png` 对应Atlas，属于**补充推导素材**，不是已知原稿图形的还原。搜索图标复用本地SVG。名称、费用、门槛和效果由正式CSV读取。

主场所和远景目前是带少量原海雾的独立原画片段，**不是建筑、人物、地面全部分离的透明素材**。它们可独立开关、变换、替换，不能因此声称内部角色或光照均可独立编辑。这保护本轮原稿画法；文化资源生产仍单独推进。

## 先组件、再整屏的实际过程

先拆普通/选中索引、资源与四维、暗心亮边动作、浅实体动作，使用真实Godot控件与原稿局部等尺度比较，形成 `restoration-components.png`。随后组合整屏，在场所尺度不变的前提下施加中央祈求和底栏压缩，同时保留F2原稿比例对照。

整屏检查发现字重过粗，追加独立实机诊断：Godot4.7.2的 `SystemFont(["Songti SC"])` 实际选中系统TTC的face0 Black；weight300仍为Black，`FontVariation.face6`在本环境的渲染也与Black逐像素相同。当前 `restoration_font.gd` 只在内存读取安装的Songti.ttc，将首face指针转向已有face6 Regular，确认返回Regular并包含中文后使用。**字体文件未复制、修改或保存到仓库。** 缺少该字体时采用宋体类系统fallback；其他平台字形一致性尚未证明。`restoration-font-comparison.png`及JSON保留了错误Black与实际Regular/Light的证据。

整屏中还将场所改回home原画片段，并修正完整Atlas UV导致裁片矩形边界残留的问题；当前使用局部UV羽化与连续海雾合成。这些是实现方法修正，不是用户同意降低目标。
