# 幽界群像 UI 母版：原型功能与状态覆盖

更新：2026-11-04。当前视觉布局和接入映射以 [设计规范](visual-system.md) 和 [功能呈现](component-map.md) 为准；下列源码证据来自2026-11-03核对，未在本轮重跑。核对基线：`e2073a4` 工作区。性质：原生原型的静态功能核对与母版覆盖依据；不是新系统规格、完整玩法验收或美术验收。规则正文仍在 `docs/specs/`，视觉尺寸与组件定义由本批 UI 规范负责。本次未运行游戏或测试、未修改生产代码。

核对对象为正式原型 `src/presentation/experience_root.tscn` 及其 `experience_root / views / actions / semantics / feedback.gd`、`action_catalog.gd`。旧 HTML 只是归档对照，不作为当前功能依据。既有有限运行证据见 [原型交互核查](../../qa/ui-experience-interaction-audit.md)、[世界态势核查](../../qa/world-situation-ui.md)；这些历史证据没有在本次重跑或升级为全场景通过。

本轮深度与呈现方案统一引用[规范F5](visual-system.md#information-flow)、[七组信息流](component-map.md#flow-g1)及[正式／样板双轨验收](visual-system.md#flow-delivery)。它们是推荐待审设计；下列原型源码仅证明业务内容与原有执行合同，不证明新空间形态已实现。

## 1. 本轮要求与当前实现之间的区别

- **最新布局：右侧祈求摘要，选择后中央详情。** 左侧为世界联系清单，中央默认世界／教团，展开祈求时互斥。该布局覆盖旧中央默认祈求；功能与知情合同保留。
- **合法事件仍先于自由行动。** `events` 时 ActionCatalog 只列未处理事件；可暂退事件查看现状，不能提前回应或执行普通权能。事件阶段结束后才进入允许祈求与自由行动的 `actions`。证据：`action_catalog.gd:89`；`experience_root.gd:656`。
- **祈求高优先级不构成强制回应。** 正常行动窗口至少一项合法祈求，最多展示三项，每轮至多回应一项；玩家可先查看、使用其他合法权能、经营或跳过回应。结束回合提醒未回应及到期损失，不强迫付款。数量源为 `data/event_parameters.csv:2`、`:3`；正式补足链见 `src/game/prayer_supply.gd:77`；跳过提醒见 `experience_root.gd:536`。
- **薄底栏不能删减权能范围。** 原型始终按 Catalog 顺序列全部十二权能，未解锁仍能查看条件；缩高应调整图标、文字与滚动布局，不改为自动筛选的常用集合。圣物当前列表排除已消耗物，已消耗身份留在历史。证据：`experience_root.gd:276`、`:297`。
- **正式灰阶原型的视觉几何不是选中方案的尺寸标准。** 它提供已有入口、真实选择、知情与结果合同；母版可调整分区以落实本轮反馈。

## 3. 必须跨页面一致的交互合同

1. **后台保留有价值的选择，行动面板不常驻（DEC-060）。** 再次打开对应功能时恢复之前有价值的选择；离开该功能后收起行动面板。关闭／返回／另选功能不应仅因呈现切换而丢掉这些选择；恢复时核对当前对象、条件和费用，不自动执行。旧原型“单一draft、另选替换、关闭／回总览清空、持续并置行动区”仅为实现事实，需按新目标调整。记忆范围、时效和显式取消行为仍讨论。旧实现证据：R:360、R:436、R:452、R:460；A:96。
2. **当前打开的功能内，正文局部滚动，执行与退出可达。** 中央具体呈现方式仍待讨论；后台保留选择不要求行动区继续显示。长文本、更多准备和完整后果不能把费用、主动作和关闭挤到滚动末尾。以下为原型功能依据，非新布局定案。证据：R:470；A:13、A:66。
3. **选择只改变草稿，执行才结算。** 唯一强制来源可自动填入，多候选不能偷偷取第一项；查看、预览、检索、对照不收费。执行前重预览，不可逆项才进入确认；取消不消费。证据：A:29、A:137；R:488、R:648。
4. **预算的三个时间口径固定。** 顶部为现有资源；行动预览为仅扣这次费用后的维护影响；轮末计划为现有资源下的先付支出与条件性收入。母版不要为节省高度合成一个“可用信仰”。证据：A:390；V:621、V:662。
5. **失效仍有可读去向。** 请求离开展示后可看历史；消耗圣物从当前列表消失但身份留史；终局停普通行动但已知对象与历史可查。证据：V:282、V:556、V:822。
6. **键盘与鼠标是一套状态。** Esc依次关闭临时层、当前行动、主体子页、再开菜单；临时层内Tab循环，重绘后恢复有效焦点；F5保存。母版需给焦点和悬停各自样式，不能把选中／焦点／不可用画成同一态。Esc关闭当前呈现不自动等于删除后台选择，关闭层级与记忆清除分别定义。证据：R:312、R:470、R:796。

## 4. 首批母版必须出现的代表状态

这些状态用于检验共用组件是否足够，不要求本批逐页绘制整款游戏：

- **轮初待回应**：右侧摘要1项与3项两种容量；请求期限、原危机期限、一次回应机会、相关世界可达；若先有事件则先处理事件。
- **选中祈求**：身份、浅／深两种分支、必付与成功收益分开、主要执行固定；查看相关对象后仍认得原行动。
- **回应完成**：中央显示实际结果并让出持续操作空间；本轮其余请求只读且能查，不能继续保留误导的回应按钮。
- **经营／对象浏览**：全员或多物件长列表，查名与范围明确；离开功能收起行动面板，再次打开恢复有价值选择；中央布局及恢复呈现待讨论；选中与键盘焦点可区分。
- **风险与无法执行**：资源不足／缺对象、供奉新增缺口、长期反制、不可逆处置至少各有一个组件状态。
- **历史情报**：同一世界四项混合“确值、估计、未知”，观察时点和来源可读，实际反制单列。
- **临时层与封存**：对象对照、不可逆确认、保存错误、终局只读可用同一套组件语法，不需要各自另造风格。

## 5. 验证边界与仍需后续实机检查

静态核对确认上述入口和状态分支在当前原型中有对应实现路径。既有报告覆盖真实新局、首团存档副本、有限回应／保存／导航，以及部分明确主体夹具；这不证明所有成熟事件、契约、降临、终局自然流程已走通。

本轮布局母版不得将人工成熟展示数据写成真实存档，不从概念图反造费用、人物身份或世界信息。主母版的几何、文字尺度、遮挡、滚动、焦点和低装饰气氛需要另作视觉检查；正式接入之后再按本批涉及路径做短交互验证，不为 UI 规范重跑整局或全策略矩阵。
