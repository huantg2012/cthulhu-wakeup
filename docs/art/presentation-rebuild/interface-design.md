# 玩家界面探索：内容、层级、场景结构与UI美术

TL;DR：本文件只维护 `codex/visual-interaction-exploration` 的新探索设计，覆盖本作主要玩法，以层级、关系和任务的不同组织方式推导界面。旧版 `docs/art/echoes-ui/visual-system.md` 是另一套已锁定规范，恢复至分支建立前的 `cd4fbd9` 版本并保持只读；本文件不替换它、不宣称获选，不改变功能分支或游戏规则。

可直接打开 [设计阅览器](interface-review.html)：主要玩法覆盖、两种结构草图、层级点选走查、UI控件美术小样及参考对应。它是设计夹具，不执行Session、不检定、不支付、不保存游戏；不以演示流程证明机制已接通。

## 1. 本轮边界与工作方式

- 制作人已确认重点：适合承载游戏内容的场景布局、功能区结构及UI美术；不以人物立绘画法定义新方向。
- 核心任务尽量完整覆盖；独立原型以有限代表路径展示结构，不把“祈求可操作”写成“整游戏承载成立”。
- 验证从简：作者核对一次文档/来源与可打开性、修明显故障；体验、结构、美术选择由制作人直接判断。没有全套自动截图、多种子回归、打分或AI模拟玩家研究。
- 原A/B/C只作失败证据。新结构仍是草案，不能把名称、参考、说明或技术检查当作审美结论。
- 本文件是新探索版设计正文；系统spec与CSV仍是机制权威。旧组件地图P01–P19只用于核对功能覆盖，旧R1–R6与线框盒子不约束本轮几何。

### 十二权能的交互归属

阅览器的名称、门槛、基础说明来自 `data/powers.csv`，由生成器直接读取，不手写第二套技能定义。为理解任务，将聆听归信息取得；入梦、谕言、赐予归培养与准备；任命归组织角色；献祭归不可逆兑现；穿隙、播种、掩迹归扩张/反制；锚定归现实依托；迁引归跨世界重配；降临归终局。上述为UI的多入口归类，同一权能仍只有一个正式规则和准备草稿。

### 内容出现的阶段

前期没有教团、圣物或锚点时，主场景保持已有联系和真实机会；仍能查到未解锁权能及门槛。中期强调组织、活动、护持、反制和维护；后期增加跨世界支付与仪式连续性。对象按真实出现而生长，界面不凭空补满建筑、人物或任务；容量扩大用完整清单、筛选和范围切换承接。

## 3. 信息架构：范围、对象和任务分开

**范围**回答“在全部已知世界、某世界还是某教团”；**对象**回答“当前具体是谁/哪件物品/哪座锚点”；**任务**回答“正在查看、安排、修复还是施力”。三者各有稳定标记，不能只靠页面标题猜测。

- **局势入口**：已知机会、迫近反制、持续责任与关键进度；允许从具体问题直达对象。
- **范围导航**：全部世界→某世界→其已知组织/机构；人物与圣物也有跨世界完整入口，局部清单不能取代全集。
- **对象工作区**：当前世界、教团、人物、圣物、机构/锚点；同对象的更多信息采用同级切换和局部展开。
- **行动准备**：只在开始具体动作后出现；目标、候选、条件、费用、必付与关键后果围绕这一个动作组织。
- **全局工具**：全部权能、收支/供奉、苏醒、历史、存档/设置。频率低不等于不可发现，使用命名明确的稳定入口。

这些是功能职责，不是固定五块常驻面板，也不规定左/右/上/下。布局要随“概览、比较、准备、查看、结果”改变空间分配。

## 4. 层级与关系的具体交互

### H1 范围层级：逐级进入，有直接上跳和同级换项

典型路径：全部已知世界→某世界→某教团→成员名册。页首保留短范围路径，各祖先可点；同级世界/教团/成员可直接切换，不要求先退到总览。宽名册支持筛选和连续换人，详情跟随选中，保留列表位置；进入详情不让名单消失后只能反复进出。

对象不只有一个父亲：同一人从祈求、全局名单和教团进入，身份页一致，但范围与返回位置按本次来处保留。人物迁移后显示实际归属，旧来处可以保留，不能把浏览路径误写成对象的新归属。

### H2 依赖关系：围绕一个目标展开，不伪造成目录树

锚点受材料/见证、组织、人物、圣物及供奉共同影响。这不是“世界→教团→人物→圣物→锚点”的单亲层级。目标页直接列出已满足/缺失条件、具名依赖、可行补齐方式和改变后的影响；当前缺口可展开具体候选，操作后回到原目标的同一缺口行。

查护持者时可看该人的相关职务及冲突；查绑定物时可看它影响的锚点。更换一个依赖前，明确它会影响哪些当前已知对象。未知关系不画边，不将设计示意图当作玩家全知关系网。

### H3 任务中的深入：速览、深入管理、返回原任务各自明确

例：修复目标→选择护持者→速览候选→查其携带物。

1. 当前目标和草稿摘要保持可辨；候选列表及选择不因速览丢失。
2. 短解释在原行展开；更长的关联资料占用一个可替换的速览位置。继续查相关物时更新同一位置，标清当前在看谁/什么，与行动目标分开。
3. “返回修复目标”一直可达，直接恢复原候选、合法选择及滚动/焦点；范围路径不冒充查询历史，关闭无需逐层退弹窗。
4. 需要真的操作另一个主体时，用明确的“管理此人/处理此物”切换主任务，保留原任务书签和草稿。资料浏览本身不改行动目标；切回后按现状复核选择。
5. 若期间改变任职/携带导致原草稿失效，定位并解释失效项，其余仍合法的选择保留。执行区不同时属于两个任务。

### H4 同对象的深度：局部展开与同级栏目

人物的职责、能力、携带物和经历不是四级页面；世界四维的精度/时点是原数值的解释；活动的规则说明属于当前活动。它们分别采用同级栏目、行内展开或可键盘固定的速览。关键风险和实际费用不藏在只能悬停才出现的位置。

### H5 需要比较时，暂时提供比较空间

选护持者保留相同的相关列，可固定一个候选作对照；收支按教团/锚点并看支付影响；世界列表按同口径呈现已知危机与情报时点。比较空间按任务出现，不把全部详情永久并排；没有可比资格的未知数据不填成0。

### 一个完整例子

在世界中看到锚点缺口→打开目标，展开护持者候选→点候选速览→查其绑定/携带关系→关闭速览回候选（原行仍在）→选择合格者→确认本次费用和受影响依托。若决定先改变候选职务，则明确进入人物管理，再通过任务书签回到锚点并重查。回执只报告真实发生的变化；本设计阅览器只演示前半段导航，不模拟结算。

## 5. 两种结构草案：相同内容，不同的空间组织

两案共享任务和语义，尚未选定。阅览器允许在同一状态切结构，不用人物画法区分它们。

### S1 连续局势场

- **主要操作对象**：某个世界及其已知联系。全局以互不宣称共同地理的世界片段进入；选中后当前世界成为主要空间。
- **功能分配**：少量资源/阶段与完整入口居边缘；组织、活动、机会、锚点直接附着在当前世界的联系标记上。进入对象时重排/收束周围联系，让主要任务获得中心空间。
- **层级处理**：范围路径始终在场；名册横向/纵向连续换人；短资料局部浮现。行动展开占据当前焦点，相关速览从邻近位置展开，结束退回同一局势。
- **应当带来的体验**：从现实联系发现机会，行动后仍记得发生在哪个世界。当前设计尚须制作人判断世界片段能否读清、对象数变大是否拥挤。
- **代价/疑问**：多对象比较时仍需临时宽清单；不能把“场景化”变成找小图标或迫使玩家猜建筑含义。对象标记与其名称必须清楚可达。

### S2 范围导航与全幅工作场

- **主要操作对象**：当前选中的范围或任务。全局从同口径的世界/责任索引进入；聚焦后当前任务使用完整工作画幅，父级情境压成定位与可点摘要。
- **功能分配**：世界概览、组织安排、宽名册、目标依赖、收支和仪式使用各自适合的整幅构图；不把全部功能塞进同一个右栏。速览借用当前画幅的一部分，主对象及返回仍保留。
- **层级处理**：祖先上跳、同级切换、对象栏目和任务书签分工；清单/候选较多时优先保持比较宽度。行动中的短查看就地打开，深入管理才显式换场。
- **应当带来的体验**：操作上下文明确，能承受中后期较多对象和条件。当前设计尚须制作人判断换场是否割裂、主场景的持续存在是否足够。
- **代价/疑问**：容易向工具界面靠拢，UI美术和状态转场必须建立游戏身份；不可只给数据表加边饰。

阅览器是结构草图，不是两套完成的游戏UI；T01–T12是设计覆盖，实际可点走查重点为世界→教团→成员、锚点→候选→关联物→返回，以及供奉/活动/权能/进度的空间切换。未实现功能不得凭导航名称算接线完成。

## 6. UI美术小样：对界面部件和关系做设计

人物图像使用同样的中性标记。场景是结构性剪影/联系组织，占位不评价角色文化。小样不沿用旧版材质和色板作为新方向约束，也不凭本文件锁定新色板。

- **视觉重心**：当前对象与当前决定最强；范围/来处为次级；资源和低频入口易找但不抢正文。进入行动后，主次随任务变化，不能只缩小背景。
- **承托与边缘**：S1使用局部承托和开放边缘表达焦点，S2使用明显的页首/栏间距和连续工作面表达范围；避免每项数据都包同样的卡片。
- **字级与排版**：身份、状态、动作、数值分工；关键条件与选择靠近，必要副作用有固定可读位置，名词不靠装饰字体辨认。
- **图标语言**：对象类别、能力、状态、动作分别稳定；未选、已选、缺失、不可用和危险用形状/文字/线条同时表达，不只换颜色。
- **状态过渡**：范围深入收束原上下文，关联速览不换主对象，准备和执行在视觉上有明确门槛；用位置连续性解释关系，不能用全屏淡入掩盖切换。
- **小样范围**：阅览器展示对象标记、选中项、可展开条件、缺口、草稿保留、返回及不可用执行。无人物立绘、无背景生成图，色彩/轮廓/字体均待制作人审阅。

### R2 Against the Storm：从场景对象进入条件、人员与后果

[官方Wiki的事件界面职责](https://wiki.hoodedhorse.com/Against_the_Storm/Glades)、[教程中的完整事件图与展开](https://wiki.hoodedhorse.com/Against_the_Storm/Tutorial_Walkthrough#17._The_Glade_Event)。对应本作H2：在一个目标现场组织要求、参与者与后果，而不是逐个子系统找答案；S1参考从场景对象进入准备、回到原对象的关系。只借内容邻接与进入方式，不引入实时计时、生产物流、工人派遣机制。教程标注基于1.0，不作为现版逐像素模板。

两项来源是开发者或官方资料，已查阅其文字与图源；本轮没有宣称重新完整实玩这些游戏。阅览器提供参考原页与抽象结构标注；原图属于原作者，不能当本作资产。本作两案是根据任务做的设计推导，待人审，并非参考作品替它们保证质量。

## 8. 制作人最快审阅路径

1. 先看“主要玩法”确认有无遗漏或错误归属。
