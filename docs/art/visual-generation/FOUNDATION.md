## 1. 核心洞察：要吸收的是「翻译链」，不是星球

ref-project 值得吸收的不是「怎么把星球画好看」，而是它把**一个看不见的状态变成一张有材料、有装帧、会呼吸的图**的那条链。它内部做了三次翻译：

```
① 意思 → 场     把「被邪神碰过的世界」变成具体的场：裂纹、菌落、符文、眼睛、城灯
② 场 → 媒介     把场落到某种材料上：铜版排线、水彩纸、网点、扫描线
③ 图 → 物件     套上编号、引线、边框、色卡，变成「世界里的档案」
```

本游戏有同样结构的东西等着被翻译：**世界态势、教团、具名人物**——它们在正式 UI 里目前全是可替换占位（路由第 9 行、`ui-interaction.md` 第 18 行）。所以不是搬生成器，是**把这条翻译链对准本游戏自己的语义**。

## 2. 三类立绘的语义对应

### 2.1 世界立绘：画「现在怎么样了」，不是画好看的球

玩家在「诸界态势」扫一眼，不读数值就该知道哪个世界快反扑。制作人列出的 ref-project 技术与游戏状态可一一对上：

| 玩家该看出的事 | 借哪支笔 | 画面上是什么 |
| --- | --- | --- |
| 污染扩散到哪了 | 腐化蔓延 | 从一个点长出的暗斑，边界毛糙，缓慢呼吸 |
| 屏障还压得住吗 | 环阴影 | 一圈压在球面上的暗带，破口处漏光 |
| 文明是不是在盯你 | 夜面城市灯 | 暗面亮起的灯点，越密越危险 |
| 教团留下过什么 | 符文带 / 法阵环 | 一圈缓缓转动的刻痕 |
| 苏醒到哪一步 | 大气、日冕 | 边缘辉光的厚度与颜色 |
| 这是哪一层文明 | 三层星点、螺旋星系 | 背景深空的结构复杂度 |
| 凹凸与地表 | 11 原型 / 凹凸法线 | 世界不是通用球，各有自己的地表脾气 |

**比技术更硬的一条**：生成器只能吃玩家**已经知道**的那部分。项目反复要求「知情边界」「只给公开投影」「未知世界只投影已知精度」。文明还没被察觉的事、玩家还没发现的世界，不能因为好看就先画出来。立绘读的是呈现层能拿到的公开字段，不是内部账本。守不住这条，立绘会变成作弊器。

### 2.2 教团立绘：同一个神，八种误读

DEC-045：教团差异来自**不同世界背景中的人对同一邪神的理解与感知**。所以教团不该是八个图标换颜色，而应是同一套仪式几何，在不同文明里长出不同的符文骨架、旋转方向、承印材料。八套皮、一个生成器、共享同一支笔——正是 ref-project「一次造型、八种媒介」的做法，只是把「媒介」换成「文明的理解方式」。

### 2.3 人物立绘：ref-project 没有覆盖，不能假装能搬

参考项目**完全没有人物**，制作人列出的技术清单里也没有。能借的只有三样：

- `apply_eye` 那套参数化器官笔刷 → 被神迹触碰之后的变异
- 触手的顶点形变 → 衣袍、发丝、影子的呼吸
- 「轮廓 / 发型 / 衣装 / 姿态」部件化 → 项目 `interface-design.md` §16 本来就已定人物靠这四样识别

真正要新建的是**人物骨架 + 处境姿态库**（求告、劳作、被追查、主持仪式）。硬要求：**同一个人重新打开必须还是同一张脸**。项目反复强调身份不被随机文本重置、世界记得玩家，所以立绘由「对象 ID + 固定 seed」生成，与存档、知情投影一样稳定，不能每次打开抽一张新的。

## 3. 画风清单：移除 3、保留 5、新增 3

制作人移除：**赛璐璐漫画 / 低多边形 / 全息星图**。三者分别对应「硬分层把主体压黑且描线描到噪点」「名不副实只是色阶量化」「科幻仪器感与本作视角不符」。

### 3.1 保留的 5 种（原名保留，按本游戏世界观重述用途）

| 原名 | 本游戏里的定位 | 世界观依据 |
| --- | --- | --- |
| 暗黑厚涂 | 主视觉、章节、苏醒临近时的神迹 | 疯狂与混乱是持续主题 |
| 古典铜版画 | 文明档案、机构对异常的解释记录 | 文明抑制力来自「维持现实秩序与解释世界的能力」 |
| 复古像素 | 远距 / 尚未看清的世界的低精度缩略 | 诸界态势里次要世界只给低精度观测 |
| 水彩手稿 | 祈求、凡人处境、调查员手记 | 祈求来自具体人物在具体处境下的愿望 |
| 怪奇杂志 | 事件、传闻、文明开始公开议论神迹 | 察觉上升后，异常进入大众叙述 |

### 3.2 新增的 3 种（按本游戏世界观推导，非 ref-project 已有媒介换皮）

关键区别：ref-project 的 8 种是「**这张图印在什么材料上**」；本游戏新增的 3 种是「**谁在看、用什么方式记下来**」。因为游戏的核心视角是「邪神从高维观察」（探索 §19 制作人纠正），以及「文明怎么理解神迹」（DEC-045）。

#### A. 梦谕残影 · Oneiric Trace

- **出处**：`world.md`「教团、圣物、**梦境**与仪式构成干预媒介」；入梦 / 梦谕权能；祈求经梦谕被承接。
- **视觉**：不是印在纸上，是**闭眼后视网膜上的残像**——轮廓双重错影、色相分离、边缘溶解成颗粒、中心局部负像，整张图以极慢的频率呼吸。越靠近回应时刻，错影越开。
- **技术**：域扭曲 + RGB 通道位移 + 噪声阈值溶解边缘 + 局部反相 + 低频亮度呼吸。
- **用在哪**：祈求、入梦、梦谕类权能；不适合放数值密集的页面。

#### B. 仪轨刻本 · Ritual Codex

- **出处**：DEC-045 教团按各自文明背景理解同一邪神；仪式、符文、圣物、锚点是扎根的实际依托。
- **视觉**：**每个文明自己的制图术**——几何度量线、环形刻度、朱笔批注压在墨线之上；图是「测不准的」，注是「试图解释的」。与古典铜版画的区别：铜版靠排线塑明暗，仪轨刻本靠**符号与度量**组织画面，不塑形。
- **技术**：三向排线做明暗底 + SDF 度量网格 + 符文带 + 朱墨套印错位 + 手绘抖动批注层。
- **用在哪**：教团、档案、机构、锚定准备。八文明换符文骨架与批注体系，几何骨架共用。

#### C. 神侧观测 · Divine Vantage

- **出处**：探索 §19 制作人纠正「邪神从高维观察世界、世界中的教团与人物」；本作视角不是任何人类仪器。
- **视觉**：**没有单一光源**；同一个对象有多个时间切面半透明叠影并存；近处与远处同时清晰，没有景深；画面上的准星与刻度不是仪器读数，而是「正在被注视」的标记。
- **技术**：多个时间切片半透明叠影 + 去单一光源（抬暗部）+ 等高线 / 经纬网格 + 全清晰无模糊 + 观测标记层。
- **用在哪**：诸界态势主基调、世界切换时的俯视；这是唯一不假装由人记录的画风。

> 三种新画风都可在同一张内容层上切换，不需要重画球体。实物切片里三者均已实现，可当场对照。

### 3.3 值与文字的可读性（制作人第 4 条决定）

**整屏压黑是允许的**，不作顾虑。数值与文字用两种手段保证可读，两者都可用：

1. 立绘的**反差色**绘制（暗底上用亮色，亮底上用墨色）；
2. 为值与文字加**背景块**（半透明实底 + 细边）。

不可越过的底线仍是 `vision.md` 的「规则提示直白，不能用叙事模糊掩盖代价」：氛围层（编号、引线、刊头、批注）不得压到费用、概率、D100 点数、条件与回执上。装帧归装帧，账目归账目。

## 4. UI 边界：只换纸和墨，不换按钮在哪

- ref-project 的风格是「整张图版一个媒介」。放到本游戏，不是给整个界面盖滤镜，而是**每个场景有自己的材料基调，只作用在立绘 / 图版那一块**。
- 控件坐标、分组显隐、阅读顺序、返回关系、焦点、默认入口、1280×720 逻辑画布——**全部照锁定的样板，不动**。
- 媒介只换「纸」和「墨」，不换「按钮在哪」。
- 装帧层（编号、引线、色卡、边框）可复用，但受 §3.3 底线约束。

## 5. 动效：表达「在变」，不是「在闪」

ref-project 的动效纯属装饰（脉动、眨眼、符文滚动）；本游戏里**真的有东西在变**——污染在长、苏醒在呼吸、仪式在转、求告者在等。让动效跟状态走，画面才从「会动的插画」变成「正在发生的世界」。

原则：低频、局部、可冻结、由「对象 ID + 固定 seed + 状态」决定，**同一状态回到同一帧**；不因每次打开而换脸。

按 DEC-033 与制作人一贯口径：**第一步不接真实 Session**，先用固定 seed 的展示夹具把方向看准；接线是方向认可之后的事。

## 6. 技术判断与仍然成立的坑

**同构的好消息**：ref-project 是 Godot shader，正式 UI 也是原生 Godot（不是 HTML 样片），算子能真搬；`fwidth` 自适应线宽正好解决 1280×720 里小卡面 / 小图标线宽糊掉的问题。零外部资源、运行时生成、seed 可复现，与项目「规则 / 内容 / 存档 / 呈现分离」「换美术不能重写系统」一致。

**仍然成立的坑**（从上一轮实测里保留下来的）：

| 坑 | 证据 | 处理 |
| --- | --- | --- |
| 换媒介会换焦点：同一主体厚涂时看发光裂纹、铜版时成剪影、全息时整体提亮 | 主体区 mean 0.059 → 0.433、dark 83.9% → 0% | 新画风切换时必须保住主体轮廓与关键状态标记；不能只换滤镜了事 |

## 7. 起手式（DEC-033：只做一环）

不铺「世界 + 教团 + 人物 + 全套 UI」。先做**「诸界态势」里一个世界**：

> 拿现在那个占位，用固定 seed 生成一张图版，塞回原位，布局 / 按钮 / 返回一律不动。给同一个世界做三个状态——干净 / 扩散中 / 快反扑——连成时间线，让制作人看到「这个世界在变，而且我能看出来」。

一个切片验三件事：笔法对不对、状态读不读得出来、放进现有界面会不会打架。看过再决定往人物扩、往教团扩，还是先定媒介基调。

## 11. 最先验证的事：不同世界如何「生成」（2026-11-09）

### 11.1 优先级纠错

制作人指出：美术管线已具备，**「如何为不同世界生成」才该最先验证**。这是对的，我上一轮把「一个世界 × 三个时刻」排在第一位是排反了：

- 「一个世界的三个时刻」是时间轴，玩家一次只看一个世界。
- 「诸界态势」里玩家**同时**面对多个世界（规范：总览至多三世界），要在它们之间分配有限注意力。如果八个文明画出来分不清，生成系统就没成立，媒介再漂亮也没用。

### 11.2 「如何生成」不用发明，游戏里已有权威输入

`data/civilization_profiles.csv` 的八个蓝本自带：`tier`（planet/system/cosmic）、`tech/occult/faith/meme` 四范式（总和 100）、`communication`（broadcast/ritual/network）、`authority`（council/decentralized/hierarchy/unified）、`weakness`、`barrier`、`stability`、`resistance_style`。

`docs/content/narrative-catalog.md` §42-50 已经定了生成纪律：**层级、矛盾类型、路线固定，防止随机生成抹掉身份**；可变的是名称、机构、人物、关系、初始冲突、有限范式偏移（≤10 个百分点）；**同一蓝本重复选中时至少更换关系布局或矛盾涉及的人与机构，不能仅改名改初始数值**；全局种子决定结构，独立命名随机流不消耗世界/检定/事件 RNG。

因此三层身份模型：

| 层 | 来源 | 决定什么 | 是否可变 |
| --- | --- | --- | --- |
| ① 蓝本语法 | `civilization_profiles.csv` | 画面结构：层级尺度、痕迹拓扑、秩序几何、记录材质、破口位置 | **局内固定** |
| ② 实例相位 | `world_id + 本局 seed` 独立随机流 | 噪声相位、卫星/灯火的具体位置 | 每实例不同，可复现 |
| ③ 当前状态 | 公开投影（污染/屏障/察觉/反制） | 场强度 | 随回合变 |

本轮验证把 ③ 固定为开局干净态，只验 ①②。上一轮我写的「把 11 个 `Surf` 原型重新解释成世界的 11 种异常相」是错的——那是把美术参数当身份来源；身份源只能是策划 CSV。

- `world_identity.py`：读 `civilization_profiles.csv`，**按字段推导**原作 `--cfg` 参数（不是给八行各写死一组），输出 `world_identity.csv`（可审阅的推导过程）。

## 12. 层级表达：天体图该承担的那一维（2026-11-09 · 当前方向）

### 12.1 语义先钉死

`docs/world.md` §36：**「文明层级：星球级、星系级、宇宙级，表示影响与反制范围；不是必须按人口逐层展开的地图。」**

所以三档**不是**「球 → 更多球 → 最多球」的物理放大，而是**玩家能指认的作用范围与反制方式**：

| tier | 影响与反制范围 | 画面该读出什么 |
| --- | --- | --- |
| `planet` | 反制集中在一个可指认的世界 | 一个**边界闭合**的单一对象，周围是背景 |
| `system` | 跨多个世界、沿通路协同 | 若干对象 + **连接它们的通路**，没有唯一中心 |
| `cosmic` | 范围大到无法指认中心，法则本身成为场 | **边界消融**：读不出「一个球」，只剩连续的场与一道弧 |

蓝本分布（`civilization_profiles.csv`）：planet 3（CIV_01/02/03）、system 3（CIV_04/05/06）、cosmic 2（CIV_07/08）。

### 12.2 原作里现成的三套尺度，不需要新写生成层

| tier | 复用原作 | 具体参数 |
| --- | --- | --- |
| planet | `scene 0` 星球立绘 + 三分构图 | `composition=2, count=1, nebula=0.30` |
| system | `scene 1` 星系图（中央恒星 + 多行星 + 轨道线 + 小行星带） | `count=5, star_type=0, nebula=0.55` |
| cosmic | `scene 0` + 巨构地平线（`generator.gd:452` `R=short_h*4.2`，球大到只剩弧面） | `composition=3, count=0, nebula=0.90` |

`tentacles=0, eyes=0`（制作人要求剔除），`corruption=0`（开局干净态）。**没有新增 shader、没有改一行 Godot 代码**。

### 12.3 控制变量验证（实物）

`tier_expression.py`：固定 `seed=4242 / style=0 / glyphs=0.2 / madness=0.1`，只让 `tier` 对应的场景与构图参数变化；再用两个蓝本（冷原 arch5/pal4、古神之茧 arch9/pal3）交叉，共 6 张。产物 `godot-baseline/tiers/`，拼图 `godot-baseline/tiers-grid.png`。

逐张打开核对：

- **planet**：一个带环的闭合球，蓝白或紫色，伴星在远处，边界清晰可指认。
- **system**：中央亮星 + 沿椭圆轨道分布的多颗行星 + 轨道线，读得出「多个对象 + 通路」，没有唯一主角。
- **cosmic**：巨大弧面横贯画面下缘，球面大到读不出边界，上方是连续的星云场——符合「范围大到无法指认中心」。

**量化（64×36 低频结构差，越小越像）**：

| 比较 | 均值 |
| --- | ---: |
| 同 tier、跨蓝本 | **10.92** |
| 同蓝本、跨 tier | 43.76 |
| 跨 tier 且跨蓝本 | 43.77 |

同 tier 的两张（不同蓝本）明显更像，跨 tier 一律差约 4 倍。**层级压过蓝本差异，成为主导视觉维度**——这正是天体图该有的读法：玩家先看出「这是一个世界 / 一片星系 / 整个法则场」，再分辨具体是哪个文明。

### 12.4 因此方向收窄为

1. **层级是第一位**：先把 planet/system/cosmic 三档做成稳定可辨的生成档位，由 `tier` 直接决定场景与构图。
2. **蓝本只留次要差别**：地表配方、色板、微量范式偏移；不追求八个蓝本各自可辨（天体图上做不到，也不该做）。
3. **不做文明细节**：城市、机构、记录、灯火、证言、契约全部排除；人物与教团另立载体，不塞进天体图。
4. 状态（污染/屏障/察觉/反制）叠加在层级之上，用已有场（腐化蔓延、环阴影、夜面灯、大气呼吸）表达；这是下一步，不是本轮。
5. 同 `world_id + seed` 稳定复现（§11 判据 C 已通过：同 cfg 逐字节相同）。

### 12.5 待确认

- `system` 目前是「恒星系」构图；它类比的是「影响跨多个世界」，不是物理星图。若制作人认为会误导成天文地图，可改用不带中央恒星的多个世界 + 通路。
- `cosmic` 目前靠巨构地平线让边界消融；也可改用「无任何闭合对象、只有星流与法则网格」。两版可各出一张让人挑。
