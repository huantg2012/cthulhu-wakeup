# UI 美术实施问题台账

唯一处理协议见 [美术规范 §9.3](ui-art-standard.md#art-feedback)。这里保存具体问题、证据和答复，不另定义美术规则。规范维护负责人为本次美术定型主会话；换负责人须在未结条目中登记接手。

## 未结问题

当前没有实施 agent 正式递交的 UIA 条目；这不表示所有场景已有成熟样板。S03 教团图槽、A14 正式图像身份等已知待接入范围仍按规范对应条目执行，实际遇到无法决定的点再登记具体问题。

## 新条目模板

复制以下模板到“未结问题”，取下一个未使用编号；从 `UIA-001` 起。一个编号对应一个可单独答复的问题；同类多场景列影响清单，不重复开单。证据可复用现有文件；新增证据放 `ui-guide/feedback/UIA-编号/`，原图不覆盖。

```markdown
### UIA-001 · [一句话说明待决定的点]

- 状态：待接手
- 提交人／日期：
- 维护负责人／实际接手日期：未接手
- 批次／场景／相关状态：[Bxx / Sxx；常态、选中、禁用等实际相关状态]
- 现场版本：[分支、提交、相关未提交修改；逻辑尺寸／展示尺寸]
- 入口与代码：[正常进入路径、具体文件／函数]
- 玩家此刻要做的决定、必须保留的信息与交互：
- 已查依据：[A/S/V 或交互条目；为什么不足以决定本问题]
- 待决定的问题：[一个明确问句；是否涉及锁定布局／行为或已通过方向]
- 期望可观察到的结果：[如必要信息同时可读；不预设尚未批准的解决方案]
- 当前证据：[同幅截图／必要视频的仓库路径；真实 Session 或明确夹具]
- 已有尝试与建议：[可为空；如已有，附局部草图／失败对照，不强制反复试错]
- 最小受阻范围／可继续工作／临时保留方式：
- 递交情况：[交给谁、何时；没有渠道则记待转交，不能写已通知]

**维护 agent 答复（接手后填写）**

- 结论与适用范围：[按现有条目实施／补样式或小样／交制作人裁决]
- 规范及小样变更：[条目与路径；无需更改时说明已有依据]
- 允许实施的动作／仍不允许的改动：
- 验收句与所需证据：[对应 V；只验受影响部分]
- 制作人裁决出处：[仅在需要时填；未决则保持未决]

**实施回填与关闭**

- 实施文件／版本、实际场景证据、剩余差异：
- 维护 agent 核对结果／日期：
- 场景审美状态：[待制作人复审／制作人通过及出处；与问题关闭分开]
- 关闭或重开理由：
```

## 转交短格式

仅发编号不够；转交时用下面三行让接手者能找到现场。答复仍回写原条目。

```text
美术规范反馈 UIA-xxx｜Bxx / Sxx｜待接手
台账：[仓库路径及条目]；待决定：[一句具体问题]；现场证据：[路径]
受阻：[范围]；可继续：[范围]。请规范维护 agent 接手，回复规则解释、规范补充或打样安排。
```

## 已关闭问题

暂无。关闭后把原条目移到此节，保留编号、证据和答复；通用规则以规范正文为准。
