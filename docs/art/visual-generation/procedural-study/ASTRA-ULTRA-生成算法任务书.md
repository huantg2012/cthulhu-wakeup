# Astra Ultra 任务书：可扩展的二维程序立绘绘画算法

## 要解决什么

在 `codex/visual-generation-exploration` worktree 中，为本游戏设计并实现能运行时生成的世界关联教团和人物立绘。用户给出的星球原生成器是美术方法与审美锚点：`../godot-base/`。背景是高维存在观察世界、教团与向其祈求的人。每个世界有一个主要教团，但需要很多个可区分的人物。

用户最近反馈：现有输出粗糙，与星球的画风和表现力差距大；教团需要**斜上约 45° 的微缩场景**；人物不能像陶罐；同世界内人物需要玩家看得见的区别。允许无脸、阴影脸、头罩。最新反馈明确指出：用几何体、立方体、投影面“搭模型”的思维不等于程序绘画，且该轮结果比旧版更差。用户明确要求算法运行时抽签组合；不能只选几张预置图。

## 必须守住

1. **直接二维程序绘画**：可用二维场、蒙版、曲线、笔触、噪声、光照、粒子、矢量与像素算法；不创建或渲染新的三维人物、建筑或场景模型。现有原星球生成器仍按原作运行。禁止用 ImageGen 静态图或从几张成品 PNG 中选一张冒充生成。
2. 别把无脸或人物身份抽象本身当缺陷，审查的是体态、构图、衣料、画面与世界观。教团要像人在其中活动、带地形和功能的俯瞰小场景，避免只有图标或正面立面。
3. 世界原型、可选原作画风、原作色板、世界种子及**独立人物种子**均能影响相应结果；更换人物种子不改变世界和教团。不同人物应有体态、动作、头部遮蔽及衣装结构等玩家可见的区别，而非统一模板贴小饰物。保留可复现信息。
4. 原星球输出必须是原生成器真实结果，同参保持基准；不得改动原作内容或拿截图替代。人员/教团与世界共享画风、光色及视觉层级，但不能宣称二维转译与球面完全一致。
5. 保持小样探索，别接入正式游戏或做大规模回归。每组标出世界/候选教团及人物、原型、画风 sid、色板、世界种子、人物种子。

## 建议先攻克的算法问题

- **绘画表征**：针对剪影、体积、遮挡、布褶、材质边缘和局部笔触提出分层的二维生成方案。对比原作“低频形体 → 中尺度结构 → 小尺度材质/高光”的层次，让颜色、高度/明暗和笔触方向受共同结构场约束。不能把任意路径的包围盒都算作独立鼓包；也不能用锐利多边形当衣服。
- **人体和衣装**：用可约束的头颈、胸廓、肩、肘、腕关系驱动画面，但输出必须像画出来的人，而不是关节管道。构图应是可辨的上半身，衣物围绕动作受力，手可以遮掩但不要画成突出的亮块。运行时抽取姿态、比例、头部、服装与视觉身份，避免组合冲突和模糊手势。
- **教团二维场景**：45° 是观察构图要求，不授权创建三维模型。探索手绘式地形与建筑群的二维组织、材质、负空间、明暗与尺度；避免统一底盘上只替换中央图标，也不要先搭出盒体再涂贴。教团应反映所属世界而非套同一教堂。
- **原型与画风是正交维度**：原作 0–10 的各自表面公式、灯光与原作的 6 种风格管线应逐项研究，但不要把一个原型的 Voronoi 石材公式无差别用在所有材质上。世界的表达应迁移至教团/人物的材料、轮廓、光和文化，不只是换色。

## 可审阅交付

先用最少必要样本证明方法：至少两个不同原型，原作星球与对应教团各一幅；固定其中一个世界，**并列至少 4 个不同人物种子**；另展示一个不同画风。全部结果由运行时生成，显示完整参数，并排供视觉检查；同时保留可切换全部原型的设计和真实覆盖状态。先观察人形、45°景深、世界美术关系及同世界人物差异；截图或结构 hash 只能证明程序运行，不是审美及格。

请先独立审查并对失败方法作技术原因分析，之后实现并自己看图迭代。若美术仍不如给定旧图，明确指出，不要宣布成功；给出下一步最需要的人类/模型输入。
