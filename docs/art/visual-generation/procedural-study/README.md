# 同源立绘：真正程序化的小样

本入口替代 ImageGen 静态母版路线。当前只验证有限部件生成，不是正式游戏接入或美术定型。

## 启动与操作

双击仓库根目录 `程序立绘探索.command` 或 `立绘卡探索.command`，启动本地 Python 服务并打开 http://127.0.0.1:8950/ 。需要本机 Godot 4；当前使用 `/Applications/Godot.app/Contents/MacOS/Godot`。也可在仓库执行 `python3 docs/art/visual-generation/procedural-study/server.py`。

选择世界模板、画风、原作色板和0–999999整数种子后点击生成。下一种子实际重绘三个对象；同参重绘比较像素指纹。地址栏保留参数，可复制链接复现。导出按钮生成一个ZIP，含三张960×960 PNG和完整参数/身份/造型选择/源码指纹。参数修改而尚未生成时明确显示待生成，不把旧图当新结果。

## 生成合同

- 原作当前 11 个星球原型、6 种可选风格和 10 套色板均可选；每个原型的文化、机构、人物均是视觉候选，不代表游戏正式存档。其中塔穆什和阿维伦的世界名称读取正式 CSV，其余用原型名加“候选世界”。
- 画风 sid 0/1/2/4/6/7 映射原作表索引 0/1/2/3/4/5；十套色板加载时对照原作 EData 色值。原作移除的 sid 3/5 未开放。
- seed 控制本次二维部件的部分结构、大小、偏移和形体；种子也直接输入原星球。0、7 原型仍是旧的两个近亲聚所，其余教团为不同程序分支。人物共享少数身体、兜帽和姿势家族；细节见[原型与人物教团转译](原型与人物教团转译.md)。
- 相同参数可重绘；色板/画风不重抽对象造型。正式对象 ID/存档持久化未接。

## 绘制管线（没有静态母版或模型替代）

1. `cult.js`、`person.js` 与 `family.js` 用二维路径、曲线与部件组合生成形态。
2. `paint.js` 根据二维形体生成独立的颜色图、材质编号与二维法线图；法线来自遮罩距离和形体局部坐标，颜色保持由模板、种子和色板驱动。
3. 颜色图与法线图送 `/api/style`；临时工程中的 `surface_2d.gdshader` 直接调用原作 noise/common 的 fbm3、ridged3、voronoi3、style_shade 与 rim_term，使用同世界原光向、原色板及天空，再走原 bloom/post。人物/教团无新增三维模型；原作天空仍为原工程既有节点。
4. 世界由 `/api/world` 调用原生成器完整管线实际生成。所有参数显示在界面和导出JSON。两接口串行访问Godot，结果以源码/参数/输入像素hash缓存，不能用参数不匹配的旧PNG替代。

`server.py`、`templates.csv`、`palettes.json` 和 API 细节见 README-world.md。原作 `godot-base`、正式游戏源码和玩法数据未修改。

## 本轮检查与实际修正

首轮实屏发现：材质噪点过密、人物帽口/衣褶硬、底座过于规则。已减少高频噪点、加入较大的方向笔触，调整帽口和手腕、取消人物内层投影，改岩基断面与塔体厚度。接原作后期后，铜版背景仍因二维输入底色不同而读作暗纸，已改内容层纸面底色后重出。

必要检查见 `evidence/generation-check.json`：同参三图hash一致；换seed后真实造型参数变化；换palette造型保持而图像变化；换template衣装/建筑/持物变化；三种画风都实际生成；导出ZIP可打开，三图均960×960，CRC无错。基准世界 `tide/1337/style0/palette7` 与原作参考PNG字节相同：332e8c43f4a7e25fb67f5c1be00687b96fd382f9750ec3afdd42435945781c3d。

截图包含tide两个种子、archive铜版及tide像素，已看实际画面，不以功能检查代替审美。

## 2026-11-10 直接复用星球方法

制作人要求参考原星球的程序作画技术与审美。当前将人物/教团从“先画死明暗再套后期”改为二维颜色与法线输入；`surface_2d.gdshader` 直接引用原 `noise.gdshaderinc` 与 `common.gdshaderinc`，使用原噪声、胞格和 `style_shade`，并用同参数世界的实际光向及原天空。二维法线方向按世界坐标约定对齐，石材颜色-高度联系改编自 `s_drowned`，布料使用独立较柔的变化。原工程不修改。

`evidence/shared-surface-check.json` 是法线消融：将人物法线清空后人物输出改变，教团不变；并记录同参光向及原天空数量。另有同参/seed/色板/三画风检查及原世界基准校验。这些检查只证明管线与限定生成，不证明人物、教团的造型或审美通过。
