16. 祈求生成与回应系统（组合生成与旧冻结合同并行）
本节承接 §15 的研究，给出生成、回应、结算和续存规则。本批按制作人最新要求交付 50 条祈求与按处境变化的具体回应；不继续扩写至 100 条。全部案例见 阅读目录，策划源见 prayer_space_cases.csv。新情境使用具体回应及独立处境账本；原十二类机制卡继续按原合同结算。
16.1 玩家循环与生成单位
玩家浏览当前世界中的求告，看清谁希望改变什么，从当下可行的具体介入中选一项，支付费用，看到实际改变。后续来自这个改变留下的关系、暴露或责任。救人、得知事实、取得物件、建立供给关系各自有作用，不统一折算成一笔信仰奖励。
一次生成的单位是“处境”，祈求是其中一方的表达。处境保存世界、参与者及其不同立场、受影响对象、当前阻力、原危机时间、已知范围、目标状态和结果。多个参与者可以对同一处境提出相反诉求，但不得把同一结果重复出售。求告者可能隐瞒或误解事实；幕后事实在首次成立时固定，不因玩家选择某个选项临时改写真相。
求告者想要的结果与玩家所选介入的成功条件分别保存。例如请求“全船靠岸”，开路成功只建立通路，身体改造成功只赋予逃生能力；两者都不能显示“船员已经获救”。指引之后的普通行动，在条件齐备时按该处境既定结果结算，不要求玩家再进入逐人传话、搬运或阅读记录的菜单。
16.2 可组合维度与处境语法
生成空间由以下相互约束的维度组成；不按一个总表随机抽完整故事，也不将维度数量直接相乘作为内容量。
  • 生活背景：海港、土地、身体、亲属、律法、职业组织、信仰、工艺、梦境、异常通路。十种背景框架及条件见 prayer_space_frames.csv。背景可以重叠；世界有何背景取决于当地真实条件，不由文明类型名称硬推。
  • 社会位置：本人、照护者、职业责任人、利益获得者、受损者、权威持有人、被控制者；绑定既有人物及其可用关系。同一事故从押运员、货主或收货人的立场产生不同目标。
  • 核心关切：生存、生计、亲密、归属、尊严、自主、公正、名誉、权力、求知、信任、安宁、责任。允许复合，采用一个主关切组织原话。
  • 目标动词：保住、恢复、取得、脱离、揭露、隐去、迫使、阻止、接续、改变自身。每个动词必须有具体对象和可判定的目标状态。
  • 阻力与期限：自然风险、资源缺口、持有人拒绝、制度限制、关系冲突、既有责任、异常影响。请求窗口与原危机时钟分别登记。
  • 认识与意愿：求告者知道什么、相信什么、愿付什么、是否知道回应者身份；不得由“绝望”自动推导愿意变形、献身或改信。
  • 介入：有限操作、作用对象、尺度、持续时间、成功代价、失败风险；不按慈悲／交易／恐怖等固定档位填满菜单。
  • 表达：恳求、责问、交易、试探、抗议、炫耀；只能改变措辞时属于文字变体，不算新机制。
九种处境语法见 prayer_space_scenes.csv：危机迫近、生活缺口、控制与保管、冲突与裁定、责任与束缚、异常侵入、接触与诱惑、关系与相处、继承与延续。每种定义角色槽、必要前提、目标形状与时钟规则；推荐操作只是候选提示，实际合法性由操作合同与真实对象决定。
绑定顺序为：选择有当前联系的世界 → 选择兼容背景 → 绑定处境语法和实际对象 → 绑定求告立场与目标 → 生成回应 → 固定表达。不存在海洋不能生成渔获；没有实际亲属关系不能生成母女；没有权力的机构不能授予资格。普通背景可按 DEC-026 一次概括成立，只保存将被行动消费的事实，不新增完整市场、医疗或司法模拟。
50 条是这套空间的已写派生实例，覆盖海港、生计、身体、家庭、律法五种背景；其余背景只有生成框架，本批没有声称已完成对应篇目。实例中的职业称呼是角色槽，不是另建一套与正式 NPC 无关的人物库；进入游戏时绑定已定名字，不外露短编号或内部 ID。
16.3 回应的构成与合法性
有限操作的输入、输出、持续性和禁令见 prayer_space_operators.csv。回应是“操作 + 真实对象 + 明确参数 + 费用档 + 后果”，不是一段任意执行的文本。
操作包括揭示、指引、庇护、救助、修复、遮蔽、开路、转移、交换、誓约、限制、解除、身体改造、记忆改变、感官通道、公开显现、资格改变、持续依赖、假象、毁去、断联、接触和物件牵引。常用时长统一：庇护一轮；遮蔽、行为限制、通路两轮；感官通道、物件牵引、誓约与供给依赖三轮。选项以短提示表达收益诱惑、危险和不可逆性质；具体变化及其数值到执行后才揭晓。曲解明确“后果未知”，不提前剧透具体变形。
每个候选检查对象存活与归属、接触途径、操作者资格、对方意愿、所需物件、费用与当前局势。信息指引只在能给接收者新增有用信息时成立，玩家查阅已知资料不付费。交换要求实际可交付并已同意的对象；资格变更要求机构确有权限；修复不能重建已经灭失的人；幻象不能成为真实证据。非自愿干预必须是明确的限制、夺取或欺骗，不能包装成双方同意。
具体实例中的“仅在可逆时”“须有可接收地点”等，是生成与执行前置，未满足时不生成可点击回应。凡需要指定接收者、财物或作用范围，卡片出现前即绑定实际对象与数量，不能留给玩家选完之后才告知无效。
每项通常提供二至五种介入；实际只剩一种有意义的可执行介入时允许单选，零种则不能进入新可回应卡。按收益、代价、对象和后续状态合并重复候选。不能选择的不混入可选列表；已有卡因资源变化暂不可回应时，就地显示具体缺口，保留暂缓与放弃。普通回应只给短而模糊的后果提示；曲解明确标为未知，不展示未发生的具体结局。必付资源、成功点数、能否执行和使用一次回应机会始终可见。
回应的非人尺度与未知
回应按 approach 和 intensity 表达介入方式及异化程度：有限帮助、索取交换、强制支配、身体／身份／环境的亵变，以及曲解。它们是可组合的维度，不是每条都填齐的固定套餐；每个处境按实际取舍配置二至五项，不能靠换标题、随机删项或给同一办法加费用来制造数量差异。暂缓与不再回应不计入数量。
疯狂必须改变愿望的实现方式：保住生命却改变其赖以生存的身体；恢复归属却侵蚀身份；使话被听到却夺走另一个人的嘴。允许残酷、掠夺和非自愿改造作为邪神的选择，由明确状态与后果承担，不将所有回应包装成互利善举。人类愿望保持具体可信，非人的理解越过人类默认的身体、时间、关系与主体边界。
disclosure=unknown 的曲解只显示短提示 hint，不显示结果池、区间、权重、潜在结局及后续合同。未知来自愿望可能被怎样理解，不等同于单纯的成功／失败。底层 outcomes 按处境配置不同数量的有限结果，每项有独立 ID、正权重、当前前置、状态变化、目标、后续／维护及揭晓文案。
新生成回应仅投一次 D100。准备时把当前合法结果按权重分配到成功点数 1…P 的连续整数区间，每个分支至少一点，区间无空洞无重叠；超过 P 个合法结果则不能执行。正式提交用本次行动骰的实际点数命中区间，不再在成功后追加抽签。结果、骰点及区间随事务保存，预览、重开与完成后读档均不重抽。超出 P 时沿既有失败／灾变区间结算。旧档已经冻结的两次抽取合同保留原语义。
玩家执行前知道固定支出与未知性质，执行后看到已经发生的怪事及实际损失／变化；未发生的其他可能性继续保密。神迹检定的成功只意味着介入显现，不保证求告者得到善果，曲解结果不标成“成功救助”。旧存档已冻结的普通选项保持旧合同，不因新内容版本被变成随机曲解。
玩家标题一律是“处境＋身份”，例如“濒死的矿工”“落魄的修女”，可附姓名但不能只用姓名或诗化事件名。正文仅保留当事人的祈求原话，原话自行说清困境和希望；不另列背景说明及所求。世界、期限和可选姓名是定位信息。按钮解释介入态度，结果写实际发生了什么；最新表达规范见本节“回应文案规范”及 §16.10。后台的“真实／指定／实际／权限／可核实”由执行校验承担，不批量塞进玩家句子。规则必要的代价保留，禁止用整段限定条款磨掉场景。
16.4 费用、检定与四类结果
八种报价档见 prayer_space_costs.csv。费用档是该回应的报价，不是玩家看到的强弱档位。数值为本次设计初值：线索采用现行低语一、信仰零的可接近基线；局部短效略增信仰；修复与强制沿现行低语二、信仰四的深干预基线；永久改造增加信仰；公开介入增加察觉。未声称已完成经济平衡。
低语与信仰在确认执行时一次支付，失败不返还；条件失效则整笔取消、不收费、不占回应名额。报价中的污染与察觉为成功后本世界变化；灾变只追加该档灾变列，不再叠加成功污染／察觉。物件交付、永久变形、身份公开等成功代价只在对应事实成立后执行。另有逐轮费用时必须单列首轮费用、总次数和中断结果；首轮即发生的费用计入可支付检查。
新生成的每项主动回应（救助、交易、强制、变形、曲解等）均使用 D100 低点成功；查看、返回、取消、暂缓、不回应不投行动骰。每项执行合同独立配置 difficulty（-20…30，正数提高阻力）、check_kind（occult/social）、attribute 和 hint，费用档不再决定是否免骰。使用权能系统 §3 的未截断基础分，减本项 difficulty 后按共同上下限截断；人物能力、世界阻力及已有合格准备共同进入计算。主体默认是承受或理解神意的祈求人，不在结算时选择最高属性者替骰。多名受益者仍只投一次。
选择前只显示“掷出 1–P 成功”，不再重复百分比、四档概率或具体灾变。类型＋行动名称之外，提示只讲大致诱惑与风险，例如更容易脱险但身体将不再如常；不得捏造规则不存在的信仰收益或散众。成本与难度独立设计：非人变形可以比完整救助更容易，后果也更难挽回。执行后展示实际骰点、成功区间和这次已发生的紧凑结果。
  • 成功：完成该选项的成功效果，并落实全部已声明的成功代价。
  • 深成：本批没有额外的直接数量奖励，因此与成功产生同一组实体／关系结果。不得凭深成再救一人、再复制一件物品、把暂时庇护变成永久治愈。以后新增数量奖励时须在内容数据明确后沿共通倍率结算。
  • 失败：已付低语／信仰消耗，主要效果与成功代价不成立，原处境继续。
  • 灾变：同失败，再追加冻结报价档中的主体理智损失与本世界察觉增加。具体数值执行后展示，不能临时添加合同不存在的死亡、献身或第三方伤害。
交易同样投骰；双方同意是合法前置，并非成功保证。未来责任成立不意味着未来工作完成，每次交付仍按实际履约发生。价格和难度在绑定时固定，准备及局势在提交时重核，不追加隐藏费用。旧档已冻结的免骰交易保留原约定，新生成合同不再使用这条免骰路径。
16.5 结果如何进入游戏
结果必须写入可消费的状态，不以一段叙事冒充作用。开路建立通行窗口；转移改位置和保管；治疗解除指定伤病；机关认可改变限定资格；揭示更新指定接收者知情；身体改变获得明确能力和缺陷；供给建立有期限的服务与维护义务。每种实例中的目标、主要效果、成功代价共同定义操作的参数边界。
持续内容保留开始轮、剩余次数、付款人、实际对象、每次交付和中断结果。供奉型供给在本轮及随后两轮各另付一信仰；断供停止服务，无预告不得额外致死。实体粮食等分期承诺冻结原交付总量，不能每轮对剩余量重新取比例，也不能把约定但未到账的收入提前花掉。自动履约只执行已获同意的固定计划，有新的取舍才再次询问玩家。
本批中“获得指引”“听到证词”不自动让机构裁决、他人服从或人物改信；关系与信仰转变继续受原消费者规则约束。成功不一律送信众、忠诚或圣物。真实见证只记录实际看到的人；副本不增加独立见证。可能引出的追查按现有反制资格产生，不因一句“可能引起追查”立即凭空扣资源。
玩家结算只看本次骰点与结果、一到两句实际后果、实际发生的数值变化与尚需供奉次数。污染、察觉本身就是结果，不再另外复述为风险／效果／后果三份信息。需要继续推进的普通事项显示进度和缺口；不让玩家进入记录根、保管关系或因果图完成无取舍的手续。
16.6 生成、调度与重复控制
参数源见 prayer_space_parameters.csv。轮初先清理已解决、已死亡或失效的请求，再处理已预告到期事实，然后保留仍有效的旧卡并补足现行最低供给。最多同时展示三项，每轮最多回应一项；不要求补满三项。
每轮在轮转的已联系世界中，最多绑定二十四个完整候选；原有保障路线先保留，其余按稀缺位置参与选择。候选权重为近期新决策签名四、近期出现过的签名一；已存在且将到期的危机再乘二。签名保留十二轮，由背景、处境语法、主关切、利益关系形状、主要操作及结果边界组成，换姓名不算新签名。权重只在合法候选之间选择，不会先选一个故事再强造缺失前提。
同世界同处境语法默认间隔四轮，同人物普通新诉求间隔三轮；已展示请求继续存在不受冷却误删。一个已经确定的关键后果回调不因新鲜度被无限压住，沿既有机会保障与到期规则进入相应流程。背景候选未被选中不会每个都生成隐藏危机。无合法普通候选时返回原有最低供给合同，不能在 UI 新造一张保证成功的祈求。
每次实际生成冻结处境身份、角色、原危机、请求到期轮、允许披露的信息、回应对象与结果方案、报价版本及随机流状态。读档或打开详情不重抽；预览只读取当前资格与费用，不推进随机序列。提交时再核资源与目标，状态变化则取消并告知，不能静默换人或改价。
16.7 暂缓、拒绝与后续
所有祈求共享“暂缓”和“不再回应”控制，不为每个故事写一份固定沉默选项凑数量。暂缓无费用、不占回应名额，不重置请求或危机时间。不再回应关闭该请求，无自动退款、察觉下降或任意忠诚惩罚；原处境按已经成立的后果继续。
任何已经执行的回应，无论成败都消费当轮回应机会并关闭该卡。若主要目标仍未实现，后续只有在原规则允许且产生新决定时才能形成另一请求，不能原样再次出售或延长原危机。已执行的费用和唯一结果按处境根身份、回应提交与效果种类去重；另一个人对同一船货求告不能复制粮食或再收一份成功奖励。
回应导致的影响可进入下一轮回调，例如被救者面对公开见证压力、三轮供给即将结束、被夺走物件的原持有人作出反应。仅感谢或复述既有结果进入短反馈／编年史，不占主祈求。后续行为遵守角色意愿和权限，不能把所有受益者写成无条件忠诚。
回应文案规范（2026-11-09）
回应前只显示类别、介入态度、模糊系统影响、费用与成功点数。态度说明类别如何对待愿望，不提前叙述缝合、长鳃、移交等具体执行；具体实现与结果在结算后揭示。短提示按实际污染、察觉与灾变理智风险分档，不捏造信仰收益、信徒流失或未实现的“彰显”数值。曲解保留未知，不读取隐藏结果拼提示。
data/prayer_response_voice.csv 是独立于处境的可复用表达库，按类别和实际效果分档选择；正式投影与离线目录共用它。稳定选择以情境键和回应键为输入，不消耗游戏随机流，不更改旧档冻结合同；同一回应反复查看不改口。后续新增情境可以直接使用，不需要再复制一套回应前文案。原 CSV 中具体行动与效果继续作为作者规则说明和结算来源。
组合生产规则见 §16.10。表达库负责玩家措辞，容量统计按语义、决策和文字分别计数。
16.8 数据交付与接入边界
本批数据由六份 CSV 构成：背景、处境语法、操作合同、报价、调度参数、派生实例。实例回应字段依次存放“具体名称｜操作引用｜报价引用｜成功结果｜成功代价或局限”；阅读目录由数据生成，不反向从 HTML 提取策划内容。内部键仅用于引用，不在祈求或人物名称后显示。
生产装载由 src/content/prayer_space_catalog.gd 注册六份设计 CSV，并装载 prayer_space_runtime.csv（50 个有限处境）及 prayer_space_response_contracts.csv（每个回应的类型化执行合同）。效果由对象路径、前置、有限更新、定时规则和维护规则执行，不解析自由文案。独立版本和随机流保存在 prayer_system.space；已冻结的报价、结果合同与旧消费身份保持原语义，兼容新内容版本。
历史有限池的调度边界：固定情境绑定聚焦世界与现存活跃人物；CIV01/02/03/04/06 支持本批人类生活背景。每轮合计最多三项，其中新情境最多两项，保留原机制供给；24 候选预算、处境四轮／人物三轮冷却、十二轮签名记忆（当前签名为背景／语法／关切）；尚未采用已存危机加权及利益关系／结果边界的完整签名。五十个有限处境依真实角色绑定派生，不宣称已经实现其余五种背景或任意自由组合。普通背景首次固定后由处境内对象、责任与定时消费者推进，不新增完整社会模拟。
正式界面以处境身份为标题，正文只有祈求原话；回应显示类型、行动、短模糊后果、费用与明确成功点数。首次维护费单列，失败不扣成功后维护。暂缓只关闭阅读，不再回应关闭请求但不取消危机。玩家投影不外露执行合同、完整场景快照或底层因果图。真实执行经过 Session、准入、轮次事务、实际扣费、结果及保存恢复链路。
神迹与亲历。 每个明确回应和曲解分支在 prayer_space_response_contracts.csv 声明 miracle，空对象表示没有超自然显现。其余配置指定公开性及真正亲历的角色，可以没有具名见证者。普通交易、出示证据等结果不会因为耗费资源或增加察觉而产生见证。玩家执行前的曲解保密与世界内公开性独立。
已选分支实际改变情境或危机期限时，以本次结果为因果来源登记神迹。指定延迟显现由原定时效果在条件仍成立且实际生效时登记，维护支付及普通后续不重复产生见证。仅向当前在场的合格亲历者登记个人见闻。原 NPC 解释行为按该经历消费一次，保留原冷却、属性成长与公开异常规则。扎根依托仍取原路线的专用材料。存档保留每项祈求冻结时的合同，旧结果无追补。
运行检查与交付范围见 接入任务。内容合理性、表达与取舍由制作人审阅；机器检查不代替体验判断。

16.9 新版祈求跨系统后果（2026-11-08）
本节补齐 §16.8 的神迹亲历之后，祈求结果对人物、材料和事件的影响。接入任务记录验收与范围。
完成目标。 祈求中的代价实际约束人物，收益推进对应玩法，后果延续到后续局势。范围覆盖现有 50 个情境、178 项回应和 56 个曲解结局中的跨系统后果，包含即时结果、危机、到期、维护及延迟效果。后果覆盖清单逐项列出实际对象、时点、亲历者、材料和事件消费者。没有外部用途的处境对象由本情境及其期限继续处理。世界名称本轮检查通过，教团名称仍为静态独立目录，本整改聚焦已确认的祈求断裂。
#### 16.9.1 人物限制贯穿玩家指令与自主行为
原缺陷：归乡者回应后 can_act=false，结果承诺三轮无法行动，仍被 World.choose_behavior 选中执行 NPC_INTERPRET 并获得成长。原先只有玩家入口读取情境限制。
规则：
  • 共用不含回合阶段判断的人物能力检查。玩家入口继续检查当前阶段和行动名额，自主行为读取同一人物限制；结算重查相关资格。按现有合同，“无法行动”阻止主动任务、调查、安抚、自我整顿和解释神迹；“无法入睡”单独限制入梦。
  • 自动计时、被动结算和状态解除按各自规则推进。临时状态的解除绑定受影响人物及原到期条件，另一位参与者离开不得使有限期限变成永久限制。人物死亡或转移分别处理，恢复不复活死者、不授额外行动次数。
  • 存档保留来源及剩余期限，多项限制并存时分别到期，解除其中一项不抹掉其他限制。
  • 人物卡及选择列表就地显示具体状态和实际剩余轮数，例如“意识沉睡 · 剩余2轮”；不可选原因与真实规则一致。恢复只给一次简短反馈。玩家据此安排人员和承受祈求代价。
关键接驳点为 prayer_space.gd 的效果与到期、prayer_rules.gd 的能力读取、action_admission.gd／权能入口、World.choose_behavior 及自主结算，以及人物投影与选择列表。
#### 16.9.2 具体经历、证词和物件推进对应目标
原缺陷：“把审讯记忆留在另一人脑中”更新了情境的 received/copy，回执宣称另一人已获得内容，正式材料识别与交付消费者仍只接受旧来源，相关玩法无法消费该结果。
规则：
  • 相关 CSV 合同明确结果类型、真实来源、原亲历者、实际接收者或物件持有人，以及可支持的既有用途。普通知情、亲历神迹、获得书信和取得他人记忆分别建模，复用已有事实与材料接口。
  • 同一次成功结算原子完成情境变化、实际知情或物件交付、对应消费者刷新。曲解只落实命中结局，延迟结果在真正发生时接续。失败、重复提交和读档不复制来源、物件或奖励。
  • 新来源接入材料识别、合法传递、机构条件和锚点检查，保留来源真实性、机构范围和当前有效性。复制同一段记忆不增加独立见证人数，得到仪式说明不自动取得实践资格。普通证词仅服务明确用途；满足对应路线规则的神迹见证才影响锚定条件。
  • 玩家在已有玩法目标中安排必要传递。例如建立锚点时，显示具体待办、费用与预计补足的缺口，完成后原处更新条件。独立“交予记录”入口继续撤销，原始因果图不进入玩家流程。
  • 玩家侧按实际事实显示“艾达记住了那场审讯的细节”“艾达拿到了审讯笔录”“艾达亲眼看见牢墙开口说话”“审讯证词已送达”。目标使用现有结构化条件控件呈现“审讯证词 · 已送达”“独立见证 · 1/2”等真实状态。示例中的人物、数量和用途由当前规则决定。
  • 全部相关祈求、活动、锚点条件、事件选项、回执和帮助清理“保管记忆”“保管记录”“保管者”等抽象泛称，按具体动作、对象及用途重写。内部 custody 等字段可继续承担规则职责。统一玩家表达约束见内容手册。
关键接驳点为新版回应 CSV／Catalog／实际结果生产、Anchors.material 与证据识别、material_transfer.gd、人物及机构知情、目标条件重判和相关投影。实际接线由回应的 consequence 声明冻结。公开异常的亲历见证进入独立证言路线；私人审讯与听证证词提供公开与保密的后续决定。其他具体记录保留其实际接收和处境用途。
#### 16.9.3 真实后果进入后续事件
原缺口：Events.observe、EventRules.descriptor 和来源审计依赖旧回调、旧到期记录及入梦来源，新版结果／进展／神迹原无事件适配。新版神迹到 NPC 解释已接入，世界数值也能影响反制；本项补具体祈求经历的后续决定。
规则：
  • 在 CSV 逐项声明有玩法意义的后续条件、原对象、允许事件及一次性身份，覆盖相应的实际结果生产、候选构造、准入、执行、审计与存档。使用同一原处境和首次满足条件去重，重复 progress 不重复发事件。
  • 例：“照亮回港的航道”在船员实际归岸的进展发生后，核同一位幸存者、原神迹及当前处境，可接“活下来的代价”的适用分支。身体已永久异变的分支需匹配其现状的选项及后果。即时照亮航道本身不等于已经获救。
  • 固定真实当事人、物件、机构及原经历，弹出及执行时重查状态。失效、死亡和已解决按具体规则关闭。私密经历不会自动成为全社会知情；公开传播及调查须有相应真实依据。
  • 沿既有轮初事件入口、数量上限、冷却及机会调度，按实际发生时间进入后续窗口。普通感谢、付款和进展在回执呈现；存在新决定时才占事件位置。
  • 新版到期独立核对请求窗口与危机期限，不直接套旧 EVENT_12 重开逻辑。重新出现的请求须有新的合法决定，不能重置危机或重复出售同一结果。
  • 玩家看到具体后续，例如获救船员向港口讲述神迹，并对公开传播、保护当事人或异变作出规则支持的选择。选项承认已有结果与身体变化，持续使用当前祈求／事件的信息精简标准。
关键接驳点为 prayer_space.gd 即时／延迟结果、事件来源 CSV、Events.observe、EventRules 候选与校验、调度及正式事件界面。具体适配按结果语义确定，维护付款、普通船只扣押等不能凭相似措辞冒充原契约或圣物事件。
#### 16.9.4 实施与交付边界
策划映射从 CSV 装载并随回应合同冻结。旧冻结回应保留价格、骰点与结局语义，现存人物限制按原剩余期限继续。新取得的材料及新后续事件由含相应声明的合同生产。历史回应不重放，也不补发过去的收益及事件。
正式 UI 沿当前 echoes-ui-motion-v1 基线及 visual-system F5/D5、P02/P06/P16、G3/G5/G7；信息归属、固定标题、局部滚动和结构化条件保持既有合同。实现必须覆盖规则与表现两端。每条结案以“代价限制了谁、收益推进了什么、后果在哪里继续”检查；具体验收及证据放在接入任务。核心闭环、直接异常、兼容及必需检查通过后按 stage-priorities 收口，不扩展无依据的长局回归或重复截图。

16.10 组合祈求生成器：实施合同（已接正式 Session，待制作人验收）
正式生产从十类背景、处境模板、诉求和效果配方组合候选。本节规定新生成祈求的行为。50 个历史情境及其冻结回应继续按原版本结算，作者可在查看器切到旧案例。§16.9 的真实后果、知情、来源与幂等约束适用于两条链路。实施范围与待验事项见 G01–G08。
#### 16.10.1 必须达成的行为与容量口径
  • 生成单位分为 共享处境 Situation 和 一方诉求 Request。先生成／读取事件、对象与关系，再求解诉求、回应、文案。新增背景、阻力或立场可与已有规则组合，无须新增整篇 case 或逐条重写所有回应。
  • 正式生成入口不得遍历 prayer_space_cases.csv 的 50 个 case_id 抽故事；现有案例仅用于回归参考、拆分素材和继续旧档。固定案例可保留作者查看入口，但必须和新生成器明确区分。
  • 数量分别报告 wording_count（文字）、situation_signature_count（合法语义处境/诉求）、decision_signature_count（实质取舍结构）。姓名、世界名、语气、同义句、随机种子、微小数值差均不得增加后两项。
  • 首版容量目标为至少 1000 种合法语义组合、100 种决策结构，十类背景各有可执行生产和结果消费。参数表数值是设计目标，不是现有测量或平衡结论。不能通过添加无用途字段或数值抖动过关；达不到则报告实际数量与短板，不能宣称完成容量目标。
  • 玩家标题只用处境＋身份，可附姓名；正文只留祈求原话。回应显示类别、介入态度、简短系统取舍、实际支出和成功点数。具体执行与结局在结果后揭示。禁止通过新增背景、所求、已知效果等栏目补足生成器的信息缺陷。
#### 16.10.2 数据源与装载合同
所有策划参数和内容 CSV → Catalog → 规则编译；不在代码里写题材、职业、祈求、效果蓝本。Catalog 加载新生成表并编译受限谓词和写入规则。生成版背景与处境使用 prayer_generator_frames.csv 和 prayer_generator_scenes.csv，原表用于历史合同与阅读。字段以下方语义及 CSV 实际表头为准。
1. prayer_generator_frames.csv：id,requires_tags,excludes_tags,entity_types,register_tags,base_weight。自然环境、社会制度、身体形态来自世界能力标签和实际对象；不得根据文明或世界名称猜测，不能把 CIV01…名单当唯一兼容条件。缺失环境信息时只用显式已知兼容背景。
2. prayer_generator_scenes.csv：id,role_slots,object_slots,predicates,initial_facts,clock,allowed_goals。JSON 字段声明类型、基数、必要关系和允许一次概括成立的普通事实。登记普通家庭关系／职业前须检查既有关系及身份，无矛盾方可创建并保存；不可每次为同一人重造职业、配偶或过去。
3. prayer_generator_intents.csv：id,scene_tags,stance,roles,knowledge_predicates,desire_predicates,goal,belief,allowed_approaches,appeal_registers,base_weight。立场描述受害、受益、责任、竞争、照护等；belief 是人物认识，不覆盖处境真相。愿付代价与忠诚、知情分别保存。
4. prayer_generator_effects.csv：id,operator,requires_tags,predicates,bindings,writes,goal,followup,upkeep,capabilities,miracle,consequence,base_difficulty,check_kind,attribute,tradeoff_profile,result_text_id。把现有 prayer_space_operators.csv 的文字合同编译成可执行原语。一个原语可用于多个背景；新增题材不得要求在执行器新增 case_id 分支。特殊原语可新增受限 adapter，但须写出消费者与失败语义。
5. prayer_generator_twists.csv：id,concept,compatible_goal,requires_tags,reinterpretation,effect_recipe_ids,weight,result_text_id。concept 为对象、归属、状态、时间等语义维度；reinterpretation 是有类型的目标变换，不能是供程序自由理解的自然语言指令。
6. prayer_generator_language.csv：id,kind,register,required_slots,required_facts,forbidden_tags,text,weight。kind 为身份标题、原话短段、连接段、结果句。使用编辑过的完整句／短段，带受限占位符；选择规则维护主谓、数、称谓、时态及人物知情。不同动机用不同段落结构，不以统一“我有{问题}，请{动作}”覆盖全表。
7. prayer_generator_parameters.csv、prayer_generator_tradeoffs.csv（当前运行初值）：前者为算法初值；后者为已讨论的四类亵变取舍基型，不是强制四选一。实施时扩充其他类别基型，不能只实现亵变。prayer_response_voice.csv（已有）负责态度和提示词，增加事实条件及系统分档引用，避免泛用词错误暗示肉体变化或无代价。
谓词采用受限 JSON AST：all/any/not、eq/ne/gt/gte/lt/lte、has_tag、exists_relation、knows、can_reach、owns、can_execute；量词仅遍历已绑定的有限角色集合。类型声明区分 person/group/institution/item/place/service/fact；写操作仅允许 set/add/remove/link/unlink/schedule 经注册 adapter 执行。禁止 eval、任意对象路径、文件访问或执行文本。Catalog 验证所有引用、类型、读写域、费用非负、计时终止和消费接口；未知原语装载失败，不能静默变为纯文案。

  • Request 引用 Situation；Response 的目标引用共享对象 ID。禁止把每个求告者的事故复制进各自 scene.objects。矿工被救后，对该矿工仍在井下的请求重新判定，已满足者关闭，不重置事故时间；矿主对暴露责任的恐惧仍可能成立。
  • 现实事实、人物相信的内容、玩家已知信息分开。每项生成事实标记 existing 或 background_committed 来源；不可把候选草稿写入世界，也不可用错误信念生成客观证据。
  • 普通背景仅在候选被正式选中时原子登记；最多每轮登记两个新背景，直接复用现有处境不占新背景预算。资源不得从既有主体无来源增加；新普通物件如需建立，记录其原归属及一次性背景来源。
  • 效果幂等键为 (situation.root_id, response_execution_id, step_id, target_id, effect_kind)；竞争目标另外使用目标状态版本和消耗锁，防止不同 request_id 对同一物件重复交付。独立见证仍按真实经历根去重，不使用执行 ID 增加人数。
  • 同一事故允许多方求告，但并不要求同时展示。已被别的行动改变的对象在提交时重核；失效整笔拒绝，不换人、不换价、不临时选另一个隐藏结果救场。
#### 16.10.4 有界生成与调度算法
在既有轮初供给位置：
  先推进旧计时/真实后果并清理失效请求，保留未过期卡
  读取现有最低供给/关键机会资格（不改变其原保障合同）
  轮转有联系世界，取已登记处境或只读构造普通背景草稿
  至多尝试 candidate_attempt_limit 个组合：
    用类型与关系索引绑定角色/对象（限定集合，不做全 NPC 笛卡尔积）
    求解立场、认知、目标；已达成目标或无真实阻力则丢弃
    至多尝试 response_attempt_limit 个兼容介入配方
    编译效果与跨系统消费者，判准入，合并重复，留下 1..5 项
    候选至少含一项当前付得起且有效的回应，否则丢弃
    按知情边界生成标题/原话；表达缺槽则丢弃，不展示半句
    累积至多现有 candidate_budget=24 个完整合法候选
  先保留既有保障/到期服务；其余按 W 加权无放回选取
  原子提交入选背景、请求、合同、随机游标和历史签名
  总可见上限继续为3，每轮回应1；不要求每轮补满3

候选的角色／对象索引分页和游标必须随档保存，避免永远尝试排序最靠前的人。预算耗尽即使用既有合法保障通路，不循环到“抽出成功候选”为止，不生成伪造保底故事。新请求可接现有普通与关键机会槽，不能无条件挤掉原有限来源路线；保障来源身份不得用普通生成卡冒充。
随机流：世界种子派生固定算法子流 prayer-generation/v2，用于候选和文字；独立于行动 D100、事件和世界命名。使用稳定编码及散列（例如 UTF-8 SHA-256 的固定字节序种子），不能依赖运行时随机 hash 或 Dictionary 遍历序。所有 ID 先排序；同种子、版本和输入状态复现。候选尝试无世界写入，批次结束一次提交抽签状态。浏览、预览和查看器过滤不得推进战役随机流。
#### 16.10.5 去重、选择权重与重复统计
定义规范化签名（稳定 JSON 序列化后散列）：
  • S：背景能力类别＋处境语法＋立场＋目标谓词形状＋阻力类型＋关系拓扑＋认知偏差类别。去除具体姓名、ID、世界名、文案、种子。
  • D：目标形状＋规范化的可选回应集合；每项包含操作族、受益/受损方角色、即时/持续/永久、已实现能力变化类别、供奉/污染/察觉/理智风险档、是否未知。去除态度同义词和具体小数值；排序集合防止选项顺序制造新签名。
  • T：最终展示文本，仅用于统计文字变体。
最近 recent_memory=12 轮统计：nS,nD 为签名出现次数，nw 为世界出现次数，nmin 为有合法候选世界中的最小次数；U=1 表示已登记危机在下一次轮初之前到期，H=1 表示来自真实结果且有新目标或新取舍的后续。
N = 1 + novelty_weight / (1 + nS + nD)
B = 1 + world_balance_weight / (1 + max(0, nw - nmin))
W = base_weight * N * B * (urgent_weight if U else 1)
    * (1 + followup_weight * H) / (1 + repeat_divisor * nD)

沿现有处境4轮/人物3轮冷却；同 D 普通候选在最近4轮出现则硬排除。关键机会及真实有期限的后果不受新鲜度无限压制，走原调度保障；例外原因进入作者诊断。权重只改变合法候选之间的机会，不创造前提、修改报价或延长期限。为可复现，加权实现采用固定精度整数（统一乘1000取整且最小1），不能在各平台使用不稳定浮点累加抽签。
同一请求内先按实际写集、成功目标、成功代价、失败/灾变、持续责任和未知结果集做等价合并。之后最多选5项，优先保留不同 D 子结构；不得保留“相同作用，仅换价格”的重复项。非未知分支若收益/约束完全相同且在成本、难度和风险各维都不优，则去掉被严格支配项；不可把不同受害者、永久变化或未知结局简单压成数值评分后删除。
#### 16.10.6 难度、费用和系统后果公式
参数从两张生成参数 CSV 和既有 run_parameters.csv。下列算法是首版实现合同，初值尚未经过长期经济平衡。成本与成功难度分别计算，禁止从价格反推难度，也禁止为亵变统一加难度。
参数取自已绑定效果，不随机摇档：
  • s：规模档。人物目标 s=ceil(max(0,n-1)/scale_group_size)；n 是真实受影响人数。s 大于 scale_max 则拒绝，不能截断后宣称救了全体。物件/机构/区域效果使用各原语显式声明的单位与分档，不拿人口绝对值充数。
  • p：即时0、跨轮有限1、永久2。ds=max(0,s-base_scale)，dp=max(0,p-base_persistence)；基型已含的规模/永久性不再收费加难。低于基型不得套高基型暗自折扣，应选另一匹配配方。
  • v：额外公开真实受众0/1；h：配方允许的额外隐蔽0/1；二者互斥。基型本身已有隐蔽时 h=0，避免重复减察觉。
  • r：操作配方声明的目标直接反抗0..2；a：已登记有利前提0..2。两者仅描述本次目标，不重复计算世界屏障/察觉、人物属性、既有谕言准备。
D = clamp(base_difficulty + 4*ds + 3*dp + 4*h + 4*r - 3*a, -20, 30)
F = base_faith + 1*ds + 1*dp
L = base_whispers
成功污染 = base_pollution + 2*ds + 1*dp
成功察觉 = max(0, base_alert + 2*v + 1*ds - 2*h)

数字分别读取参数表对应行，不能把本段抄为代码常量。效果配方须匹配贸易基型条件；低费用持续供奉型必须真正建立维护，不得单独取其低价给永久无义务结果。成功理智损失、灾变理智损失、灾变察觉分别读配方，指定实际承受者。成功与灾变的理智影响分别登记到实际承受者。
D100 沿 Powers.probability，只在最后截断一次：
B = check_base + check_attribute_step * (actor.attribute - tier_difficulty)
    + clamp(preparation, -check_preparation_limit, check_preparation_limit)
    + sanity_modifier(check_kind, actor.sanity)
    - floor(world.barrier / check_barrier_divisor)
    - floor(world.alert / check_alert_divisor)
P = clamp(B - D, check_probability_min, check_probability_max)

不要先把 B 截断，再减 D。B 使用现有原始函数输入；当前上下限10..90由原参数表读取。行动主体冻结为实际承受/理解神意者，不能执行时挑最高属性者。费用与 D 生成时固定；P 随当前合法局势和准备重算，玩家点击执行须使用当前预览及对象版本，不静默执行过期确认。前提/代价改变须重新生成明确选择，不能悄悄改冻结 D。
一次确认先验证全部资源（含成功首期供奉）和效果，再原子扣 L/F、消费回应名额并投一个 D100。失败只扣已确认执行费；灾变沿已有四档分区追加灾变后果；成功/深成执行成功写集、成功理智损失和实际首期供奉。成功污染与灾变察觉不相互叠加冒充双重惩罚。深成不自动复制人、物、资格或奖励。
四种亵变可核算例：prayer_generator_tradeoffs.csv 给出单人、基型原定持续性的四种剖面。令相同局势 B=72，ds=dp=v=h=r=a=0：成功点数依次80、60、75、75；即时信仰依次4、4、1、4；成功污染依次8、1、2、4；成功察觉依次4、0、1、2；成功理智损失依次0、8、0、2。低首付型另有每期1、共3期维护。它们是可供不同处境调用的取舍组件，不要求同卡同时出现，不声称这些常数是正式游戏当下行为。
供奉：installments=3 包含成功当轮第一期，再于随后两轮各扣一次；预览显示执行费、成功另付首期、剩余期数/总额及停止规则。总承诺 F_total=F+upkeep_faith*installments，立即所需 F_ready=F+upkeep_faith；未来钱不能当作已经拥有。断供只执行冻结 on_stop。首版低首付型默认停止服务、不追加伤害；若停止会因原危机致死，候选必须能明确提示原危机继续且有有效应对窗口，否则不得使用该“安全断供”基型。
#### 16.10.7 能力变化与其他真实消费者
“改变今后用途”须建立 CapabilityModifier {person, granted_tags, blocked_tags, conditions, expires?, source}，不能仅写成 scene 内布尔值。每个新能力必须有至少一个正向消费者，每个限制必须有真实拒绝/撤职/派遣边界；例如水下能力要有实际可进入的探索或工作路径，陆地限制须由任职、活动、转移及自主行为共同检查。没有对应玩法消费者时，拒绝生成该效果，不交付装饰性能力。 接手者需补消费者后再启用；不能以关闭第四种取舍冒充全部接入。
多来源限制按现有 PrayerRules.space_allows 的全部有效来源合取，任一有效阻止则不可执行；到期只撤自身来源，不复活死亡人物、不覆盖后来的身份。永久改造必须与旧档现有身体特征检查兼容，后续普通背景不得覆盖它。效果触发失格时通过既有角色/任职生命周期解除相关职务，回执显示已发生改变，不能留下一个无法工作的任职者却继续结算其贡献。
证言、知情、物件、神迹、救援和供给通过 §16.9 现有 adapters 产生真实来源；prayer_consequences.gd 当前只接受有限 kind，必须显式注册新增种类和消费者，不把它当任意结果容器。Anchors.material/HistoryIndex/MaterialTransfer 仍区分知情和亲历，同一来源副本不多算。每项新 recipe 声明 consumer_ids，装载与准入都检查；不得仅修改中文反馈。
#### 16.10.8 曲解编译与单骰区间
先从已冻结愿望的 typed goal 中提取概念槽，再应用兼容的目标变换（对象、归属、状态、时间），生成能落地的效果配方。不能从玩家原话用关键词自由猜逻辑；原话和变换共享同一语义结构。不能把“某人认为海是家”直接写成全世界的地理事实，也不能用时间曲解绕过已死亡状态复活人物，除非未来存在明确获准的相应原语。
冻结候选结局、正整数权重和结果句，至少两种实质不同后果才展示曲解。提交前合法分支数量 N 必须满足 2<=N<=P；失效到只剩一种则该未知选项失效，不冒充随机谜底。曲解各分支须共享公开收费/维护条件；其他风险按所有合法分支的范围生成诚实提示，不能抽中后突然增加未披露的供奉。具体结果、权重、区间不进入玩家投影。
复用 _effect_ranges 的最大余数分配：
R=P-N; W=sum(w_i)
x_i=R*w_i/W
count_i=1+floor(x_i)
将 P-sum(count_i) 个剩余点逐一分给 x_i-floor(x_i) 最大者
并列按冻结 branch_id 顺序；连续累计得到各 [first_i,last_i]

只投一次 d∈[1,100]；d<=P 时执行命中区间的唯一分支，d>P 按原失败/灾变规则处理。例 P=60，权重1/2/1，N=3：长度15/30/15，区间1–15、16–45、46–60。所有区间、版本、实际骰点和唯一结果入事务；读档不重新编译结果池。深成依然只是神意更有效地显现，不自动变善良。
#### 16.10.9 后续生成与文案边界
实际结果通过已知消费点发布一次 ConsequenceOpportunity {root, result_source, actors, changed_facts, eligible_intents, depth}；用原对象继续生成下一诉求，只有新目标或新取舍才入候选。同一次结果同时命中旧事件与新求告时共享消费仲裁：一个决策只能由一条入口承接，另一条最多成为无操作反馈；不得再付一次钱领取同一收益。
同根最多3层主动衍生，超过只保留状态和短反馈；后续有独立新事件可以成为新根，但必须有新因果来源，禁止用换 ID 绕过深度限制。请求到期与危机到期分离。后续不得回滚已发生的救援、异变、死亡或公开状态。
表达分三层：事实绑定/目标 → 编辑过的句段选配 → 冻结完整标题/原话/态度。原话只消费求告者知道或相信的槽；未知真相不因模板插槽泄露。缺文案时该候选不发布；不得用内部 ID/类型/“保管记忆”兜底。抽象或非人文明需有兼容身份与生活词料，不能把所有背景都说成矿工、母亲和港口。
短提示由真实结果维度派生：成功污染、成功察觉、成功必付理智与灾变风险分开；零值不能描述为增加，失败风险不能描述为成功必损，未知风险取可能范围并标“可能”。只选最影响当前取舍的至多两个风险维度，供奉和能力代价若存在必须保留；不重复资源费用和骰点，不暗示未实现的信众收益。所有基型的“成功理智”与“灾变理智”语气不同，现有只按灾变列写 hint 的 prayer_response_voice.gd 必须相应升级。没有独立“彰显”机制时使用现有察觉，不为文案新造数值。
#### 16.10.10 模块接驳、兼容与失败处理
运行模块包括 src/game/prayer_generator.gd 负责只读有界求解；src/game/prayer_effect_compiler.gd 将 CSV 配方变成 typed writes、预览和消费者；共享处境注册表独立于 Request，仍由 Session 事务拥有。具体实现登记到 architecture，不能由 UI 持有世界事实。
接入点：src/content/prayer_space_catalog.gd 装载/类型校验/版本；PrayerSpace.freeze 新生产入口；prepare/commit/deadlines 执行新合同和共享时钟；PrayerRules/World.choose_behavior 能力准入；prayer_consequences.gd、Events/EventRules 后续仲裁；Session 保存/恢复与玩家投影；production/prayer_space_view.gd 读取同一投影；查看器通过生成核心导出结果，不能另写一套 JS 故事算法。
新合同 generator_policy_version 与旧内容版本并存。按 scene/response 的 schema 分派：旧 schema1 保持固定合同、旧随机语义和未结清责任，新 schema2 才使用共享处境。迁移只安装新生成器状态及生产入口，不将所有历史 scene 重新生成、不回填奖励；旧活动和计时继续执行。首次迁移保存 policy/rng/source；幂等恢复不能重复安装。
冻结文案、配方和关键参数快照，未知新版本必须明确拒绝/提示，不得回退到现行表重编历史结果。新增保存审计核对象引用、原始授权、区间、写集和一次支付链，不能只把新 hash 加进 LEGACY_VERSIONS 即称兼容。旧档活跃请求、持续维护、隐藏结果已命中后的保存三类均须代表性续存。
不兼容背景/无合法主体/无消费者 → 候选拒绝并作者侧记录原因；无可支付项 → 不发布；已有卡资源不足 → 显示缺口允许暂缓；提交发生版本变化 → 无副作用拒绝；任一 adapter 失败 → 回滚整个行动，不扣钱/不占次数/不留下部分证词。每轮执行和生成有预算，无递归重试与同步全世界遍历。
#### 16.10.11 查看器与有界验收
在现有 docs/content/prayer-space.html 所在入口提供生成模式：输入种子、固定背景/处境/立场、连续生成下一批、锁定同一处境看不同求告、重现一个实例；固定50条移至“旧案例”。玩家预览默认只显示允许字段，作者展开可看组件、前提、真实后果、价格/D 推导、签名与拒绝原因。浏览器通过本地只读生成服务或 Godot 核心批量导出调用同一规则；查看器假想世界明确标“预览环境”，不得污染玩家存档。独立祈求浏览和同根多方诉求两个模式都支持。
验证分层且一次收口：CSV全量引用/类型检查；一次有上限的离线容量抽样，最多10000次候选尝试，记录种子、成功/拒绝数、三类容量和十背景覆盖；不跑10000次完整战役。容量报告是该样本观察到的下界，不是全空间总量，不能用乘法宣称上限为已实现内容。选择少量代表性真实 Session 做普通/曲解/维护/能力变化/同处境冲突/后续仲裁/旧档续存闭环，边界合并验证；正式标准和大字各复看一个代表界面。核心与必要边界通过即停止，不反复抽样直至数字好看；文案、玩家感知和好玩与否由制作人审阅。

15.1 研究依据与设计提取
以下历史材料不构成普遍心理学定律，也不用于把真实宗教映射成邪教；采用其中的生活处境、社会关系和求告行为。小说采用其冲突结构，不直接搬用角色、神名和剧情。
  • 大都会博物馆：产后还愿浮雕：馆方推测母婴存活的场景是向治疗神表达保护后的感谢。提取：身体、照护关系、人生关口，以及求援之后的还愿；不把感谢本身都做成需要玩家再次付款的主祈求。
  • UCL／Petrie Museum：致亡者书信：向近期去世的亲属求助，涉及疾病、财产争议与生前／死后的照料义务。提取：祈求依附于具体关系和互惠期待，语气可以是恳求、追问或责备；不一律写成陌生人的绝望献身。
  • UNESCO：妈祖信俗：海洋生活背景之外也涉及生育、平安与日常问题。提取：职业风险、社区仪式与个人生活共同影响求告；日常希望也能成为动机。
  • 不列颠罗马铭文：Biccus 诅咒片：被盗物品与向神转交的表述。提取：寻回、惩罚与申诉可以共存，也可以分离；对神的求告并非天然无私。
  • 《印斯茅斯之影》原文：渔获、财富与非人力量的交换。提取：现实利益能够建立长期依赖，个人受益可能转成整个社区的责任与冲突。
  • 《暗夜呢喃》原文：以脱离身体的旅行与知识作为诱惑，交流者身份和信息可信性构成恐怖。提取：愿望可以真的得到满足，同时改变主体的身体、控制权或判断条件；不能把所有代价压成理智扣点。
  • 《克苏鲁的呼唤》原文：梦境、雕塑与远方的记录逐渐关联。提取：接触未知不等于已知神名或加入教团，同一影响可被不同人理解为疾病、灵感或征兆。
  • 《星之彩》原文：看似丰盛却不能食用的收成，以及生活环境逐步失常。提取：成果的外观与实际可用性可以分离；此结构不是每次回应必有恶意反转。
