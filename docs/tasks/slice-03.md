# Slice 03 · 正式经济与收入

系统集成任务 `TASK-ECONOMY`，由作者“继续”的指令授权执行。前置 `TASK-TURN` 在开工时验收通过且来源匹配；唯一任务状态、依赖与检查绑定在 [追踪登记](../implementation/traceability.json)。

## 可观察目标

正式经济接入统一回合后，传教与供奉先使用现有信仰，收入随后按真实资格计算；新招募或迁入的人不能顶替本轮损失的老信众领取收入。三种策略改变真实人口、察觉和收入，人物／文明不能因执行顺序看到同批新变化。存档、失败重试和重复输入不制造资源。

## 依据与范围

读取 [回合与经济](../specs/system-turn-economy.md)、[人物与人口](../specs/system-powers-cults.md)、[锚点供奉](../specs/system-progression.md)、[架构](../architecture.md)及正式 CSV。共享结算沿 `SET-RESOURCE / SET-POPULATION / SET-TURN / SET-ANCHOR / SET-SAVE`；不能复制第二份人口或资源真相。

本轮实现已有教团的正式经济：三种策略、前置支付与缺资降级、合资格无名信众收入、容量与溢出、招募与自然流失余量、可读支付预览与计划锁定；接入已有锚点的真实供奉支付顺序和拒付时点。人物提名、群体转化／迁移／损失必须同步维护收入资格，不能用轮初与轮末总数取小值代替存续资格。

完整教团形成／玩家任命、全部权能、锚点创建修复及完整文明机构资格、事件和终局仍归后续任务。蓝本独特条件由上游有来源的资格事实提供，本轮必须重查已能实查的对象条件。缺少必需资格凭据与明确不合格分别报告；不能默认为成功，也不能以静默空集合掩盖缺失。验证会明确披露已有对象和上游事实的准备，正式经济公式与效果必须由生产规则执行。

## 分工与交付

- **design**：原地补齐经济 spec 的人口资格、流失取样与支付冲突口径，不新增数值方案；之后只读核对实现与断言。
- **code**：负责 `src/game/economy.gd` 及必需的统一回合／世界接入，编写 `tools/economy/run.gd` 集成驱动；真实生成经济报告并回归原套件。证据包装器 `verify.py` 与入口说明由 director 协助维护。
- **qa**：独占 `tools/economy/qa_cases.gd` 与独立验收报告，构造套利、半笔结算、非法输入和存档续跑反例，不改生产源或降低验收标准。
- **整合**：维护本任务书、架构、追踪、当前进度及工作台，绑定真实检查编号和来源指纹。

共享代码与文档按上述所有权协作，不回退他人工作。经济沿既有方案单线实施，以可否证断言检查，不开并行数值候选，不把机器测试当作平衡或乐趣判断。

## 验收

`ACC-INCOME` 加本轮 `ACC-ECON-COHORTS / PAYMENTS / STRATEGIES / ATTRITION / PREVIEW / SNAPSHOT / SAVE / ATOMIC / COST`；完整前提与预期在追踪登记，证据运行后才绑定。

新套件必须使用正式 CSV、生产经济和真实 NPC／文明，通过统一六阶段入口运行。已有回合 29 组与正式推演 32 组继续回归，不删除原反例；来源冻结后再生成报告。单独测量接入正式经济后的完整回合成本、活动和历史增长，不沿用旧单独推演耗时，也不凭空设定性能通过阈值。

本轮无游戏内 UI／美术变更；预览的规则正确性用纯数据断言验收。玩家对支出与风险的理解交给 `TASK-UI`，如后续无法清楚表达则回到经济预览合同及 UI spec 修正。没有新增短体验前置阶段。
