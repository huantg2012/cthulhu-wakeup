已确认范围：形成共享处境、按不同利益/知情生成诉求、组合有实际后果的回应、单骰曲解、四种不同代价结构、真实后续与低重复供给、同源生成查看器。全部十类背景最终均需可执行，不将剩余五类留成文字标签。既有50例保留对照，不能作为新入口的故事池。

### 阶段一：生成核心与可审阅查看器

- [x] G01 数据编译：按 §16.10.2 建立可执行组件表、受限谓词和效果写集，扩展 Catalog；录入参数及四个取舍剖面，再补其他介入类别。未接消费者的配方装载/生成明确拒绝。
- [x] G02 共享处境及生成：实现 Situation/Request 分离、只读候选、有界角色绑定、不同立场/目标、可用回应求解、正式登记和单独随机流。禁止循环 cases 表作为生产入口。
- [x] G03 表达与查看器：人工句段与真实事实绑定；同一核心支持种子、锁处境看多方诉求、下一批与作者展开。旧50例单独标记。输出一次有界容量报告，分文字/语义/决策统计；不能把世界名、人名和数值微调当新玩法。

查看器使用隔离的作者世界。锁定同一海港事故可见求生、开路和留证三种诉求。角色关系来自生成世界，选择结果及规则可在作者区展开。

### 阶段二：正式玩法与保存接入

- [x] G04 真实执行：把编译结果接进 `freeze/prepare/commit/deadlines`、Session/Turn；新难度读取原属性与世界阻力公式，单独计算费用和影响；成功理智损失与灾变分开；维护包含成功当轮首期；共享事故版本与幂等锁防多请求重复救人/交付。
- [x] G05 能力及后续：对“改变人物用途”补正向任务与限制消费者，玩家指令、自主行为、任职/失格、供奉与过期共用状态；真实救援/神迹/证言继续原接口，新后续与旧事件共享消费身份，深度有界。
- [x] G06 兼容与表现：旧 schema1 合同、责任和已抽结果原义续存，新 schema2 独立政策与随机状态。按当前 P02/G5、S0/F5/D4/D5/J2 复用正式界面，固定费用/执行、局部滚动、曲解隐藏；实际回执显示已发生变化，能力资格在原人物/任务入口体现，禁止新造多层资料菜单。

### 阶段三：覆盖与一次收口

- [x] G07 补齐十类背景的身份/关系/语气/原语及结果消费者；新增背景组件应能与已有至少两类处境、两种立场组合，不要求逐篇 case 特判。使用缺口清单处理未支持组合，不能默认套人类家庭生活到非人文明。
- [x] G08 按 §16.10.11 执行一次有上限的容量抽样及少量真实 Session 路径；记录实际覆盖、未达容量目标、旧档限定和待制作人审阅项。核心与直接边界通过即收尾，禁止随后扩成全组合长局、反复截图或反复抽样。
