# 初识人物、祈求去重与祭仪玩法整改计划

日期：2026-11-16。工作分支：`cthulhu-wakeup`。

**状态：B01–B04、O01–O08 已实施并完成逐项核验；待制作人体验复审。** 本文件保留问题、玩家收益与原验收目标，实际结果见 §6 和[核验报告](../qa/first-contact-ritual.md)。规则已回写原系统 spec。制作人原存档未改动。

## 1. 目标、依据与边界

整改整条“人物如何进入视野 → 由什么卡承载 → 能参与什么 → 执行后发生什么”的链路，使玩家知道这些人从何而来、为什么可以干预、此次行动值得付出什么，以及实际改变了什么。

**制作人明确要求：**首次出现的求告者当轮不重复投放人物手牌；调查新局人物来历和祭仪可用性；论证玩法价值；消除“当前来源／某某依据”等无法理解的选择；所有计划必须文档化，每个优化项写明玩家体验收益。

**当前实施范围：**下列人物承载、发现经过、祭仪介入、候选、准备、结果与兼容规则均已接正式 Session。O03 已定型为三种真实介入通路，并由首次开放、候选、执行共用；不是仅改名称。

现行依据：

- [游戏 UI 执行路由](../progress/stage-priorities.md#game-ui-routing)：当前视觉、交互依据与持续禁令。
- [世界玩法交互合同](../specs/ui-interaction.md#worldplay-card-study)：完整手牌、对象只读、行为配置、轮初回响、去重及现有可用性待办。
- [功能牌首次开放](../specs/system-powers-cults.md#functional-card-discovery)：首次结构条件与临时执行条件分开，首团前活动不要求先有教团。
- [事件与发展路线](../specs/system-events.md) §14.11：保留首团、孤立人物与祭仪路线，删除无决策收益的中间字段。
- [世界观](../world.md)与[核心愿景](../vision.md)：玩家是邪神；知晓人物、人物知晓邪神、信仰及可干预关系不能混同，干预具有具体依托。
- [现行美术规范](../art/visual-generation/ui-art-standard.md) A06–A08、A15、A17：锁定卡壳、分色字段、回响及真实骰点与结果演出。

范围包含正式新局、轮初回响、世界／教团手牌、人物档案、行为候选、准备／结果态与读档。保持现有卡壳、肩签、牌堆运动、邪神窥视背景和共享掷骰演出。不重做祈求生成器，不改为固定回应，不扩建仪式筹备／会面／证明收集子系统。禁用生图工具及项目已禁用的 `in-game-ux`、`visual-art-production` 和衍生流程。

## 2. 已确认的问题证据

调查对象为制作人截图对应的新局：阿兹沙鲁文明，CIV_03，第 1 轮；在原存档副本使用真实 Session 核查，未修改原档。

1. 两位实际求告者是米拉·里德、塞拉·科尔；回响里的罗安·佩里、诺拉·鲁克、艾达·马什是祈求情境的其他参与者。现有回响已按求告者 ID 去重，但泛化的身份／职业信息不足以让玩家辨明他们与事情的关系；正式人物手牌还需独立整改。
2. 玩家知情层读取祈求来源事实时，可将其中 actor／targets 加为已知人物；人物投影及回响未给出可理解的发现经过。需要审核这些身份哪些确实应当公开，不能把后台参与者一律等同玩家已知者。
3. 祭仪当前要求真实祭仪者，但不要求其为信徒或已有教团。样本祭司罗安·佩里合法；截图另一处却选中了信使米拉·里德，真实预览拒绝，暴露候选筛选与固定活动不一致。
4. 样本中的“初识世界”“聆听的联系依据”和两条“入梦的联系依据”，选作祭仪来源时费用、概率和进展没有区别。两条入梦记录对应不同人物，并非同一事实重复存储，但展示丢失对象信息，读起来完全一样。
5. 样本祭仪预览为 2 低语、4 信仰，D100 不高于 62 成功；副本实掷 65 失败，实际支付费用，祭仪者理智降低 2、当地察觉增加 4。这是该样本的核查结果，不是所有人物的固定概率。
6. 祭仪成功可从真实当地非信众池转化最多 3 名无名信众，并产生相关实际记录；前置成团有价值。但当前通用详情对 CIV_03 也显示“两次成功”，而对应祭仪依托路线并不普遍适用，可能制造虚假的成长目标。

实现定位：[玩家知情](../../src/game/player_knowledge.gd)、[回响模型](../../src/presentation/production/worldplay/round_arrival_model.gd)、[Session](../../src/presentation/session.gd)、[活动规则](../../src/game/progression_routes.gd)、[选择器](../../src/game/entry_selectors.gd)、[候选文案](../../src/presentation/experience_actions.gd)、[来源标题](../../src/presentation/player_record_text.gd)、[活动详情](../../src/presentation/action_catalog.gd)。这些链接用于实施定位；本轮调查不是整改后的验收证据。

## 3. 优化项

### O01 · 首次求告人物当轮只由祈求牌承载

**问题：**同一个初识人物以祈求牌和人物牌重复出现，增加首轮牌量；若只在回响去重，正式手牌仍然重复。

**玩家体验收益：**第一次见到一个人时，注意力集中在其求告与处境，少辨认一张重复牌；处理完祈求后不会被同一人的突然补牌打断，仍能查资料、施展权能和安排活动。

**计划规则与实施范围：**

- 以稳定人物 ID、首次公开认识的回合及祈求公开身份判断，不按姓名、立绘或 NPC 出生回合推断。本轮初识且作为求告者公开的人物，在回响、世界和教团手牌中由祈求牌优先承载。
- 当轮回应、拒绝或关闭祈求后，仍保持人物手牌抑制至该轮结束，不临时补发。不能仅根据“当前是否还有开放祈求”重新计算后使人物牌冒出。
- 下一轮起，已正式认识且符合现行展示条件的人物正常入手牌；延后入手牌不计为再次发现，不重播“新知人物”。尚仅有请求线索的身份不因此升级为完整人物认知。
- 早已认识的人本轮再次求告，保留原人物牌与新事情牌；同一人多项不同请求不合并请求，仅去重人物身份。
- 祈求查看区通过求告者姓名查阅人物资料，底部人物档案继续只读。合格人物仍进入权能／活动候选；隐藏手牌不得改变资格、真实身份或关系。
- 分类数量、手牌寻牌、空分类在去重后计算；人物档案仍按实际已知身份计算。搜索不绕过手牌去重补出隐藏牌。
- 同轮换世界、进出教团、回看回响和读档均保持此规则；回看已冻结回响不能重新标记人物为新发现。

**验收：**初识求告者当轮没有独立人物手牌；关闭祈求不补牌，仍可查阅和作为合法行动目标；下一轮正常入牌且不重复宣告发现；同轮保存恢复前后结果一致。老人物的新求告不误删其原人物牌，同名不同 ID 的人物不误合并。

### O02 · 新人物的发现经过与公开资格

**问题：**后台情境角色进入已知集合，却只显示“身份已进入你的视野”，玩家不理解人物为何出现；还存在把后台身份提前公开的风险。

**玩家体验收益：**能把人物与自己看到的求告、经历和行动联系起来，知道为什么值得关注；世界中的人像有来历的角色，而不是随机塞进手牌的资源。不提前透露尚未得知的人物与关系。

**计划规则与实施范围：**

- 审核人物被公开的实际原因。仅作为情境后台 helper／observer／target，不自动证明玩家已知其姓名、身份和关系。
- 对应求告、公开行动结果、初始联系或其他真实公开事实足以揭示身份时，记录首次发现回合、可追溯的原事件／请求／结果和允许显示的关系说明。
- 人物卡保留姓名、身份和简短已知关系；查看区与轮初回响共用一句具体发现经过。示意句“你在回应某次求告时认识了他”仅在真实发生该事件时使用，不倒填未执行的回应。
- 已公开关系可进一步说清；隐藏“观察者”等后台角色不可直接作为叙事事实输出。未知来历不通过编造“由某人引见”补齐。
- 祈求中实际求告者、人物资料与行动候选使用同一姓名、身份和立绘；区分求告者与其他相关人物，不靠相似职业让玩家猜。
- 审核范围也包括开局关系、聆听、入梦、事件和回应结果，避免另一路仍无依据地授予知情。

**验收：**每张新增人物牌可追溯到真实且允许公开的发现原因；后台未公开的参与者不被发牌；同一人的各入口身份一致，玩家无需查编年史或理解内部事实结构就能读懂其出现原因。

### O03 · 定型祭仪的介入逻辑与首团前价值

**问题：**当前可以认识祭司后直接使用其活动，却未解释邪神如何影响尚非信徒、甚至不知晓邪神的人。直接加“已有教团”又会堵塞首团路线。

**玩家体验收益：**能够理解“为什么我现在能做这件事、要影响谁、对首团发展有什么用”；体验是邪神利用具体媒介干预凡人，不是无来由地指挥陌生人，也不会为解锁首团先被要求拥有教团。

**实施定型（2026-11-16）：**

正式名称为「浸染祭仪」。沿用真实祭仪者、费用、判定、至多三名普通信众转化及实践消费者；以 `data/ritual_interventions.csv` 定义三条介入通路：①本人仍开放的求告（关闭失效）；②对本人成功／深刻成功的入梦结果（记录失效则失效）；③仍忠诚的正式信徒身份（退团／忠诚不足失效）。全都绑定同一人物和当地世界，不接受他人的梦境、初识世界或仅有入梦资格证明。该规则由首次开放、候选与正式执行共用。


- 保留祭仪在首团前发展信众的用途，以及适用文明中的实际祭仪实践用途。
- 将行动定义为通过能够触及的祭仪者或祭仪，把自己的影响引入当地仪式。最低条件包含真实祭仪能力和实际成立的相关介入途径，不以“认识职业”代替可干预关系。
- 优先复用已有关系、相关求告、梦境或实际结果提供的通路。必须逐条确认其足以支持本次介入；无关的初识世界、聆听证明或他人的梦境不能充当通用许可。
- 不把信徒身份设为所有祭仪的强制前提，也不强制“先入梦一次”。非信徒可以被介入，但应有具体、可理解的机制承接。
- 若现有事实无法支持一种拟用通路，先明确该机会由哪一个已有行动／结果产生，以及公开给玩家的条件，再更新规则；不得凭空补出正在举行的祭仪。
- 名称和说明体现邪神介入的身份；最终用词在该机制定型后确定，不仅替换“主持”两字而保留错误因果。

**定型产物：**列清每种合法介入途径的现有事实生产者、公开范围、资格条件、失效条件及玩家获取路径；说明无教团新局如何从可用祈求／基础权能走到祭仪。策划条件由 CSV 驱动，更新原系统 spec；不另建仪式筹备、逐人会面或证明收集系统。

**验收：**至少一条无教团可达的真实路径和一个“只认识祭司、尚不可介入”的反例；只有相关合法途径才能施行，陌生／无关记录不能绕过；不靠测试注入一个标志冒充自然可达。此项未定型前不得宣称活动机制已修复。

### O04 · 首次开放、人物候选与正式执行使用一致条件

**问题：**牌已开放却默认选到不合格职业，最终才得到“活动失效”；已解锁、当前可执行和草稿未选完整混为一谈。

**玩家体验收益：**拿到的功能牌有真实用途，选人时知道谁能做、谁暂时不能做及原因；不必反复试错寻找程序认可的组合，也不会因为花完资源就丢失已认识的功能牌。

**计划规则与实施范围：**

- 首次开放检查至少一个满足最低结构前提的真实组合；祭仪按 O03 定型后的条件，不只检查当地职业存在。
- 已开放记录持续保留；资源、本轮行动机会和冷却影响当次执行，不作为重新隐藏手牌的理由。历史开放不豁免执行校验。
- 打出固定活动后，先固定动词，再筛选对应候选。祭仪不混入非祭仪者；一位合格者自动填入，多位时由玩家选择。
- 有结构资格但本轮已行动或受限的人可说明具体不可选原因；未知人物不能通过候选列表泄露。没有候选时给明确缺项，不展示含混“活动失效”。
- 换人、材料或回合后重查；不得静默改成另一种活动，提交仍由正式规则复核，不以 UI 放行代替真实准入。
- 逐项审计 16 项独立活动：私祷、共同工作、秘密集会、祭仪、记录／历法实践、教习、共同见闻、记忆／异议实践、保管约定、互惠交付、网络交换、三类异常活动。确认 12 权能未被人物去重及知情调整误伤，保持现行开放合同。
- 对接既有 `ISSUE-WORLDPLAY-ACTION-AVAILABILITY`：不能以“待选对象”或查询超时作为可用／缺条件结论。该待办涉及的全目录覆盖若未完成，保留剩余范围，不以祭仪一个样本关闭整个待办。

**验收：**祭仪者与信使正反例；唯一候选自动填入；多个候选可比；临时受限与结构不符分别表达；缺钱不锁回旧牌；UI 预览与真实提交在同一状态下结论一致。审计清单逐项记录已验和剩余项。

### O05 · 移除无意义的来源选牌，保留真正有区别的材料选择

**问题：**玩家被要求选择没有费用／概率／结果差异的内部因果记录；不同记录又都叫“某某联系依据”。

**玩家体验收益：**少做无意义点击，不再猜哪张“依据”更好；保留下来的选择都有可理解的对象或取舍。程序记录真实因果，而不是让玩家替程序填账。

**计划规则与实施范围：**

- 逐类区分内部执行依据与实际玩法材料。仅记录“为何允许执行”的事实由系统自动关联；仍保存真实来源并在提交前验证。
- 删除祭仪当前无区别的来源卡组及选择槽。若没有合法介入途径，显示真实缺项，不能用任意世界记录绕过 O03。
- 会消耗、限定对象、改变结果或影响后续的记录／物件继续可选，并说明差异；不能以精简为由删除记忆、契约、锚定等实际材料玩法。
- 对确需选择的梦境、见闻、记录，显示具体对象、经历及当前用途，必要时再补回合。既不并列两个无法区分的“入梦依据”，也不把同根的派生事实包装成多份资源。
- 候选的语义文案不能再被通用 FACT 标题覆盖；通用“来源／依据”只保留内部字段用途，不直接作为玩家必须理解的名词。
- 来源失效时明确反馈并重新准备，不静默换人、换实际材料、换行动或重复扣费。预览和自动关联不消费随机数、不产生实践或奖励。

**验收：**样本四张无区别来源不再出现；相同有效配置的成本和结果语义不因去掉选择器而改变；有不同真实材料的行动仍保留差异；失效来源不能执行、不能扣费；同根事实不重复计量。

### O06 · 祭仪准备态只呈现本次决定所需信息

**问题：**活动、来源、费用等字段重复；收益、必然影响和条件性风险不清，非适用文明也出现两次成功进度。

**玩家体验收益：**玩家能在同一个执行区回答“谁来做、能得到什么、花多少、冒什么险、成功条件是什么”，减少阅读负担，避免为不存在的后续目标反复投入。

**计划规则与实施范围：**

- 按“施行者 → 实际目的与预期收益 → 消耗与风险 → 检定并执行”组织信息；打出的牌已经确定活动，不再选择一次活动。
- 保留必要对象选择；删除来源卡组、重复费用和空泛状态。“必付”不恢复，具体资源费用仅列一次。
- 说明成功从当地真实非信众池转化信众，当前规则最多 3 人；不得表述成凭空产生 3 张具名人物牌。人数及可公开信息从真实规则读取，不硬编码样本收益。
- 区分即使失败也发生的施行影响与成功／失败／灾变后果。使用实际预览阈值与 D100 小点成功规则；62 只是调查样本，不是卡牌常量。
- 多人候选比较真实能力、状态和已知关系；不为装饰增加没有机制依据的评价。
- 两次成功／跨轮实践只在当前文明确有消费者和成长用途时展示，并说明将推进什么。不适用的 CIV_03 不展示虚假的祭仪锚定目标。
- 沿锁定卡壳、分色字段和原内容滚动区域，正文可读；不扩为后台式参数表，不遮挡手牌、顶部及底栏。标准／大字均检查。

**验收：**施行者、费用、收益与风险各有唯一明确位置；唯一对象无需额外点击；当前概率正确；不适用文明无假进度，适用文明能读懂实际进展用途；标准／大字与长名称没有遮挡或截断关键条件。

### O07 · 用真实结果说明世界与人物发生的改变

**问题：**只给成功／失败不足以支撑投入判断；实践、首团和锚定可能被笼统表述成已获得。

**玩家体验收益：**投骰落定后能立即理解自己赢得什么、损失什么、下一步为何发生变化；失败也有可解释的代价，成功有可感知的成长，不必跨多个页面寻找效果。

**计划规则与实施范围：**

- 复用现有掷骰演出，展示真实点数、条件和真实结果，不另掷一次演出骰。
- 从本次实际回执读取转化信众数、允许公开的污染／察觉变化、施行者理智等变化及产生的实际记录／实践。无变化的字段不堆成结果清单，费用不重复。
- 失败说明未获得的核心收益及已经发生的费用、影响；不能只写“未成功”。遵守当前情报精度，不借结果页泄露隐藏的实时四维或人物属性。
- 实践确有下游用途时指出当前进度；首团仍按真实领袖、信众、投入等条件成立，祭仪成功不冒充已建教团或已建锚点。
- 提交后牌堆、人物状态、候选、解锁和相关实际进度同源刷新；新牌演出沿同一首次开放规则，不重复播报。

**验收：**成功、失败代表回执与实际状态一致；实际骰点正确；收益不足或无剩余非信众时不夸大奖励；不泄露未知数据；相关 UI 更新且不产生双重奖励。控制骰点的分支测试明确标为夹具，不能当自然发生的证据。

### O08 · 统一身份、展示与行动规则，补齐保存和跨入口一致性

**问题：**目前回响去重、手牌投放、人物资格和读档基线各自处理，局部修补可能导致换页又出现重复牌、人物无法选中或读档重播。

**玩家体验收益：**同一个人、同一张牌在不同场景里有一致身份和状态；退出再进入不会改变体验，不会丢掉可用目标，也不会因新人物出现而再次等待立绘生成。

**计划规则与实施范围：**

- 分离三项职责：公开认知决定何时因何认识人物；展示规则决定当轮由哪类卡承载；正式行动规则决定人物是否合格。不要通过删真实人物或删行动候选实现手牌去重。
- 本轮初识／祈求承载及首次开放状态须可保存恢复，不仅依赖 UI 实例中的 seen 集合。按真实公开时间定义，不以生成时间、当前视图是否画过代替。
- 旧档只恢复可证实的既有认知和记录；不能把全部存量人物当本轮新知，也不能补造未发生的发现故事。历史已公开身份不因修复而静默抹除，已结结果不重算、不补发奖励。
- 对缺少历史发现信息的旧档，明确采用可验证基线并记录兼容边界；本轮祈求承载可确定时仍去重，不能猜出不存在的历史时间。
- 覆盖轮初回响／回看、世界与教团手牌、祈求人物关联资料、人物档案、行为候选和结果刷新。底部档案保持只读，返回保留原草稿与焦点。
- 新增可见身份继续走展示前立绘准备；复用稳定外观 ID 与缓存，不把隐藏人物手牌当作省略生成的优化，不把贴图变化当人物新增。

**验收：**同轮保存恢复、跨轮、换世界／教团、回看回响后，身份、计数、去重和资格一致；已有玩家资料和实际结果不丢失；隐藏手牌人物仍可合法选中；真正要展示的牌立绘已就绪，查看不产生额外玩法写入。

## 4. 实施批次与交付要求

每批在本文件更新状态、已验范围、实际证据及剩余项，不新建并行版本计划。B01–B04 均已实施；自动核验不代替制作人体验裁决。

1. **B01 · 人物公开与当轮去重（O01、O02及必要的O08）。** 先明确公开身份和首次认识，再接回响／手牌／档案／候选，完成同轮与跨轮保存检查。玩家先获得更精简、来历明确的新局牌组。
2. **B02 · 祭仪机制与活动资格（O03、O04）。** 定型具体介入通路及原规则消费者，审计16活动资格，修候选与固定动词的关系。机制定型不阻塞独立的人物去重工作；未完成定型不伪称已经修好。
3. **B03 · 来源选择与准备表达（O05、O06）。** 在真实资格明确后自动关联内部来源，保留实际材料取舍，完善准备态和适用文明进度。玩家只需作有意义的选择。
4. **B04 · 结果、兼容和正式闭环（O07、O08收尾）。** 接实际回执与刷新，核对正式入口和有限兼容案例，交付制作人可体验的完整链路。

正式运行入口为仓库根目录 `正式UI体验.command`。在隔离新局／存档副本验证，不覆盖制作人的原档。测试随实际改动聚焦新增规则、失败边界和代表交互，不扩大长期模拟、全量平衡或无关视觉重做。

玩法改动同步原[事件系统](../specs/system-events.md)、[权能与教团系统](../specs/system-powers-cults.md)及相关进展 spec；交互规则同步原[交互合同](../specs/ui-interaction.md)，结构职责变化再登记[架构](../architecture.md)。此计划保存问题、收益、批次和验收，不成为第二份正式规则正文。计划文档完成不等于游戏整改完成，自动检查不等于制作人体验认可。

## 6. 实施结果与玩家收益

1. **O01 已完成。** 首识求告者当轮只出祈求牌，关闭仍不补人物牌；次轮恢复手牌，不重复新知演出。玩家少辨认重复牌，也不会失去人物资料或行动目标。新局、真实跨轮、同轮保存恢复、同名／多求告边界、寻牌与只读图鉴分别核验。
2. **O02 已完成。** 新情境只直接公开真实求告者，后台角色不再跟随泄露；资料和回响显示真实公开来历。原截图种子由 5 张已知人物投影收敛为实际 2 位求告者，初轮人物手牌为 0。旧档已经公开的 5 人保留。玩家能理解人物从何而来。
3. **O03 已完成。** 正式活动改为「浸染祭仪」，三种真实联系共用准入。无教团新局实际可执行；仅认识职业、初识世界、他人的入梦、关闭的求告、失效记录不能替代联系。玩家不再无由指挥陌生祭司，也不被“先有教团”堵死首团路线。
4. **O04 已完成本批资格审计。** 固定动词先于人物筛选，祭仪不再选到信使；唯一人选自动填，暂时已行动明示。核对 16 项独立活动与 12 权能，另修网络交换被额外加忠诚门槛的问题。玩家少试错；花完资源不丢已开放牌。全目录组合可用性求解待办仍 open，不用本批替代其验收。
5. **O05 已完成。** 牌桌及保留工作台均隐藏自动因果槽，取消四张无区别的「依据」选牌；实际材料、第二份记录、对象及阶段继续保留。来源失效提交被拒且不扣费，已选择的合法材料不被程序换掉。玩家只选择有玩法差异的对象。
6. **O06 已完成。** 准备页聚焦祭仪者、联系、至多表定人数归信、适用实践、施行影响与一次费用；D100 使用实际小点成功上限。CIV_02 显示跨轮实践，CIV_03 不虚构两次锚定目标。标准与大字版实机核验，保留锁定美术。
7. **O07 已完成。** 实际回执接入共享骰子结果：成功示例 45 ≤ 60，普通信众 +3、污染 +2、察觉 +4、祭仪者理智 −2，实践 1/2；失败示例 85 > 62，不转化信众，察觉 +4、理智 −2。两次均实付 2 低语／4 信仰。玩家看到自己的投入与改变，不把成功等同自动建团／锚定。
8. **O08 已完成。** 公开认知、承载展示、正式资格分离；新增展示历史随 Session 保存。真实旧档、缺字段兼容、跨轮与返回核验；原事实和资源不重算。祈求关联资料、图鉴、手牌与行动候选保持同一身份；立绘仍按完整可见集合预热。

**核验记录：**规则闭环 114 项、边界 23 项、既有功能牌开放回归 69 项通过；正式场景标准／大字／失败路线分别记录于[逐项报告](../qa/first-contact-ritual.md)。A01–A12 的证据类型在报告区分真实 Session、原生输入、只读投影夹具和代码审计；不把夹具称为自然长局。
