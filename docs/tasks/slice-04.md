# Slice 04 · 分层推演与注意力基础改造

状态：前六项基础任务已交付；TASK-FIDELITY-VERIFY 的跨模式集成与正式负载执行见[报告](../qa/fidelity.md)、[独立审查](../qa/fidelity-review.md)及[执行协议](../../tools/fidelity/README.md)。本任务组的最终状态、实际证据和下游准入由[traceability.json](../implementation/traceability.json)唯一登记。基础验收不代表完整教团、祈求、权能或事件业务已完成。

本任务组接在 `TASK-ECONOMY` 之后，完成后接回 `TASK-CULTS`，其后的权能、祈求、锚点、事件、抵抗及终局沿既有依赖继承这项基础前置。整个任务组属于正式开发，没有短体验、灰盒或等价的前置阶段。

## 依据与可观察目标

依据 [分层推演技术方案](../implementation/simulation-fidelity-plan.md)、[作者决策](../progress/decisions-log.md)、现有五个系统 spec、[技术架构](../architecture.md)与正式 CSV。核心体验仍是从神的一侧回应祈求，并看到其对具体人物与文明的持续影响。

目标：真实推演范围受明确的注意力与活动容量约束；后台文明从宏观状态生成概略变化，既成身份、经济、暴露、风险与承诺继续成立。普通行动不再反复复制或扫描全部累计历史。界面观察、模式切换、重复请求和保存继续均不能制造资源、重抽身份或刷新期限。

先在全详细模式下验证保持既有规则性质的底层改造，再验证概略推演的新规则。概略模式不要求重现旧全详细模式中每个未被观察的细节；它必须保持共同结算不变量、事实连续和自身确定重放。

## 任务顺序与责任

依赖链：`TASK-ECONOMY → TASK-FIDELITY-RULES → TASK-INCREMENTAL-TX → TASK-HISTORY-INDEX → TASK-ARCHIVE-SAVE → TASK-ABSTRACT-SIM → TASK-ATTENTION → TASK-FIDELITY-VERIFY → TASK-CULTS`。

每项按一次 AI 会话可独立核验的子批次执行。需要进一步拆分时，先更新追踪中的任务、依赖和验收再派发，不在实施中扩成没有边界的“大优化”。数值与系统组合沿这条方案单线迭代，不开并行经济候选。

### TASK-FIDELITY-RULES · 正式规则、预算与接口对齐

交付证据：[规则审查](../qa/fidelity-rules-review.md)及 [静态检查](../qa/fidelity-rules-results.json)。三张新增正式表已落地；生产运行时保持全详细参考基线。

- **前置／责任**：`TASK-ECONOMY`；design 负责规则和 CSV，code 负责架构与技术接口，director 整合追踪。
- **范围**：原地明确重点／后台资格、主动干预分类、三个活动预算及持久身份容量、预留和释放时点、成员转换、背景风险推进、候选固化、唯一责任表与冷热查询边界。定义每项参数的归属和可检验约束，数值初值只写正式 CSV；管理页展开限制不偷换成注意力名额。
- **交付／影响**：`docs/specs/system-civilizations.md`、`system-powers-cults.md`、`system-events.md`、`system-turn-economy.md`、`system-progression.md`，以及 `docs/architecture.md`、`data/civilization_parameters.csv`、`fidelity_parameters.csv`、`intervention_policies.csv`、`simulation_responsibilities.csv` 及事件失效约束；同步对应 REQ、SET、ACC 和下游影响。
- **验收**：每一类对象和本轮职责有唯一归属；所有主动干预入口使用同一容量判定；忠诚达标与正式入团分开；无容量时的拒绝／延后发生在扣费或承诺之前；未结事项没有因撤关注而消失的规则路径。新参数没有第二份来源，旧规则冲突逐条有原地替换或明确的迁移安排。
- **风险／非范围**：注意力规模与后台频率仍需后续平衡及负载验证；本项不以参数表存在证明性能或乐趣，不实现游戏功能，也不提前完成完整入团、祈求或事件系统。

### TASK-INCREMENTAL-TX · 受限读取与增量事务

- **前置／责任**：`TASK-FIDELITY-RULES`；code 实施，qa 独立检查失败与跨系统冲突。
- **范围**：先保持全详细模式及既有随机语义，拆分只读视图、候选生成与共同提交。事务暂存本笔对象、事实、索引、ID、随机和回合上下文；以集合级首次写入及保守依赖闭包实现，计划/游标操作不深复制全部 NPC，自动演化可覆盖全部当前实体。工作区内仲裁、合并、刷新派生状态后，校验最终候选及受影响依赖，再一次发布。
- **交付／影响**：`src/game/turn.gd`、`src/game/economy.gd`、`src/simulation/world.gd` 及架构指定的纯数据辅助模块、`tools/incremental-tx/` 与专项报告；更新正式推演、回合、经济回归及本任务专用反例。
- **验收**：同种子、同内容、同命令在表示差异规范化后，状态、费用、事实、随机位置和回执与改造前一致；单项合法但合并后破坏守恒／唯一归属的批次被拒绝。失败不留下半笔写入、不撤销先前成功行动；参与者不能修改权威嵌套数据，预览不消费随机或改变状态。
- **风险／非范围**：增量校验漏掉反向依赖会破坏身份、人口、锚点和收入联动，必须先登记验证覆盖。全量语义校验继续用于读档与审计；本项不改变背景规则、不直接删除安全检查，不保证归档前历史开销已经消失。

### TASK-HISTORY-INDEX · 有效决策投影与历史索引

- **前置／责任**：`TASK-INCREMENTAL-TX`；code 实施，design 复核旧来源的有效性和失效条件，qa 验证。
- **范围**：将当前有效状态与完整历史分离；为人物行为、机构风险、按域活动对象、到期工作、已消费来源与回执建立增量投影／索引，并把默认参与者当前投影接到有效对象与按需来源查询，避免已死身份/旧来源在默认读取中无界累积。按 ID 或有限查询读取旧事实，不按轮重新筛遍全部 `known_facts`、证据或回执。
- **交付／影响**：`src/simulation/world.gd`、`src/game/turn.gd`、`history_index.gd` 与架构指定的读视图/事务接口；内存历史使用不可变持久树，导出保持原 schema 1 语义。`tools/history-index/` 验证差分、无关历史增长、有效旧来源、分页和回滚；同步旧套件的历史读取适配，保留原断言。
- **验收**：同一有效状态追加大量无关旧历史后，普通行为不新增全历史扫描或复制；仍有效的旧证据、成长消费凭据与多来源因果均可准确查询，过期投影及时撤销；失败事务同时恢复索引。全详细模式差分重放继续一致。
- **风险／非范围**：不能靠“只保留最近若干条”伪造有界性；规则若允许无限有效来源，必须定义可证明足够的投影或有限检索。完整历史仍保留，本项不以删除回忆换性能；持久树路径查找有对数成本，既有 native 根浅复制/身份检查仍交 ARCHIVE-SAVE，不负责最终分段保存格式。

### TASK-ARCHIVE-SAVE · 分段档案与完整提交恢复

- **前置／责任**：`TASK-HISTORY-INDEX`；code 实施，qa 构造中断与损坏场景。
- **范围**：以已实现的持久内存历史树为基础，把冷事实、知识来源、旧回执、阶段日志及完成工作移出热状态根；消除 native 根浅复制/身份检查的历史增长路径，实现当前检查点、不可变档案段与后续提交记录。世界、索引、随机、阶段和回执关联同一提交序号，以最后发布的清单决定恢复版本。
- **交付／影响**：`src/simulation/archive_store.gd` 管持久根读写、覆盖层及schema2分段协议；world/history_index/transaction/state_view、turn/economy接入同一根接口。`save_archive/load_archive` 与原schema1诊断导出并存；`tools/archive-save/` 与专项报告覆盖恢复、差分、成本和故障。
- **验收**：未提交尾部可忽略，已提交内容损坏必须拒绝；不能静默丢失成功提交。恢复语义校验通过后才替换会话；旧请求仍返回原回执或拒绝异内容；续存不重复支付、演化或收入。普通保存只处理变化及新档案段，完整导出与读档审计成本单列。
- **风险／非范围**：新格式需明确版本；没有迁移器的旧版本拒绝，不能重抽身份凑兼容。历史磁盘占用仍会增长，本项不承诺无限战役或跨引擎版本随机兼容。单写者协议不提供跨进程锁；物理断电、发行文件系统原子替换与真实版本迁移由TASK-RELEASE/ACC-RELEASE验证。

### TASK-ABSTRACT-SIM · 概略生产者与背景候选协议

- **前置／责任**：`TASK-ARCHIVE-SAVE`；code 实施，design 负责正式背景规则／模板的一致性，qa 验证。
- **范围**：接入读取宏观摘要的概略生产者，与详细生产者、正式经济共用阶段四版本和唯一提交入口。保留后台既有暴露、证据、风险及到期事项；生成有合法来源的当前变化与结构化候选。候选固化协议确定人物、来源、ID、期限及一次性键，支持正式规则的容量预留接口。
- **交付／影响**：`src/simulation/abstract_sim.gd` 与 world 的共同批次接入、turn 的阶段二固定读取/阶段五期限钩子、`data/background_templates.csv`、`tools/abstract-sim/` 专项报告。通过开局受控分配验证正式协议，完整玩家注意力入口与匿名混合开局由TASK-ATTENTION接续。
- **验收**：后台不能撤销查证、拖延预告后果或重复人口与收入；背景结果可重放且不伪造旧亲属、证言或神迹；同批详细人物与概略文明竞争时遵守身份优先和唯一归属。候选固化后再次读取、续存不重新抽取；没有合法候选允许静默。bootstrap 同样预留/扣人口；阶段四生成及固化、阶段二选取分开。旧目标失效不自动重定向，只能使用固化时真实的备选主体。
- **风险／非范围**：本项只交付概略变化及候选生成／固化协议，**完整祈求呈现、回应选项与游戏入口归 `TASK-PRAYERS`，完整事件池和处理归 `TASK-EVENTS`**。此时用明确场景数据和候选消费者验证接口，不把验证参与者当成这些下游系统已完成。

### TASK-ATTENTION · 注意力准入、名额转换与模式切换

- **前置／责任**：`TASK-ABSTRACT-SIM`；code 实施，design 核对时点及所有主动干预分类，qa 检查绕过路径。
- **范围**：接替ABSTRACT-SIM的开局受控分配接口，接入实际玩家准入、匿名混合开局与本地按需展开；将既有候选holds/游标/固定名单对接统一attention模块，保留旧身份与已承诺事项。落实重点文明、具名教团成员和临时主体的容量／预留；阶段二、三合法入口按规则检查，阶段四锁定责任，撤关注按下轮轮初时点生效。成员个体可在后台文明保持详细推演，不递归展开其关系链；临时主体成为成员时原子转换预算。
- **交付／影响**：`src/game/attention.gd`、turn/world/economy/abstract_sim及StateView接入，hybrid/schema2与attention/schema1、实际generate_hybrid入口和tools/attention专项报告；正式容量仍只来自既有CSV。教团/权能/祈求/事件后续实际入口必须复用同一准入与成员效果，不能用本夹具替代业务验收。
- **验收**：重点用满时新主动行动在扣费前拒绝，包括背景祈求的一次性深度污染；本轮不能轮流释放名额关注全世界。升降级不复制人口、不刷新机会／期限／冷却，不重设随机。成员名额满时不能通过随机结果或忠诚增长突破，已承诺预留不会被偷占；后台成员仍真实行动，关系引用不自动激活整个文明。N/P 双满且同人被多份互动引用时，默认离团立即失去成员权限，原 N 转退役保护，既不卡死也不丢未结义务；后续轮初转 P 或释放保持守恒。
- **风险／非范围**：**完整建团、正式任命与继任归 `TASK-CULTS`**，本项验证既有成员与合法身份转换接口。受伤、拘禁、失联不能作为隐藏释放名额的路径；真实承诺未被安全表示前不能回收其必要状态。本项不做游戏内 UI 或玩家理解终审。

### TASK-FIDELITY-VERIFY · 跨模式集成、故障恢复与负载验证

- **前置／责任**：`TASK-ATTENTION`；qa 负责独立反例与证据，code 修复问题，director 核对要求覆盖及下游准入。
- **范围**：通过统一回合运行详细／概略混合、经济、死亡迁移、风险、容量和存取档交互；分别改变活动规模与历史长度，测量实际读写、候选数、复制字节、历史触达、时间和保存成本。验证期间持续有行为、风险、收入与成长，禁止空跑制造乐观结论。
- **交付／影响**：带稳定检查编号及实际来源 SHA-256 的集成／负载报告、独立审查、追踪证据与工作台状态；修复后回归受影响的既有推演、回合、经济性质。
- **验收**：前述各任务的反例有实际通过证据；固定当前有效状态、增加无关累计历史时，普通操作没有新增全档案遍历／复制；活动预算满载仍完整结算已承诺后果。故障后世界、索引、档案、随机、阶段和回执一致恢复。报告披露测试规模、环境、尚未接入的下游系统及性能边界，不以一次平均耗时证明所有规模达标。
- **风险／非范围**：当前 32 项 SIM、29 项 TURN、27 项 ECON 是全详细参考配置的 88 项证据，不证明本任务组已通过。不能删反例、减弱断言或刷新旧哈希代替重跑；全游戏平衡、叙事趣味、美术、发行性能仍由对应下游任务验证。

## 下游交接与范围隔离

`TASK-CULTS` 新增 `TASK-FIDELITY-VERIFY` 前置，原 `TASK-IDENTITY` 与 `TASK-ECONOMY` 前置保留。完整业务系统通过该链读取新的权威状态、提交及准入接口；不能继续直接扫描历史字典或自行维护第二套名额。

本任务组的集成验证不依赖 `TASK-CULTS / TASK-POWERS / TASK-PRAYERS / TASK-EVENTS` 完成，避免循环依赖。对这些系统的场景使用明确的已有对象与受控调用者，只证明基础协议；正式玩家入口与业务行为必须在下游自己的验收中再实际接通。

注意力与后台变化的**玩家理解**交给 `TASK-UI`，失效时回修本任务组的准入／预览合同及同一 UI spec；**经营取舍、注意力名额与背景密度平衡**交给 `TASK-BALANCE`，失效时回修归属 CSV 与规则；**背景故事的连续性和重复感**交给 `TASK-CONTENT`，失效时回修候选模板及来源投影。这些未知不阻止已授权基础实现，也不被机器正确性代勾通过。

## 计划维护要求

任何新增或修改方案都必须在同一轮更新开发计划：对应要求、结算、任务范围、前置依赖、验收、当前顺序及工作台。既有任务足以承接时原地更新其范围与验收；确需新增责任时再增任务，不能只保存方案或写“后续再编入”。计划登记不自动把实现状态改为完成。具体约定与检查入口以 [实施保障](../implementation/README.md)为准。
