## 2. 当前1080p输出与两档锁定规格

制作人更正：**当前B01–B08只实施、检查1920×1080**。另两档规格保留但锁定，须制作人另行解锁，不因进入B08自动实施：

- **1920×1080（FHD）**：当前唯一内容输出目标，用于制作、体验及美术检查。
- **2560×1440（QHD）**：锁定留用，本轮不实现、不配置入口、不测试。
- **3840×2160（4K）**：锁定留用，本轮不实现、不配置入口、不测试。

依据：2026-11-04 查询 [Steam 2026年10月硬件调查](https://store.steampowered.com/hwsurvey/)，三者主显示器占比分别 50.23%、21.82%、5.05%。调查是自愿样本，不是本游戏用户预测。选择前两档覆盖主要桌面分辨率，第三档覆盖高清桌面；不称这是所有宽高比中排名前三。

**共用一套逻辑布局，保留工程 1280×720 的固定逻辑画布**；当前1080p对应1.5倍输出。用当前 `canvas_items` 路径在目标输出分辨率绘制原生文字与控件，不将完整 UI 先烘成 720p 图片再放大。样板 1672×941 的坐标需转成正式布局，不能逐节点统一缩小后跳过字级与留白审查。Godot 的逻辑设计尺寸与窗口输出尺寸区别参见 [Multiple resolutions](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)。

后续解锁其他规格仍复用同一布局，不预建三套页面、断点或不同条目数量。保留标准／放大文字档。非16:9保持比例留边、不裁 UI；不制作超宽专属布局。窗口化按可用桌面限制尺寸（含标题栏），必要时回到既有720p窗口；屏幕不足时不可让窗口伸出屏幕。全屏沿实际显示器输出，不擅改系统显示模式。HiDPI下区分内容像素和实际窗口尺寸；不扩展高清规格验证。

B01只接1080p输出，不做分辨率切换器；B08设置只提供本批需要的窗口／全屏与文字档，不放1440p／4K可选项。本轮仅改规划，不修改 `project.godot`；工程逻辑画布保持不变。原有720p小桌面窗口限幅只沿用兼容行为，不新增一套制作／验收档。

## 3. 接入边界与共用基础

- 已有 `src/presentation/session.gd` 的 `project / action_catalog / preview_action / execute_action / progress / save_game / continue_game` 负责事实、预览与提交。优先复用 `experience_views/actions/semantics/feedback` 的查询、语义和结果逻辑，替换旧布局与不符合F2的导航行为。
- 按需将 `ui_components / ui_composites / motion / round_action_button / dock_content` 等共用实现迁入 `src/presentation` 的共享目录；样板与正式页同源。只迁本批所需，不先搭完整“UI框架”。正式出口不能长期依赖工具夹具脚本；已有可用素材可先原路径引用，B08核导出依赖。
- 表现层保存当前任务、主体ID、栏目、一个关联阅读位置、明确来处与选择记忆；控件只发意图。查询不得修改实际行动目标，提交只经Session。状态一变就重预览，失效目标给原因，不自动替换。
- **暂行选择记忆策略（实施默认，可依体验调整）**：同一运行、同一回合内按功能＋对象ID恢复有效选择；执行成功、对象失效时清对应项，换回合／换局／读档清行动记忆。不写游戏存档；取消确认、暂看人物、关闭面板不清选择。列表阅读位置与行动选择分开。不得将该默认表述为制作人已单独确认的跨回合设计。
- **左侧世界清单实施默认**：读取真实已关注世界，加当前有效祈求涉及的有限世界线索，稳定去重；不会因此取得关注资格或完整情报。其余已知世界从档案进入。准入不新增数值门槛；来源应在列表状态中可辨。B03实机审阅后再修订显示策略。
- **新祈求实施默认**：使用正式冻结／首次呈现回合等现有字段判定新增，不能把全部offered都当新增。B02先核真实字段，缺少可知字段时仅补最小公开投影；不改供给与存档schema。不重复在每次刷新时播放拍脸层；读档允许重播一次当前回合介绍，查看不会结算，后续若需跨运行记忆再单独定案。
- 立绘占位沿V/A规范：固定对象或情境的可替换槽、稳定ID、裁切焦点、安全区、柔边融合；使用已存在的中性材质或明确临时图，标“场景示意”，不假称专属人物。占位也要保持构图和可读性，不能留下刺眼空白框。图标、控件皮肤和文字不属于延期范围。
- 建议统一新增 `正式UI体验.command`（B01创建，后续沿用）。接入期间默认正式入口暂保留；B08替换默认入口。各批必须在同一新入口体验，不能只交付控件展示台。未接入功能有明确迁移范围说明，不能冒充玩法锁定；本批闭环内不得用旧界面或范围说明按钮代替实现。
- 不改正式玩法、CSV数值、随机、游戏存档格式。遇到确实阻断本批的底层bug，先定位；可做最小修复并只补相关验证，超出UI接线边界则报告，禁止用假数据掩盖。

**前置**：现有Session可以启动；样板基线已通过。**映射**：P01/P03最小只读/P14/P15/P18最小菜单，G1/G5，C01–C04/C06/C15/C16/C20。

**实施**：
1. 新建生产表现根并挂既定OverlayRoot；迁入最少共用控件，接1080p输出和输入／焦点／动效公共处理。保留样板可运行。

**边界**：不做祈求回应页；本批允许明确跳过回应推进回合。祈求存在时给真实数量及未回应提醒，未接入入口在体验版本说明中明示，不能伪装“未解锁”。不先做全量世界资料。

**必要检查**：上述路径一次；事件未处理时不能普通行动；重复点阶段牌不重复提交。在1080p实际键鼠操作；放大字只查长事件与固定操作区，不安排1440p／4K或独立720p验收。

**美术重点**：共同背景承托、顶底栏边界／留白、事件纹理隔离、阶段牌文字居中、占位图不抢主体；运行后修复，不接受灰盒外壳。

**完成条件**：同一真实Session跨入下一回合并能继续保存；无需旧UI完成上述路径。交付可运行入口、整屏及事件状态图、本批短记录。
