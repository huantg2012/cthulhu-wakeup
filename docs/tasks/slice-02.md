# Slice 02 · 完整游戏回合编排

本轮执行 `TASK-TURN`。唯一状态、依赖与验收绑定仍在 [追踪登记](../implementation/traceability.json)，不另设短体验前置阶段。

## 目标与范围

将已验证的正式 NPC／文明规则接入唯一的六阶段回合入口。可观察结果是：轮初到期事实先于预算；事件与自由行动共享执行机会；预支付先于同快照演化；收入和期限后果先于终局；中途保存后从正确阶段继续，不能重复领取或跳过后果。

前置是 `TASK-REPLAY`，包含其真实祖先的正式数据、身份、行为、因果与文明演化。开工已核对其来源与通过证据。读取 [回合规则](../specs/system-turn-economy.md)第 3–10 节、[进度规则](../specs/system-progression.md)、[架构](../architecture.md)及 `SET-TURN / SET-RESOURCE / SET-NPC-ACTION / SET-EVENT / SET-PROGRESS / SET-SAVE`。

## 职责与交付

- 设计：原地细化回合 spec 中的游标、事务、幂等输入、阶段续存和参与能力约定；不另造数值方案。
- 实现：`src/game/turn.gd` 负责统一回合；`src/simulation/world.gd` 保持同一正式世界并提供必要阶段边界。验证工具位于 `tools/turn-cycle/`。
- 独立 QA：对照既有规则及新增约定，检查正常路径和坏参与者、乱序输入、半途失败、不一致存档等反例。不会以阶段名字依次出现替代真实状态断言。
- 整合：维护任务追踪、架构、当前进度、工作台摘要与证据来源。共享文件按职责划分，实施与 QA 不回退彼此改动。

验收为 `ACC-ROUND`、`ACC-BUDGET`，以及本轮补齐的 `ACC-TURN-IDEMPOTENCY`、`ACC-TURN-ATOMIC`、`ACC-TURN-SAVE`、`ACC-TURN-PARTICIPANTS`、`ACC-TURN-OPPORTUNITIES`、`ACC-TURN-EVENTS`、`ACC-TURN-COST`、`ACC-TURN-DEADLINES`。完整前提、动作和预期以追踪登记为准；实际检查编号在运行后绑定，不提前填写通过。

## 验证边界

真实 NPC 与文明演化必须调用正式核心、正式 CSV。尚在后续任务中的经济、事件、权能和终局可以通过受限验证参与者构造实际支付、收入、到期死亡、失锚或终局读取，证明编排顺序与事务合同；它们的完整内容验收仍保持未完成。缺少必需能力不等于合法空集合，必须明确拒绝。

本轮不制作游戏内 UI，不改美术方向。阶段正确性可以由实际 Godot 状态、因果和续跑断言验证；玩家理解与可操作体验转交 `TASK-UI`，若后续不能正确表达状态或操作，应回到回合信息合同和 UI spec 修正，不倒置为短体验前置。

完整回合的事务和参与能力检查会增加成本，本轮单独记录正式规模的完整回合耗时及历史增长，不沿用旧单独演化的性能数字，也不设无来源的流畅度通过阈值。

不扩展完整教团经营、十二权能、祈求候选、全事件池、锚点建立维护、完整降临与断联判断；这些仍沿现有任务依赖推进。完成本轮不等于完成可玩游戏。

## 接续

开工和交付检查：`python3 tools/implementation/check.py --task TASK-TURN`。运行命令、已测范围与限制由本轮实际报告提供；来源变更后须重跑受影响的正式核心回归，不能仅刷新工作台基线。

## 接入边界补充

到期工作以整项为取消单位：同批死亡使普通恢复或迁移失效时，它的费用与配套效果一并取消，保留原计划和死亡前因。当前确定性身份仲裁不支持与检定混合，也不支持同项同时声明死亡和普通恢复；这类声明必须在消耗随机数前拒绝。后续正式危机若需要扩展，先补规则和反例，再放宽能力。完整事件随机抽样仍属于 TASK-EVENTS。
