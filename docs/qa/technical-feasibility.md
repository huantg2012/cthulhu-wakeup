# 技术可行性验证记录

日期：2026-10-25。结论：**已验证的底层能力在本机 Godot 上成立，正式游戏的完整规则、经济平衡、内容品质和最终性能仍未验证。** 本次直接执行技术验证，没有建立或要求作者先通过短可玩体验阶段。

## 环境与复现

- 本机：macOS，Apple M4 Pro，14 个逻辑处理器。
- 引擎：`/Applications/Godot.app/Contents/MacOS/Godot`，版本命令返回 `4.7.2.stable.official.ed1daf0bf`；引擎 API 版本显示 `4.7.2-stable (official)`。
- 模式：Godot 编辑器二进制的 headless GDScript 执行，无渲染、无正式导出、无外部模型调用。
- 工程：[tools/feasibility-godot](../../tools/feasibility-godot/README.md)。数据从 `data/feasibility_*.csv` 装载，规则不反向导出策划数据。
- 复现命令：在仓库根执行 `python3 tools/feasibility-godot/verify.py`。自定义 Godot 路径可加 `--godot /absolute/path/to/godot`。
- 原始证据：[technical-feasibility-results.json](technical-feasibility-results.json)。含全部断言、负载、失败原因样本、内容哈希和源文件 SHA-256。
- 本次完整运行约 10.38 秒；28 项检查通过，0 项失败。包装脚本同时验证报告为本次生成，并排除引擎脚本报错但进程返回 0 的情况。

## 实际验证了什么

**受约束文明生成：通过。** 连续 1000 个种子（1000–1999），每个生成 6 个文明、120 个具名人物，共 6000 个文明、120000 个具名人物。检查文明取值、相容条件、对象唯一 ID 与引用；1000 组有效。产生 604 种结构组合，这只证明组合空间在变化，不证明 604 种不同玩法。该输入池每组 6 个文明最多使用 6 次尝试；刻意制造不可满足条件后，第 32 次尝试明确失败，没有无限重试。

**内容装载边界：通过。** 10 类坏输入被拒绝：非法效果、矛盾数值条件、缺事件引用、后继自环、缺必需参数、整类文明维度缺失、重复 ID、非整数属性、缺范式引用和未知字段。该结果支持离线生成内容进入检查管线；不等于生成模型已接入，更不能自动判断故事语义是否合理。

**状态事件与因果：通过。** 实测前置过滤、优先级、同优先级稳定排序、冷却、一次性事件、多个事件预算下的互斥组；20 个回合可以完全没有事件。调查的后果在第 2 回合以同一个父因果 ID 返回。排队目标提前死亡后取消后果、圣物解除死亡持有人；全体死亡后不再发出祈求；过期队列项丢弃。后果只进入之后的轮次，不递归结算本轮新队列。

**资源操作原子性：通过一个代表场景。** 资源不足时干预请求被拒绝，整个状态不变。夹具没有实现正式信仰经济、低语、全部权能与苏醒结算，因此不能声称正式支付路径全部覆盖。

**随机隔离与确定性：通过限定环境测试。** 同 seed、同命令、同内容版本运行 70 回合，其中一侧额外消费 2590 次独立表现随机数，结果逐字一致。模拟推进不消耗生成随机流；不同 seed 产生不同初始世界。没有做跨操作系统或跨 Godot 版本重放。

**存档与续跑：通过。** 快照包含死亡人物、已解除持有人的圣物、尚未发生的排队事件和超过 `2^53` 的 RNG state；加载后状态与再次序列化逐字一致，续跑 100 回合仍一致；另做 FileAccess 磁盘写入读回。RNG 大整数以字符串保存，未经过 JSON 浮点数转换。

**异常存档拒绝：通过 15 个场景。** 截断、错误内容/schema/引擎版本、缺失人物、圣物持有人不存在、错误 RNG 类型、缺父因果、负资源、将新事件编号退回已用 ID、悬空最近因果、错误冷却记录、缺统计字段、重复跨文明成员及坏校验和均被拒绝，当前会话未被半载入污染。此为有限坏输入集，不是完备安全审计。

## 长期演化与负载

两个场景都运行 1000 回合，驱动在干预与遮蔽间切换以保持人物存活与持续事件资格。**这是专用负载驱动，不能拿它的表现评价正式策略或难度。** 每回合检查资源与文明指标范围；每 50 回合及末尾检查完整引用，共 21 次完整检查。以下时间不包含渲染；单回合耗时不包含测试器附加检查，但包含实际人物演化、事件筛选、执行及定期历史压缩。

这些结果支持“数个文明、有限具名人物、有限模板事件”的首版规模。不能直接外推到数千种正式事件、任意 NPC 关系网、AI 在线生成、100 个可交互文明、低端机器或导出版本。

## 暴露出的技术重点与处理方向

1. **历史增长和保存是实际成本。** 压力案例存档约 30.84 MB，序列化约 599 ms；最大回合约 51 ms。当前实现定期扫描历史压缩，未对峰值单独做剖析，不能把全部峰值归因于某一函数。正式版需要基于战役长度做保留策略，并考虑只处理新增归档、分批保存或检查点加日志。尚未验证这些优化。
2. **“有因果”需要实体状态与历史共同约束。** 不能仅把 NPC 名称插进随机段落；死亡、归属变化、排队后果和最近因果都必须存档。存档异常测试已发现并修复了 ID 复用、最近因果悬空、统计字段缺失与重复成员四类漏洞。
3. **严格复现需要固定版本。** 保存 seed 不够，必须保存各随机流 state 与待决事件。内容版本不兼容时当前明确拒绝，不承诺自动迁移；正式迁移器尚未实现。
4. **AI 规模化生产仍有未验证部分。** 本次证明 CSV 候选可以被结构校验，不证明长篇生成内容的语义一致和叙事质量。采用离线编辑、有限效果语法和运行时事实驱动模板，可以把未验证的模型能力移出必要运行链。
5. **表现独立尚需正式 UI 接入检验。** 当前模拟完全没有 Control/Node 依赖；这是可替换表现的良好边界，但未做两个实际视图互换，不能宣称美术替换已经验收。

## 未覆盖项

- 正式策划中的完整文明演化公式、教团经济、信徒成长、苏醒、跨域传播、终局和全部权能。
- 正式模板量下的检索效率、全部边界组合、长期平衡、无通解、真人理解和乐趣。
- 原生卡牌交互、视觉、音频、可访问性、窗口缩放或键鼠体验。
- 导出模板、安装包、Windows/Linux/macOS 分平台运行和低端硬件性能。
- 自动存档断电恢复、双文件轮换、云同步、版本迁移、跨平台逐位重放。
- 任意敌意文件的安全审计、运行时 LLM 生成、联网成本和隐私。校验和不是防作弊机制。

结论的适用范围到上述 28 项实测为止；后续实现扩大功能或更换数据时，应重新运行并增加对应边界，而不是沿用本次 PASS 当作整款游戏的通过证明。
