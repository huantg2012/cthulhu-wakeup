# 表现层方向评审：复杂策略游戏的决策需求

日期：2026-11-01。性质：独立专业评审。评审提交时为建议；制作人后续明确认可并授权开工，采纳范围记录于 [DEC-028](../progress/decisions-log.md#dec-028--以玩家决策组织全局结构授权制作审阅材料)。下文保留评审原论证，不将其例子自动扩成新玩法或逐页布局裁决。评审对象为 `docs/specs/ui-interaction.md` 顶部的全局信息架构计划；重点是这种游戏需要怎样的界面，而非降低返工或开发流程效率。旧美术文档、skill 和 agent 的视觉经验不作为判断依据。

## 结论

全局信息架构先行适合本作。其理由是祈求、权能、教团与锚点等选择共享资源、人物资格和跨回合后果，玩家需要把它们理解为同一个可推理的局势。局部祈求界面的完整性不足以证明整体策略判断受到支持。

但“流程/系统/数据 → 信息清单 → 场景布局”本身仍不充分。建议把现计划已经包含的“玩家问题/决策”提升为组织主轴：**玩家目标与决策模型 → 必要信息及因果/时序关系 → 信息架构与场景 → 结构线框与决策走查 → 可玩实现和视觉深化**。这是对现计划的强化；现有计划并未忽视知情、跨系统关系或结构可读性，不能将这些已有条款误报为缺失。

## 核心评审

1. **从局势与取舍组织信息。** 系统和数据说明世界有哪些事实；玩家需要比较可选行动、暂不行动、竞争资源、资格占用及未来机会。例如一次权能的费用，应能与同轮祈求和后续供奉共同判断。信息分散在各自完备的档案中，仍可能迫使玩家靠记忆拼出局势。界面可代为汇总确定的账目和直接依赖，策略取舍仍由玩家完成。
2. **将持续后果写成可理解的时间关系。** 已发生事实、已承诺尚未发生的事项、条件性预览和未知结果需要共同且明确的表达。历史可追溯只是其中一部分；与当前行动有关的过去原因、当前限制和未来义务，应能连起来理解。保持玩家知情边界，不以辅助判断为由提前泄露隐藏结果。
3. **操作频率与思考重要性不同。** 祈求/权能作为默认操作中心合理；低频的战略判断仍可能主导当轮行动。进度和域状态通常辅助，但在准备持续降临、维持锚点或应对危机时成为直接决策依据。按玩家当前目标与局势提升信息，不将默认层级固化为永久边缘位置。
4. **场景服务完整决策活动。** 支持发现机会、比较、查证、执行、理解结果和修订计划；同一人物或圣物的上下文不因跨页面消失。对象详情、局势总览和行动入口各有用途，不必将所有交互强行收进单一任务队列或为每个系统独立开屏。
5. **视觉后置须限定含义。** 材质、插画、装饰与风格可后置；分组、位置、对齐、状态层级、比较距离和阅读顺序本身承担认知功能，应进入结构线框。现计划已经区分两者，应继续保持。当前不必制作接入游戏的样板，但应以低保真材料检查跨回合决策是否能够推演。
6. **角色立场约束表达，不证明真人情绪。** 邪神视角支持把凡人与教团当作可利用、偶尔有趣的存在；其身份、能力和后果仍须可辨认。不能据角色冷漠推导出玩家不会关注某个人，也不能据疯狂主题合理化信息含混。

建议的核心判断句：在既定知情边界内，玩家能否说明自己有哪些选择、在放弃什么、哪些后果已经确定、哪些仍未知，以及世界变化后为什么要改计划。信息有位置、字段齐全和操作路径存在，都不足以单独证明这些需求成立。

## 扩展专业判断：制作人举例是输入，不限定评审范围

制作人进一步要求评审不受其知识和表述限制。以下补充仍为评审意见，未自动成为新的玩法或实施任务。

- **主动意图与被动响应：** 祈求/事件天然提供待处理事项，权能与教团经营则允许主动筹划。仅按操作频率安排界面，可能使玩家只清理事项，弱化作为邪神设定目标、选择干预对象和改变世界的主动性。需检查全局结构是否同时支持玩家主动寻找机会、比较目标和跟踪自定计划；这不是强制新增任务系统或推荐最优行动。
- **玩家理解世界的模型：** 底层对象关系不直接等于玩家应该采用的世界表征。应先回答玩家主要通过空间、组织关系、影响通路、行动机会还是时间后果理解局势；具体表征需要从玩法中推导，不能预定地图/卡牌桌，也不能完全留待信息清单完成后才考虑。信息需求和结构表达应双向修订，装饰风格仍可后置。
- **战略深度与管理负担：** 复杂度只有进入可辨认的取舍才构成策略价值。若大量字段只要求反复记忆、机械核对或执行不变操作，即使信息完整也未满足游戏需求。盘点时应标出哪些负担可以靠聚合、确定性推导和上下文比较减轻，哪些暴露了需要回机制层讨论的重复事务；不能默认用更多页面承接所有复杂度。
- **信息分配也是玩法：** 清晰说明可操作规则、已知成本与可知后果，并不要求公开所有世界秘密或未来结果。调查、判断与意外可能依赖未知。必须区别规则不明、缺失必要反馈、有意的不完全信息，避免把游戏变成全知优化器，也避免将信息缺失当作神秘感。
- **流程顺序的限度：** 公开案例支持信息分层、上下文连续、按需解释和功能性视觉，但不能证明全行业遵循“全量数据盘点完成后才开始结构设计”。建议全局决策模型先行，信息需求与结构表达相互验证，跨阶段和跨回合检查是否支持策略；近期无需运行时可玩样板。

## 可核查的同类实践及适用边界

以下是开发者公开说明的具体做法，不是行业统一流程或本作已验证结论，也不是视觉风格参考锁定。

- [Crusader Kings III 主机版 UI/UX 开发日志](https://www.paradoxinteractive.com/games/crusader-kings-iii/news/ck3-console-dev-diary-3-uiux-and-controls)（2022-03-23）：围绕形成与执行策略提供信息访问，强调菜单、地图和已打开元素之间的焦点切换，减少深层导航和大量全屏菜单。可借鉴保持决策上下文的目标；主机控制映射不直接移植。
- [Victoria 3 开发日志 #51：Tutorial](https://www.paradoxinteractive.com/games/victoria-3/news/dev-diary-51-tutorials)（2022-06-22）：按局势生成学习任务，区分 Tell me How 与 Tell me Why，并提供按需、模块化解释。它说明操作说明和决策理由是不同需求；该文讨论教程，不能当作其全部 UI 开发顺序的证据。
- [Factorio Friday Facts #318：New Tooltips](https://www.factorio.com/blog/post/fff-318)（2019-10-25）：重组与排序信息、补必要信息、移除无关信息；区分配方、物品属性与实体当前状态，保持不同入口中的同类对象表达一致。可借鉴语义组织与对象连续性，不能据此断言越多提示层越好。
- [Factorio Friday Facts #238：The GUI update (Part II)](https://www.factorio.com/blog/post/fff-238)（2018-04-13）：将装饰后置，同时处理字号、对比度和对象就地交互。支持区分装饰风格与功能性视觉组织；并不证明本作应采用其外观或布局。
- [Stellaris 3.10 官方发布说明中的 Outliner Improvements](https://www.paradoxinteractive.com/games/stellaris/news/astral-planes-release)（2023-11-16）：为后期管理引入分类页签，相关时出现，区分非紧急变化与需要行动的提示。可借鉴按规模/相关性披露信息与分级提醒，不从单个功能外推完整制作方法。
