# TASK-PRAYER-DESIGN · 两类求告与有限原根设计交付

日期：2026-10-28。状态：设计提案已写入，供制作人审阅；尚未接入代码、未运行Godot、未证明自然新局可达或体验成立。规则单源为[事件规则第14节](../specs/system-events.md#14-两类求告与有限原始处境task-prayer-design)。本报告没有替旧运行报告刷新指纹，也不把原消费夹具算成新生产证据。

## 这次具体解决什么

人物不知道邪神，也能向可能的回应者求援。人物实际识别过邪神，无论是否信仰，都能明确向它求告；知道邪神不强迫本次向它呼唤。两种求告同用原固定池和回应流程。

这份设计只做有限当前事件生成、指定人物知识记录和请求调度。它不模拟完整的疾病、家庭、社会网络、心理或宇宙法则。cell仍是聚合招募资格；无名人口被招募或后来提名，不继承整个群体的旧知识、亲属或见证。

## 已锁定方向与本轮可审取舍

作者已明确的方向不重复请批：无指向承接、实际知情者可定向，认识与信仰/察觉/F分开，撤F不遗忘，密教不需要普遍官方许可。

以下是这次为使方向可实施提出的具体取舍，**不是作者已逐项终审**：

- 知晓只由明确梦谕辨认、实际献身被接受或一次指定有源告知取得。其他祈求成功不自动使人认识邪神。
- 已知者在两种合格求告模式间作一次按发生键稳定的选择；未知者只能无向。这是有限内容取样，不是人物心理模拟。
- 新处境仍每域4轮1次机会；已发布原根的确定后继改为两模式每轮最多1次。后台不再因候选调度遗漏失去全部请求。
- 新自然危机的到期从出生时推导，给原两/三轮请求窗口留出交接时间；旧危机不续期。固定前检查实际执行阶段是否还留行动机会。
- 初始稀疏关系可含当前family/support/rival/cooperation；新的事故、争议、约定、共同读取/见证整理和宇宙同位读数是有限脚本化当前规则。
- PR08未知者的意愿是“若有谁回应，我愿替它发声”。目录标题改为中性，只有知道对象且本次定向时使用“你的口舌”。

## 从世界处境到回应

1. 有限原根规则根据实际人口、人物、关系、岗位、记录及通路产生本轮状态；已有的回应结果只能作为后续输入。
2. 下一快照以具体人物和原根提出本次求告，记录方向、必要的采样时知识证明和唯一发生键。
3. 验证来源、当前窗口与原P/N/候选容量后，使用World.fix_prayer_source同一入口固定，不另建第二个祈求池。
4. 固定请求最早下一轮展示；最多3张、回应1张，浅/深费用、概率及效果不变。新外部root在T出生，最早T+1求告并固定、T+2展示。
5. 回应前重查当下对象和原F/媒介/成员准入；回应后写实际后果。窗口与原危机分别到期，失败回应不解除危机，也不叠第二笔未回应罚。

无独立危机的当前contact允许从旧人口/机构快照直接产生并固定。bootstrap提交初始化后取独立快照，从当前非信众合法提名一个无向PR08求告者，实际扣人口/预留身份并验证浅触可执行；不能用高阶不可回应模板或预置认识保证起点。

既有具名人物的完整call/采样知识/意向先作为世界意图提交；预期容量阻挡只撤fix预留及候选，后续仍沿原call。匿名contact先核完整提名/固定容量，成功才同事务扣人口、命名并生成call/fix，阻挡时没有虚假人物或call；真正事务故障全部回滚。

容量不足、没有前提、没有行动窗、未到抽样轮、未选中、已消费分别记原因；缺生产者是接入失败。拒绝固定不改原人、原意向、原危机到期，也不挤旧卡。求告索引只有当前原根/有限主体和可续游标，独立危机全部继续由原due索引结算；不是无限新候选队列。

## 两模式与知晓的可观察正反例

| 场景 | 应能观察到 | 不能拿来代验 |
| --- | --- | --- |
| 重点域、未知邪神的人、合法处境 | detailed_candidates正式处理者从实际根产生无向call并固定 | 手工插候选、只见处理者名字 |
| 后台域、未知邪神的人、合法处境 | abstract_candidates_due处理同一类原根后继，不要求先取得F | 只有后台无向而缺重点生产 |
| 重点域、已识别但非信徒、本次选择定向 | 原取得事实早于采样；directed call引用同一对象，原低忠诚不强制过滤 | 只改忠诚或在当前know集合塞任意事实 |
| 后台域、已识别者、本次选择定向 | 同一有源知识可持续，后台仍有定向来源；深回应可因缺F不可用 | 重点定向成功代替后台定向 |
| 已知者本次选择无向 | 无向仍合法；不会因现在知道神就被强制升级 | aware=true即所有请求定向 |
| 无向卡固定后才辨认邪神 | 旧卡方向/可见轮/due不变；新独立处境才可重新选意向 | 用新知识补旧卡采样证明 |
| 神迹失败或只看到异常材料 | 不写身份辨认；原请求/危机照原后果 | 祈求结果存在即识别 |
| 撤F/离团/迁移/发送者死亡 | 保留取得历史，当前域/角色/通路资格按规则重查 | 撤F删除知识，或保知识即任意权能永久可用 |
| 同争议、同人、02/10均合格 | conflict_petitioner先持久选一个need，失败/切F/知识更新不再出第二型 | 发生键含need所以各发一张 |
| 原危机在可见轮的阶段一到期 | no_action_window，不发出生即失效卡，不延原due | 只比较visible<=due认为一定可回应 |
| 当前根满/固定池或人物容量满 | 有明确拒绝原因；危机仍到期，未出现无来源替身或续期 | 把missing_producer写成容量满 |
| 保存/重试/切F/重复开页面 | 同一call/知识取得位置、发生键、方向和源时钟，消费不重放 | 重新抽模式/根、重算checksum洗旧版 |
