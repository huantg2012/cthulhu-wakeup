# 正式调度与模式交接：制作人报告

状态：本批实现及独立限定验收通过，2026-10-28。调度专项55项行为＋5项运行检查通过；原知晓专项72＋5项正式重跑通过，未削弱原断言。对应 TASK-PRAYER-DISPATCH；父任务 TASK-PRAYER-ORIGINS 尚未完成。

原来的实现问题是：重点关注一个世界后，代码停止走后台的候选生成，却没有由详细模式接替；到期机会仍被推进，相当于消耗了一次没有执行的机会。这是调度实现缺陷，不能靠调整出现概率解决。

本批把安装了 Events 的正式回合接到一个协调入口，详细和后台按阶段四演化开始时的同一份快照分别处理，并共用新机会的四轮游标。已发布的合法求告处境另按每轮有限检查处理。指定身份告知检查具体发送人、接收人、原知晓、关系与通路；选中与告知须在同一笔结算中完成。这里处理的是有限具名人物及来源记录，没有新增社会传播网络模拟。

独立复核发现并修复了三个问题：同时修改记录和游标可能互相自证；同一求告人的不同独立处境会被后写覆盖；容量不足后，分页位置会让晚到期处境抢先。现在分别保留独立来源，按原危机期限排序，并检查随机转移、分页位置与实际结算回执。新增反例均经正式回合入口重跑通过。来源省略重复的危机字段时，排序仍读取原危机期限，不延长期限。

测试还发现前轮知晓实现漏了首名信徒：没有现成教团时，人物已完成实际成员转换，却没有“加入某教团”的记录；代码强读该记录导致成功回应报错。本批改为引用本次实际成员绑定，并核对本次献身、请求及同笔回执。现成教团与无教团两类前提都有实际回归，浅/深回应成功、失败及保存恢复均覆盖。它没有新增知晓途径；失败回应仍不授知晓。首次路径的前提核查已交后续CAPABILITY-AUDIT承接。
