# 有限关系网与跨机构合同：制作人报告

本轮做的是TASK-SOCIAL-GRAPH-DESIGN：确定规则、参数和各实现任务的接口。游戏代码未改，新关系网还没有运行。

## 人际关系怎样改变

原来初始化把人按序号连成环，每人基本只有两个邻居。新设计先看同机构共事或现有机构往来是否允许接触，再按共同职责、关切和共同联系人分配联系；已有跨机构联系较少时提高其权重。六人初态目标是七对邻接，每人的上限按初始影响有所不同，允许小圈子、联系较多的人和跨机构联系，不强迫每局同一张图。

亲属、合作、竞争是互惠类型；支持、敌意、欠人情有方向。同一对人可以同时有几种关系，不能据此多算联系人。初态只给本次新定义的人物建立背景；已有bootstrap人物可能仍孤立，下一项ROUTES必须设计合法的当下接触/合作途径，不能补造旧亲友。普通招募仍从人口池聚合计算，这不是全人口传播模拟。

模型包含22项参数、6种关系。数值是本游戏的预算和节奏取舍，研究仅提供接触偏好、局部群聚和桥接的参考，不能称作现实社会学拟合。参数与未来128种子的统计门槛已写CSV，统计尚未运行。

## 同时堵住的三个接口问题

1. **争议到期不能顺便送职位。** PR02现在设计为沿机构原立场结案；岗位、代表和人物归属不变。处理机构与争议双方所属机构分开，真实岗位继任继续由EVENT03专线处理。
2. **共同见闻不要求同机构，审查也不能越权。** 不同机构的真实关系人可以实际共同读取同一记录。只有这次确实提交到该机构的个人登记才受审；PR07/EVENT06保持或撤销的也是这一份资格，不能抹私人知识、邪神身份或其他机构的独立见证。没有有效可处理资格，不能领取空审查收益。
3. **揭示信息必须有新信息。** PR10不能把当事人已知的对手关系再告诉他。本版只取祭仪记录的真实发起人作为第三人，只揭示一条此前已存在、祈求人尚不知道的“对手与发起人的关系”。争议资格边、待披露边和EVENT09合作方的真实供给结构分别保存；第三人仍在原最多四人的预算内。

第三项给出无需先有PR10/EVENT09的设计路线：已有图中的作者实际产生祭仪记录、取得这份记录知情，向真实参加者共同展示/递交；双方再就该记录产生争议。祈求人读到了记录，不等于知道作者与对手的另一条关系。现有祭仪生产只写事实而没交回发起人的缺口，已明确交SOURCE-MEMORY修正；LOCAL-CONFLICT先依赖MEMORY。此路线还没有运行，不能据文档称已经连通。
