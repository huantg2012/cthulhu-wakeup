# TASK-SIMULATION-STRATEGY — Lightweight Simulation Strategy and Scope Revision

制作人指出模拟过细、成本过高。本轮已修改规则和后续任务；轻量生成器尚未接入游戏。

默认改为“少量条件 → 加权抽签 → 一次确定情境 → 结算重要后果”。例如亲属求援直接生成必要人物、背景、期限和结果，不先做职业活动、事故、伤害、传话链。共同见闻、约定和第二观察也用同样粒度概括。

保留会影响玩家判断的资源、身份/死亡、重要关系、材料独立性、跨轮进度、期限和一次性结果。已有事实不能被抽签改写；抽签背景不能描述成已运行的社会过程。必要进展仍有不同路径、玩家促成与概率修正。

实际削减：

- 13个来源子任务合回五个SOURCE父任务。
- 14个未开工的Core、业务操作和界面细分合回 `TASK-PROGRESSION-OPERATIONS — Critical Progression Route Integration`，不预设18套新活动。
- 保存负例并入 `TASK-CULT-SAVE-COMPAT — Current Rule Version Save Compatibility`，不再做全仓库联合重签审计。

共28个细分撤销，必要玩法归并，不计为完成。映射在 `docs/tasks/slice-14.md`。路线CSV仅同步18处责任任务列，未调整数值，仍为design_only。

本轮检查限于规则/计划一致性、任务引用与依赖、CSV改动范围和工作台同步；没有新引擎运行，也没有把旧报告改签。当前旧事故代码冻结、未验收，旧诊断已结束，剩余测试预算撤销。后续以少量可控随机输入检验正式生成与实际后果，不逐切片重复全量回归或搜索数百种子。

制作人补充的测试要求已同步：共享核心集只守回合、资源/名额、正式生成到回应、期限/一次结算与保存；每任务默认2–4个相关代表用例、快速批次目标≤60秒。复用工具，实际Bug补最小回归，不预设大矩阵、联合重签/历史规模测试或每任务新运行器。

下一项：`TASK-SOURCE-LOCAL-TIES — Current Incident and Kinship Prayer Sources`，端到端替换为轻量求援情境。原两个实际阻塞、完整新局及玩家体验仍未通过。
