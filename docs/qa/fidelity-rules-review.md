# TASK-FIDELITY-RULES 规则与数据验收

本项完成正式规则、数据预算和实施接口，未开发分层运行时。静态配置检查与独立 QA 语义审查支持交接下一项 `TASK-INCREMENTAL-TX`；它们不证明模式切换、预留事务、混合负载、玩家体验或平衡已经通过。

## 交付与数值边界

五个系统 spec 原地更新，L1 exposes 登记新增接口；架构明确当前全详细参考实现和六项后续改造。新增 `fidelity_parameters.csv`、`intervention_policies.csv`、`simulation_responsibilities.csv`，保留旧参数的唯一归属。

初始工作值为 F=3、N=12、P=12、L=6，因此详细人物去重集合的理论上界为 42；失能人物与退役保护也计入容量。全局活身份上限仍是原表的 144，展开管理页仍是 6，两者均不等于 F。后台日常间隔为 4 轮；经济、机构风险与到期事项逐轮准确执行。数值是可验证的容量约束，不是帧耗时或平衡结论。

## 自动配置证据

实际运行 `python3 tools/fidelity-rules/verify.py`，检查 77 个入口分类、14 个唯一职责、参数类型/单位/容量关系和正式内容覆盖；23 项测试包含缺分类、重复分支、非法枚举、单端迁引、深回应/浅破屏障绕过、入团无预留、默认分支索要新容量、后台重复收入/暂停风险及无效预算等反例。

[配置机器报告](fidelity-rules-results.json)绑定读取的 CSV、五系统 spec、架构、任务书及校验器源指纹。检查器没有启动游戏或替代 Godot loader；新表实际接入仍由 ABSTRACT-SIM／ATTENTION 任务验证。

## 独立规则审查与修正

qa 子 agent 只读对照原内容表与新规则，主会话落实以下修正并复核落盘：

- 候选阶段：常规背景生成在阶段四，固化与生成同事务；阶段二只从既定候选选择冻结。bootstrap 使用相同容量/人口规则；阶段二/三的确定性后继沿用已授权来源，不重抽随机机会。职责表同时登记 bootstrap 的身份、准入和固化责任。
- N/P 双满且同人被两个未结互动引用时，默认离团立即解除成员权限，原 N 转退役保护，直到义务结束或轮初可原子转 P；不挤走义务、不阻塞默认后果、不免费增加详细人物。
- `EVENT_11` 原目标失效即结束旧计划；换目标必须另案预告。`EVENT_01/05` 替代主体只能用固化时已存在并预留的真实身份，禁止临时补人或伪造旧史。
- 主动入梦、一次性破屏障、全部深干预及传教同样取 F；后台守持、敛藏、供奉和收入保持原有准确结算。迁引与降临一次预留两个相关域，不能同轮循环释放。
- 成员身份、忠诚、持久身份及详细激活分别保存；成长不会自动入团。候选共享人物按引用持有，随机分支先预留最大需要，未展示建议可静默，已承诺结果不可吞掉。
- 后台日常与重点日常互斥，经济唯一生产方，所有域机构风险仍逐轮执行；已有暴露及确认来源不因撤关注消失。完整冷历史保留，当前投影有来源撤销与去重协议。

上述反例已经写回后续任务的验收条件，但**未执行其运行时场景**。本审查没有“真人觉得好玩”或“性能已优化”的结论。独立审查认为规则可交实现，无需重做整体方案；初值仍待作者与正式负载/平衡验证。

## 旧证据适用性

架构/spec 修改使旧报告指纹失效。本轮实际重跑 SIM、TURN、ECON 原套件，报告新增 `executionProfile=all-detailed-reference`，保持断言、原运行规模和实现。其证据只支持既有共同不变量及旧参考行为，不能覆盖新 F/N/P、惰性提名或概略日常。具体运行结果分别见 [NPC/文明](formal-simulation.md)、[回合](turn-cycle.md)、[经济](economy.md)。

下一项以这个明确范围的参考实现开展增量事务差分；其后索引、分段存档、后台生产者、注意力及混合集成分别验收，不另设短体验前置阶段。
