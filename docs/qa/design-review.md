# 策划案一致性与覆盖审查

日期：2026-10-25。状态：首版策划交叉审查与技术证据核对完成；新增机制仍是待作者审阅的提案，正式玩法尚未实现与验证。

## 范围与证据边界

本次是设计文件与技术验证证据的独立核对，不是试玩评测。基准为作者的原始构思、首次评审确认项及本轮要求：完整自然语言策划案、Godot、技术难点直接验证、机制优先与最简交互、美术后置但架构可替换、跳过单独短体验前置阶段。

策划案中的新增具体机制是供作者审阅的第一版提案。自动检查只能支持其实际覆盖的规则、数据、存档和性能结论，不能证明好玩、完整经济平衡、无通用最优策略或最终美术品质。

## 覆盖与结论

1. **回合与决策：规则覆盖。** 每轮最多一项祈求回应、可使用多个合法权能；允许零事件、不回应、无钱承受和无对象结束回合。支付、演化、收入、期限与终局顺序均有归属规则。
2. **经济与进度：规则覆盖，平衡未验证。** 收入上限、自然流失、人口来源、扩张费用、污染到锚点再到苏醒、维护拒付、进度回退与资格刷新均有说明；不把有限策略检查当作无通解证明。
3. **文明与抵抗：规则覆盖。** 层级与混合范式分别定义，完整屏障仍可污染；蓝本给出可观察的传播和机构承认条件，正式抵抗表有资格、优先级、预告、冷却与后果。完整状态演化未接入技术夹具。
4. **人物、教团与圣物：规则覆盖。** 四属性初始蓝本、提名与活人人口口径、自然形成教团、任命与继任、献祭、死亡、迁移、圣物唯一归属和不可重复兑现已说明。正式大规模角色关系与成长尚未运行验证。
5. **事件与因果：规则覆盖，基础技术部分验证。** 状态筛选、冷却/互斥/唯一、零事件、死亡对象、到期、明确选项和事实回调已有定义。技术夹具覆盖代表性链路，未覆盖所有正式条目的组合与叙事品质。
6. **内容生产：方案与首批标杆覆盖。** CSV 是策划输入，模型不自由改规则；祈求主事实、事件效果、文明条件、人物原型与抵抗条目分别有来源。发行内容尚未量产，语义编辑质量不可由结构检查代替。
7. **技术与表现：基础技术部分验证，表现未验证。** Godot 实测有证据；纯数据模拟不依赖呈现节点。最简 UI 的操作与信息责任已有方案，但没有正式交互实现、双视图替换或美术验收。
8. **交付边界：已核对。** 主案为自然语言策划与导航，技术材料单列；没有恢复短体验前置门槛，也没有提前宣称完整游戏或作者终审完成。

- 人类试玩、乐趣、长期平衡、真实内容量产质量、最终美术与声音：本次未验证。

## 技术证据核对结论

证据为 [技术报告](technical-feasibility.md)、[机器结果](technical-feasibility-results.json)和 `tools/feasibility-godot/` 对应源码。最终记录为 28 项通过、0 项失败，报告明确这是纯数据技术夹具，不是正式游戏实现。

源代码和断言覆盖受约束生成、状态与因果调度、独立随机流、同环境复现、死亡对象与物件归属、存档续跑、坏内容/坏存档拒绝和两档长期负载。压力场景每轮确实更新人物并筛选事件，检查点保持 2000 人存活；不是以世界灭绝后的空转作为性能结论。

已核对其公开限制：没有正式教团经济与全部权能，没有跨平台导出测试，没有正式界面或美术替换验收，没有把结构组合数量视为故事品质。千回合压力场景的历史与保存成本已列明，不能据低 p95 回合时间忽略序列化峰值。

## 数值自洽的有限检查

- 对当前成功率下限至上限的全部 81 个整数概率，按统一四档公式检查一至一百的骰点，区间完整且不重叠，深成加普通成功的点数等于标示成功率。
- 一星球、一星系、一宇宙各三锚、洞见达到上限且无创伤时，公式苏醒为 93、维护为 21、三团理论收入上限为 24，因此没有发现终极门槛在代数上不可达。该假设不保证对应状态能在真实反制中建立或维持，也不是通关攻略或平衡证明。
- [玩法内容手册](../content/gameplay-catalog.md)的十六轮首锚样例，列明支出 38、期间收入 23、开局 18、结余 3，算术一致；自然流失不会使该样例跌破所需人数。它明确约束为指定成功结果和没有额外经济损失的账面样本，不是完整随机世界模拟，更不是另设短试玩关卡。

## 审查期间发现与处理

- **D-01 · 锚点定义冲突，已修正。** 文明文件初稿用统一污染 60、三轮建立与两轮宽限；核心数据用按机构序号 25/50/75 的门槛及即时判定。现文明文件引用核心规则，删去重复门槛，并统一未建立/有效/休眠/被毁状态。
- **D-02 · 标杆内容操作不够确定，已补齐首批条目。** 首稿存在“付代价”“忠诚增加”“改变主张”等未定效果，以及文明机构继任被误当教团任命的风险。现由文明条件、事件效果和祈求事实表明确其边界；机构继任和回收是事件专用行动，不冒用教团任命。
- **D-03 · 结算时点与资格存在歧义，已明确。** 旧锚点至实际拒付结算才失去贡献；新锚点付本轮供奉后才生效；苏醒/峰值/容量在事实变更后刷新；首建直接委任护持者；换护持须任命生效后修复；低语转化只能补到本轮初始预算；降临最后轮的骰率在付费提交时锁定，轮末再复核持续资格。
- **D-04 · 正式人物与人口基线缺失，已补齐。** 新增六种正式人物属性/处境蓝本及每域初始人数、全局活着具名上限、人口容量与提名规则；没有混用技术夹具的属性口径。
- **D-05 · 请求与危机、事件与物件的生命周期混淆，已明确。** 失败回应消费卡牌但不取消原危机时钟，不重复征收未回应惩罚；事件产生的可处置遗物可以当轮使用，其后继调查仍最早下一轮进入事件筛选。定点复核后与首锚账面样例一致。
- **T-01 · 存档可能复用历史 ID，已修正并纳入拒绝测试。** `next_event` 不能退回已使用序号；否则下一条事实可能覆盖历史。
- **T-02 · 存档引用及运行字段校验不足，已修正并纳入拒绝测试。** 最近因果、冷却记录、必需统计字段和人物归属的逆向关联已补检查。有限坏输入集通过不代表完备安全审计。
- **T-03 · 压力驱动后半段人口灭绝，已由实现方修正。** 改为持续活跃的专用负载驱动，并记录候选检查次数与存活人口；该驱动不作为正式策略评价。
- **T-04 · 历史压缩可能丢结果事实，已由实现方修正并新增独立断言。** `success/effect/delta` 留在事实字段，压缩只删除冗余显示标签，保持父因果、对象、事件类型和结果可追溯。

本轮发现的具体设计歧义已在上述范围内收口，没有保留已知的首版策划阻断。该结论不替代正式玩法验证，也不表示没有未覆盖的边界；自然语言条目仍需在实施时转换成有限结构化效果并逐项检验。
