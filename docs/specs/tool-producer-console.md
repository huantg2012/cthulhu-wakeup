TL;DR：为制作人提供游戏能力、关系、时序、内容与数值假设的可视化阅读入口，并把讨论保存在具体对象及其来源版本上。本工具属于制作辅助；它的完成不表示游戏已实现。

# 制作工作台

## 阅读职责

主图描述“玩家可以做什么、世界会怎样回应、付出什么、影响谁”，不按类、服务或程序目录组织。每项机制至少解释能力、前置、输出、代价、不得丢失的边界与仍需判断的问题；点击连线可以追踪两端与关系来源。

回合视图解释结算先后，因果路线解释可能的后果链，内容图鉴直接读取 CSV。数值试算只重算已声明的公式，明确有效锚点、已付供奉等输入假设。试算不替代 Godot 模拟、长局平衡或玩家体验证据。

来源按钮必须能查看对应策划正文或 CSV。已确认方向、设计提案、独立技术证据、正式游戏实现应清楚区分。每次数据加载显示来源版本；生成离线页标明快照属性。

## 实施追踪职责

同一个本地工作台加入关键行为、结算约定、开发任务和验收场景四类阅读入口。来源为 `docs/implementation/traceability.json`，证据判定由项目追踪检查器统一提供；界面不能自行把计划状态当成运行结果。

- 每项关键行为能找到权威规则、相关机制、开发任务、结算约定和可否证验收。缺任务、未完整接入、证据缺失、证据过期与检查失败分别显示。
- 每项结算约定展示责任、读取与写入事实、生效阶段、冲突解决顺序和不变量，避免只看见系统箭头而看不见具体结算职责。
- 每项任务展示实际前置、负责人、交付范围、风险、范围外工作与验收场景。不能根据游戏作用关系图自动推定实施顺序。
- 每项场景展示给定条件、动作、预期后果、检查编号、运行时间、报告来源和来源变化。证据的文件指纹匹配不等于报告检查通过；玩法品质与人工判断仍保留独立验收。
- 支持按机制、状态和文本筛选；机制详情能跳到相关追踪。`REQ-*`、`SET-*`、`TASK-*`、`ACC-*` 都是可讨论、可复制、可定位的稳定对象。
- 概览并列显示已登记行为、有任务行为、已接入行为和有当前通过证据的场景数量，不将它们合成“游戏完成百分比”。
- 本地版更新来源时重新计算证据适用性；离线版携带同样的追踪、原文和报告快照，明确不会检测生成后的文件变化。加载失败必须显示错误，不能渲染为空列表并暗示完成。

## 沟通职责

议题依附机制、关系、具体内容定义或实施追踪对象，保存原文、类型、状态、创建/更新时间和记录时来源版本。可复制带来源的上下文、导出 Markdown 与导入/导出 JSON。导入不能静默覆盖同编号不同内容，两个页面不能凭旧版本覆盖彼此。

议题处理状态只表示沟通进展；是否采纳设计、是否进入开发、是否验收，仍由用户授权和对应正式记录决定。当前版本只提供主动保存与移交，不连接聊天服务，也不在后台自动执行议题。

## 更新职责

规则真相保持在原 spec 与 CSV。工作台是摘要索引；修改来源后允许新原文和旧摘要同时可见，但必须明确“待复核”，不能自动涂绿。更新摘要后才能重建指纹基线。新增机制、来源与讨论目标保持稳定编号。

## 界面与交付

载体是独立的制作软件，使用清晰文字、关系图与详情阅读栏；不套用游戏内 HUD，不决定游戏美术风格。桌面双栏和窄窗口上下排列都保留文字导航，节点与关系可用键盘选择，不用颜色独自表达风险或状态。

本地服务将讨论写回仓库，提供离线 HTML 阅读快照。后续如需跨设备实时协作，再增加共享存储、身份与同步；保留现有稳定编号和讨论交换格式，避免更换界面造成历史沟通失效。

## 可否证验收

- 点击一个机制能找到能力、得失、关联和真实来源；点击一条关系能找到方向与作用。
- 任何内容图鉴行能对应原 CSV 行；试算系数从 CSV 读取。
- 保存一条议题后重载页面仍存在；用旧版本提交不能覆盖新记录；格式错误的导入不部分写入。
- 改动来源文件后，刷新必须出现待复核；只按“更新来源”不能清除漂移。
- 离线页不请求第三方资源，可浏览机制和公式；明确说明离线讨论的存储位置和回传方法。
- `REQ-* → TASK-* / SET-* → ACC-*` 可以逐项打开、记录讨论并以稳定定位链接再次打开；讨论状态变化不改变追踪判定。
- 来源指纹变化后重新加载，相关证据显示过期；报告指纹匹配与检查通过分开表达。
- 工作台完成度与正式游戏完成度独立报告，详见 [验收记录](../qa/producer-console.md)。
