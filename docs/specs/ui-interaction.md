# 全局信息架构与表现层规划（2026-11-01）

依据：DEC-027/028的方法与开工授权，以及DEC-029对首稿的否定和整体重做要求。旧三个活动空间、固定图数及锚定日常链已撤回；当前稿重核正常回合、世界与其他必要信息，并提供常驻最新消息和可展开编年史。本节优先于本文旧的最简界面布局与推广顺序。现有支付、资格、知情、输入和结算规则继续由各自系统负责。frontmatter 的 implemented 状态仅指旧功能界面；新结构由 `TASK-UI-STRUCTURE` 承接，当前 in-progress，以下结构稿供审阅，尚未获得人类理解/操作验证。

## 1. 已确定的输入与推导边界

**制作人明确要求：**

- 本作系统复杂且仍将增长。先由游戏流程、系统规则和数据建立全局信息清单、层级与关系，再决定场景划分、布局和交互；不以单个祈求样板推定全局架构。
- 默认注意力以祈求处理、权能行使为中心；中后期增加教团管理。事件低频但处理优先级高；整体进度和域状态重要，通常承担辅助判断。
- 玩家角色是邪神，疯狂与混乱是持续主题；凡人与教团在角色立场上渺小、可利用，可能因其特殊性而有趣。不把保护凡人、同情祈求人设为默认动机。
- 近期交付应能表达全游戏场景和界面结构，可玩样板、风格选择及正式视觉制作后置。
- 自行从已定玩法推导设计，不逐项索取确认。所有关键输入、判断及变更持续留档；专业化转述，不将口语比喻自动扩成机制或设计规范。
- 本轮不使用旧美术文档、skill 或 agent 中的视觉经验作为新结构的前提。既有界面只用于后续核查当前功能入口，不作为目标设计。

**本轮专业推导（设计判断，非制作人逐项裁决）：**

1. 使用频率、后果重要性、紧迫性和当前行动关联度分别判断。高优先事件应在合法处理时点优先呈现；不能据此让每个事件随时打断选择。域状态或进度触及当下资格、期限或存亡时，应从辅助信息提升为当前决策信息。
2. 人物的辨识度服务于能力、稀缺资格、关系、可利用性和行为后果；冷漠立场不消除身份连续性，也不强迫现实玩家只能产生一种情绪。疯狂与混乱不推出随机按钮、模糊费用或不可读的布局。
3. 数据存在、玩家知晓、当前决策需要，是三道不同筛选。内部标识、证明字段、后台候选和隐藏关系不因对设计者可读就获得玩家展示资格。
4. 场景指玩家的稳定活动空间与操作上下文，不预设为独立引擎场景、地图或每个系统一页。先确定必须同时看见、比较和操作的信息，再决定何时换场景、展开详情或暂时覆盖。
5. 全局先行要求覆盖当前已设计的全生命周期、主要跨系统关系和信息规模；不要求穷尽未来内容。给对象、关系和操作模式留下扩展方式，不为未知系统预造入口。
6. 风格、材质、插画、配色和装饰后置；信息密度、阅读顺序、比较距离、操作可达性须在结构线框中验证。可用结构材料修订架构，不把首次纸面设计永久冻结。

这里的“注意力”指玩家认知资源；游戏机制中的 F/N/P 容量、关注或低语另按原规则，不能相互替换。

## 2. 信息架构的分析坐标

同时分析三条时间轴：**整局发展阶段 × 回合阶段 × 单次操作状态**。前中后期按已存在的能力与管理规模区分，不擅自规定第几回合进入某期。跨域与扩张可以与其他阶段并存。

下表是已读规则支持的初步覆盖框架，不是完整信息清单或已定页面：

| 局势/阶段 | 主要决策与必要信息 | 关联/辅助信息 | 必须覆盖的变化 |
| --- | --- | --- | --- |
| 新局与继续 | 已知世界、可接触对象、当前预算、合法行动；继续时恢复未结事项 | 已有进度、原局身份与近期变化 | 未知信息不全知展开；继续不重置上下文语义 |
| 建立现实联系 | 祈求比较、浅/深回应、权能目标、成本、资格、期限 | 相关人物/机构、已知域状态、现有联系与来源 | 无教团、资源不足、对象失效、回应机会已用 |
| 教团形成与经营 | 人员/职责、策略、实际可用预算、供奉次序和缺口 | 成员资格、圣物、锚点依赖、暴露与收益 | 新团尚无收入、任命待生效、多人/多团比较 |
| 跨域发展 | 不同域的行动机会、关键依托、可分配主体/媒介和容量 | 通路、已知文明差异、后台变化摘要 | 查询/切换与实际关注操作区分；后台仍演化 |
| 反制与局部危机 | 受威胁对象、后果、剩余期限、当前可行处置 | 受影响的锚点、人物、资源和进度 | 多项风险同时存在；原计划失效或暂失能力 |
| 持续降临与临近终局 | 当前持续条件、已付与待付、机会/主体占用、中断风险 | 有效锚点、苏醒来源、信仰和断联情况 | 持续条件失去；高阶能力回退；结局优先级 |
| 结局与回顾 | 结局原因、关键已知后果、本局回顾、新局/退出 | 对象关联与已知历史 | 只读封存，不把回顾当新行动或补发隐藏知识 |

每行还须横向穿过轮初整理、事件处理、自由行动、计划锁定/演化、收入/期限、终局判断；并检查浏览、选择、预览、执行、结果、取消/返回等操作状态。系统结算阶段不自动等于独立画面。

## 3. 工作顺序与交付物

### A. 全局决策与信息盘点：先回答玩家如何形成和修订计划

先由五个机制 spec 建立目标、可选行动/暂缓、共同机会成本、持续后果和改计划条件，再以正式 CSV 与当前公开接口核信息。建立“阶段—决策—信息—对象—来源”矩阵。规则定义、实际实现、当前玩家可得信息分开登记；数据装载状态、旧文矛盾或接口缺口标明，不用界面文案补造能力。A/B/C 双向修订，不以全字段审计结束作为第一张结构图的前置。

信息条目至少记录：稳定条目 ID、玩家问题/决策、所属对象及关系、机制/数据来源、出现阶段、知情条件及精确程度、时效/更新触发、默认阅读层级、关联操作、需要共同查看的信息、空/多/失效状态。对不应展示的内部数据说明排除理由，不逐字段照搬数据库。

产物：**全阶段信息矩阵 + 对象/依赖关系图 + 明确缺口表**。关系区分归属、控制/持有、行动资格、资源依赖、因果、知情与时限；有关系不等于玩家已知，有依赖不等于需要画整张网络图。

### B. 场景与导航：由信息和任务确定空间

在 A 的覆盖基础上，划分稳定活动空间、主次任务、共享上下文和进入/返回路径。逐一判断哪些内容常驻、随选择更新、按需展开或仅在特定时点出现；跨系统比较与操作链优先于按代码模块分菜单。

产物：**全局场景/导航图 + 每个场景的信息职责表**。必须能沿祈求、权能、经营、危机、轮末与终局完整走查；人物/圣物/机构/历史的关联查询要能返回原任务。此时不预定左栏、右栏、卡牌桌或地图布局。

### C. 全局结构线框与交互合同：让结构可以审阅

为 B 的所有主要场景提供低保真结构线框，并以早期低规模、中后期高规模、危机并发等内容实例检查。线框标明信息区域、阅读顺序、主要动作、关联详情和覆盖层；共用结构可复用，但须展示各阶段实际承载差异。

同时规定选择/比较、目标与媒介选择、展开/返回、事件处理时点、轮末预览、临界提示、结果阅读、不可用解释、保存继续的上下文恢复。键盘/鼠标及选中/焦点模型在此阶段定义；不把拖拽预定为必要输入。

产物：**全场景结构线框组 + 关键操作流程图 + 显示/切换/返回规则**。材料使用一致的编号互相引用，优先汇集在本文；必要的导出图是本文的派生产物，不另建第二套有效 UI spec。当前不接运行时、不制作可玩样板。

### D. 全局走查与交接：覆盖成立后再进入实现和视觉

以信息矩阵逐项反查场景和操作路径：每项玩家任务有入口/后果/返回；每项必要信息有可达位置和来源；同一资源、人物、圣物和期限在不同表面语义一致。用少量有代表性的纸面情境查空/满、未知、失效、多域、多团、多个到期事项以及持续仪式，不跑全组合游戏模拟。

产物：**覆盖对照表 + 结构问题清单 + 实现/视觉交接边界**。结构审阅证明信息可承载和流程可推演，不冒充实际操作、性能、审美或乐趣通过。之后可分批实现与验证，但不再由一个局部样板倒推整局架构。

- `TASK-UI-STRUCTURE`（design）负责 A–D，Director 汇总判断与冲突。输入为现有设计、数据和制作人方向，不把全局平衡或旧运行证据全部复验设为设计开工门槛。

- 方案变更原地更新本 spec，并同步决策、任务与进度入口；旧说法的失效范围明确写出，Git 保存历史，不靠聊天摘要承接。

- **未完成边界：**静态结构和源码核对不证明实际理解/操作通过；接口缺口仍须后续接线。首稿不覆盖每条内容文案/每项选择器的最终像素细节，不制作运行时样板。

## 重做依据：玩家实际会做什么、需要知道什么

本轮按DEC-029整体重做。旧首稿的三个活动空间、固定图数和默认锚定操作链撤回。以下布局仍为提案；用户明确要求的是正确流程、具体游戏功能、完整的信息评估和方便触达的编年史，并未逐页认可布局。

### 正常一回合

1. 展示轮初已经发生的变化。有必须处理的事件时处理事件，没有则直接开始自由行动。
2. 主界面提供当前祈求和权能。每轮至多回应一张祈求，也可不回应；权能可在回应前或后使用，不强制排列成一串任务。
3. 选中祈求后就在原操作里阅读诉求、选择回应、人物或媒介，并查看费用和结果。选择权能也是如此。不同权能只出现实际需要的选择项。
4. 点击执行后立即扣费、结算并显示结果。玩家随后可继续合法行动；无需先去编年史才能知道成败。
5. 已有教团的策略沿用上轮，按需要修改。查看人物、圣物、世界和历史不消耗行动资源，不强制逐页巡检。
6. 点击结束回合后按原六阶段规则结算。普通回合不强制进入审核页面；实际重要到期事项可就地提醒。只读结算摘要不增加一个新行动阶段。

锚定是有条件的权能，持续降临是后期特定状态；二者的费用和依赖要讲清，但不代表日常操作。首团前的合法组织行动仍需入口，不能以低频为由删除既有玩法。

### 游戏内名称与信息取舍

玩家界面直接使用祈求、权能、教团、人物、信徒、圣物、世界、编年史、低语、信仰、苏醒，以及实际人物/组织/物件名称。世界为当前说明性的功能名，具体世界应以自身名称和已知特征辨认。

域、F/N/P、内部机构职责、事实编号、经营、当前牵动、现实依托、跨系统行动等不能作为玩家区块名。不能把“域”换成“诸域”继续使用，也不为邪神题材另造一套晦涩替代词。制作资料中的规则引用与缺口说明不进入游戏画面。

每项信息须至少支持一种真实需求：比较选择、理解规则与费用、识别人或事、察觉变化、记住仍在持续的事情、解释结果。暂时用不到的信息仍可查，但不挤占每轮核心操作。未知内容与尚未接入界面的内容分别登记。

### 查看一个已知世界：应当看到什么

玩家查的是“那个世界现在怎么样、我在那里能接触谁、我的行为留下了什么”。不能把世界做成一张全知指标表，也不能只剩几个没有身份的数值。

| 内容 | 为什么需要 | 默认如何呈现；何时展开 |
| --- | --- | --- |
| 世界名称、文明名称与已知特征 | 认出这是哪一个世界，区别它和别处 | 开头给名称、文明特点与已有联系；星球/星系/宇宙层级可作说明。未获正式名称时用已知来源描述，不显示DOMAIN编号 |
| 从哪里得知这里 | 区别仅听到一则祈求与已经多次接触 | 保留首次接触或当前消息来源；仅有请求线索时只呈现其涉及的人和事，不自动展开全部机构和居民 |
| 文明怎样理解异常 | 同样的神迹在不同文明可能引发不同反应 | 用已获知的实际特点解释记录、仪式、记忆、契约等社会作用；与当次行为有关时再展开具体条件，不直接泄露整个蓝本规则表 |
| 屏障、污染、察觉、稳定 | 判断施力难易、自身影响、被发现的危险，以及组织是否还能维持 | 世界资料中显示已知档位；有精确信息才显示数值。每项有简短含义说明，保持四者区别。不是全部常驻主界面，也不是全部永久隐藏 |
| 此地的祈求、人物和教团 | 决定要影响谁，以及现有信徒状况 | 显示实际已知名字、教团人数/领袖/变化；点击直接查看或执行相应合法操作，保留当前世界 |
| 机构与圣物 | 理解具体组织、神迹材料和物件有什么用 | 使用具体组织/物件名称、已知作用和相关人物；罕见条件放其详情，不把锚点建设塞进每个世界的默认中心 |
| 已知通路 | 判断能否接触或转移到别处 | 列已知目的地和真实联系；没有距离规则就不画有地理距离含义的星图；有通路也不等于所有迁引都可执行 |
| 调查、追捕、清洗等已公布行动 | 看见具体威胁，决定承受或应对 | 显示谁在做什么、针对谁、还有多久、已预告的后果。已启动的调查不会因察觉下降而消失 |
| 近期发生的事 | 知道这个世界如何变化，认出此前行为的后果 | 显示该世界的近期消息，并可展开相关编年史；不另外制造一套相互矛盾的世界历史 |
| 情报的时间与可靠范围 | 区别当前可知状态与过时消息 | 对有时间依据的具体信息标最后获知回合/来源；不得给整个世界资料虚构一个统一更新时间 |

已核规则：system-civilizations.md §5要求初见获得范式线索和状态档位，主动探知后获得更精确情报。当前Session.project却将污染/察觉/稳定置空，只提供最后获知的屏障。因此这部分是设计与接口之间的缺口；旧稿将它概括为“有意一直隐藏”是错误判断。另一方面，某次污染增加2不等于玩家已经知道污染总量，公开本次综合成功率也不必同时公开所有后台修正。

### 除世界之外，必须评估的信息

这些是信息需求，不意味着每行都要开一个页面。字段只有与玩家知情范围相符时才显示。

| 玩家需要知道什么 | 放在哪里与出现时点 | 必须讲清的内容 |
| --- | --- | --- |
| 本轮还能做什么 | 主界面常驻 | 回合、剩余低语、信仰、是否已经回应；查看对象不扣费，未用低语不结转 |
| 谁在祈求、想要什么 | 祈求列表与选中后的全文 | 祈求者身份、相关人物/事物、诉求、浅触和深度干预的实际区别；不以救人为默认价值判断 |
| 请求和原危机还有多久 | 祈求及相关人物附近 | 请求到期和病危/追捕期限分开；失败消耗请求和回应机会，却不自动解除原危机 |
| 人物是谁、为何值得留意 | 祈求、目标选择和人物详情 | 姓名、身份、所在世界、机构/教团、与邪神的已知经历；知道邪神、信仰邪神、加入教团分别判断 |
| 人物现在是否可用 | 选择人物时立即可见 | 存活、受伤、拘禁、失踪、已执行任务、明确期限及本次不可用原因；不猜失踪者何时回来 |
| 人物已被怎样改变 | 人物详情长期保留，变化时进入消息 | 真实变异、先知身份、永久赐予、理智和能力变化及来源；不新增异化值，不把变异自动写成加战力或必死 |
| 人物适合做什么 | 选择具体权能时突出相关项 | 已知属性、忠诚、理智、职责与准备；非信徒的后台完整属性不因选中而泄露 |
| 权能的作用、开放与限制 | 权能入口简述，选中后详述 | 当前苏醒、费用、目标、冷却与具体缺项；曾经解锁不代表当前仍能用；聆听不是任意扫描 |
| 谁承受、谁执行、使用什么 | 当前回应或权能中选择 | 区分承受者、执行者、见证者和圣物；入梦不必另派一个执行者，各动作不套同一必填表 |
| 准备带来什么、还剩多久 | 与本次行动相关时显示 | 谕言、一次性情报、圣物的实际帮助、适用目标、到期时间及是否本次消耗 |
| 会花掉或永久失去什么 | 执行前与选项同屏 | 低语/信仰、材料、人物执行机会，以及死亡、销毁、失职/失去护持等直接后果；献祭不会只展示收益 |
| 会发生哪些结果 | 执行前可查完整结果；执行后当场给实际结果 | 随机行为有四个互斥概率与各档后果；确定性动作说明确定结果；始终代价和成功后代价分开 |
| 圣物在哪里、还能否使用 | 圣物详情和媒介选择 | 持有人、绑定、封存/扣押、次数、效果与代价；曾经见过不等于可控制；类型来历不能冒充实例往事 |
| 教团是否正常运作 | 教团摘要；异常时即时消息 | 领袖、具名信徒与无名信众、凝聚、策略、供奉、休眠/覆灭原因；任命现任和下轮生效分开 |
| 信仰够不够、何时收入 | 常驻余额；相关操作展开支出与收入 | 当前库存与预计收入分开；先付传教和锚点供奉再收收入；新团/新人当轮不重复产收入；接近容量时提示 |
| 苏醒为何变化 | 常驻总值，可直接展开 | 初生、洞见、有效锚点、创伤；变化列具体原因。当前值管权能，历史峰值管容量；洞见满后不伪称仍有收益 |
| 有没有快要失去联系 | 实际断联时明显显示 | 已连续断联多久、实际寂灭期限、哪些已知联系失效；不能把低语耗尽当断联，也不曝光未来随机祈求 |
| 哪些事情仍在进行 | 挂在相关人物/教团/世界上；临期提升 | 已公布调查、待生效任命、实际跨轮活动、持续降临；降临说明当轮是否续付和仍需维持的条件 |

| 保存与本局结局 | 游戏菜单、保存反馈、真实结局画面 | 保存成功/失败、将舍弃的未保存行为、真实结束原因；封存后只读，不因结局自动公开世界秘密 |

这里还包括两类容易漏掉的事实：人物改变必须在该人物身上留下可读痕迹；名额/机会不足必须说明被什么占用及何时释放。界面不使用F/N/P或后台身份总数代替解释。变异确有EVENT_01/B的实际记录，但当前人物投影没有完整的此类状态展示。

### 编年史：常驻最新消息，可以立即展开

用户提出“很小区域即时呈现最新事件并快速展开”作为参考。采纳方便触达、保持连续性的方向；区域尺寸、位置和显示条数仍由排版与阅读验证决定，不把参考表述当作已批准像素方案。

- 主界面保留可见的“编年史”最新消息区。正在选祈求、人物或权能时，消息仍可看见；新消息不抢走当前选择。
- 一条摘要写具体发生了什么、涉及谁；名字可点开对应人物/教团/世界。点击摘要展开这件事的完整内容、实际变化和已知前因；点击编年史展开全部记录。关闭后回到原操作。
- 行动结果仍在当前回应/权能中立即展示，并进入同一份记录。消息区不会代替必要的成败反馈；查看两处不是执行两次。
- 新祈求、教团成立、领袖死亡、人物变异、圣物易主、已知调查启动、苏醒变化等具有实际意义的事件应被看见。普通收入和同轮重复小变化可按来源合并，避免连续刷屏。
- 一次原因造成多项变化时先给易懂摘要，例如“领袖死亡，教团停止供奉”，展开再看该人物、教团及苏醒的实际变化。不能仅列三条互不相干的数值变化。
- 普通消息只提示；必须选择的事件遵守原事件阶段；即将到期的危险同时保留在相关人物/事项上，不因新消息挤掉而失踪。已读不等于已处理。
- 玩家正在读旧记录时不自动滚走；新到消息给可见提示。消息未在小区内完整展示不代表可丢失，完整记录始终能查。
- 按人物、世界、教团、回合查记录；对象详情可直接展开相关往事。只取玩家已知事实，未知前因不自动补齐。
- 本稿线框仅示意底部较小消息区；是否改为侧边、显示几条、如何展开仍可调整。没有固定消息条数或新“消息确认”机制。

可参考的公开实践：

1. [Civilization VI官方开发者介绍：Diplomacy Gets a Major Upgrade](https://store.steampowered.com/news/posts/?appids=289070%2C353370&enddate=1472565620)：外交消息随玩家获得的情报而来，支持把“能收到什么消息”纳入知情规则。本稿不据这篇2016年的说明宣称已审计当前版本所有通知布局。
2. [Weather Factory：Cultist Simulator — The Renewal of Skin](https://weatherfactory.biz/cultist-simulator-the-renewal-of-skin/)：2017年的开发记录明确强调情境窗口中新内容提示、可回看此前消息和文字可读性。借鉴的是让当前事情与前文保持联系，并非照搬其桌面或实时计时。

以上是对公开做法的借鉴。本作采用“常驻摘要→展开这件事→查完整往事”，并保留原回合阶段，是本轮设计判断。

### 界面关系：由功能决定展开方式

主界面承担正常祈求与权能操作。教团、人物、圣物、世界可直接打开；所选对象可就地进入相关权能，不强迫跳到抽象的“干预”分类。编年史有常驻摘要，展开后查询完整记录。

回应选择、权能选择、执行结果和有事件时的处理，是主界面的不同状态；不因此新增四个并列主菜单。菜单与结局各有其实际流程。图数用于覆盖必要页面和状态，不是需求指标；这次材料也不声称每个稀有权能的微布局已经完成。

鼠标/键盘都要保留当前对象、已选参数和返回位置。取消尚未执行的选择不扣费；已执行行为不能借关闭窗口撤销。不可逆行为用明确确认；对象失效时说明真实原因，不静默换目标。

### 跨阶段纸面走查与状态变化

以下按实际条件推演，用于检查同一套结构能否容纳不同阶段，不是要求玩家依次完成的攻略，也不是自然游玩证据。

| 情境 | 操作与信息应如何接续 | 必须承载的状态 |
| --- | --- | --- |
| 已有信徒，尚无教团 | 从人物或“尚无教团”说明查看该人的合法集会、祭仪等活动；执行时看实际费用、风险和人数变化，达到成立条件后依轮末规则形成教团 | 教团空状态显示合法组织者、无名追随者及缺少的实际条件；没有无条件创建按钮，具名信徒不冒充无名信众；成立消息可直接打开新教团 |
| 多个世界、多个教团，正在选择祈求回应 | 直接打开教团，按名称或世界查找；只修改需要改变的教团，其他安排沿用。查看相关人物后先返回原教团，再返回原祈求 | 列表保留筛选、选中项与滚动位置；可比较领袖、信众、指令、预计供奉及异常；同名人物加所在世界/教团区分。查看世界不自动取得关注，也不暂停其结算 |
| 自由行动中发现追捕即将在本轮末发生 | 在人物和请求附近查看已公布的目标、期限和后果，按当前合法回应或权能应对，或接受后果；读完消息返回原操作 | 请求到期与追捕到期分别显示；相关危险持续保留，结束回合时可就地提醒。本轮生成的事件候选不擅自变为即时弹窗，仍按原规则最早下一轮处理；察觉下降不自动取消既有追捕 |
| 已开始降临，进入需要续付的一轮 | 主界面直接看到进行中的降临，查看相关人物/教团，按当前规则继续或取消；第三轮续付展示并锁定最终概率，实际检定仍在轮末并核持续条件 | 下方苏醒摘要区域在此局势改为“降临”摘要，总苏醒仍在顶栏。摘要显示进行到第几轮、尚未/已经续付及失效条件，点开同一权能详情看低语/信仰/人物机会与具体依赖；尚未续付不等于已经中断 |
| 已连续断联两轮，历史中仍有认识的人 | 主界面给出实际断联计数与已知原因，相关人物说明旧记录是否仍代表有效联系；本轮确实恢复则轮末据实清零，否则按原三轮期限寂灭 | 主界面在祈求上方保留明显风险提示，区分断联与苏醒归零。结局指向最后失效的实际联系；不泄露未来随机祈求、不编造救援，本轮低语耗尽不算断联 |

共有状态约定：

- 没有祈求时明确显示“本轮暂无可回应的祈求”，合法权能和结束回合继续可用；已经回应则显示“本轮已回应”，不重复扣费或制造占位请求。
- 没有教团、没有已知圣物、筛选无结果分别说明，提供相应的合法入口或清除筛选；不统一写成“暂无数据”。
- 人物死亡、离开、拘禁或圣物失效等导致原选择不可用时，停止执行并说明实际原因，保留其他有效选择，不自动替换对象。资格不成立不收费、不抽随机结果。
- 费用、人数、资格或概率改变时旧预览失效，先刷新并让玩家重新执行；不能沿用过期预览。
- 长列表滚动与筛选不移动执行按钮；多处异常可在列表保留简短原因和到期回合，不能只藏在单个对象详情或消息流。长故事和结果可滚动/展开，费用与关键后果不能被截掉或靠缩小字号塞入。
- 连续查看人物、教团、世界时，返回按钮说明回到哪个具体对象或哪项操作；同一详情区替换内容并保留返回记录，不无限叠加窗口。
- 处理必须选择的事件时，可查相关对象和往事；自由行动入口遵守原阶段限制，不能借导航执行当时不合法的权能或跳过事件。
- 常驻消息区保持全局最新消息，打开世界或人物不悄悄将它过滤为该对象消息；对象自己的往事在详情或展开编年史时明确筛选。

这些是本稿应实现的结构合同。现有线框呈现代表状态，尚未画完每个空态、长列表和稀有行动的具体排版；文字覆盖不代替对应状态的实际可读性与输入验证。

# 既有最简功能界面的实施合同

以下描述既有功能界面；其规则接线可供新结构核查，布局、视觉参考和分批推广顺序不约束上文的新设计。

## 既有实现授权与规则适用

此前作者明确“前期不考虑美术风格，最简单最简单的可交互界面即可”，据此制作下述功能表达。旧批次使用过项目 in-game-ux 方法和 U1–U12 清单；它们不是本轮新结构的设计前提。

载体为邪神对时空与信徒的认知操作面，叙事上没有强制制造一台电脑。初期实际用 Godot 默认控件、文字与简单矩形卡项实现；它是功能表达，允许朴素工具感，不能被误写成最终美术验收通过。正式载体与视觉语言留待美术阶段确认。

暂不要求锁定两至三款视觉参考，也不以美术样板阻塞系统推进。交互研究候选可包含 Cultist Simulator 的对象关联、Into the Breach 的行动前后果表达、Slay the Spire 的代价与状态辨认；这些只是后续功能研究方向，不代表已研究画面或作者已选定参考风格。

## 屏幕流

新局或继续 → 轮初事件（可能没有） → 时空总览 → 选择祈求或权能 → 指定合法对象/媒介 → 阅读预览 → 执行 → 查看直接变化 → 调整教团策略与供奉 → 轮末预览 → 结束回合 → 新一轮。

任意时刻可查看已知人物、机构、圣物和历史，但打开信息不会推进时间、消耗低语或触发判定。无法行动时仍能查看原因、承受后果与结束回合。

打开方式：运行正式 Godot 工程进入主菜单，由“新局”或“继续”进入同一会话呈现。功能验证工具、制作工作台和调试夹具不是玩家入口。主菜单允许直接说明种子、保存、继续与文字大小；不显示不存在的音量功能。

## 最小表面

1. **全局栏**：当前回合、苏醒及其来源、信仰/容量、剩余低语、进行中的终局仪式或断联倒计时。
2. **时空列表与详情**：已知文明、屏障/污染/察觉/稳定的已知值、机构和锚点、重大抵抗的目标与到期。折叠只改变展示。
3. **行动区**：本轮祈求、可用权能、正在选择的目标。矩形条目即可；不要求拖拽或自由堆叠卡牌。先用点击选择、按钮执行保证完整键鼠路径。
4. **人物与物件详情**：属性、状态、任职、持有/绑定、重要关系和关联事实。圣物在哪、谁在护持必须直接可查。
5. **结果与历史**：一次结算的成本、骰子区间、结果、状态差量和后续线索；链接至来源事件。
6. **菜单与结局**：保存/继续、音量及文字设置入口、放弃本局、编年史回看、新局。实际音频和最终呈现后置，不能让空设置项假装已有功能。

## 信息优先级

P0：当前要处理的选择、可用行动、资源成本、重大不可逆后果、回合是否可结束。

P1：相关文明/人物/物件、成功率及四档概率、锚点供奉、为什么不能执行、正在倒计时的抵抗。

P2：公式分解、全部历史、被压缩的过去事实、深层文明情报。它们可展开，不让所有数据常驻抢占主要决策。

表名、数值、档位分开显示。未知是未知，不能显示假数字；数字以外再提供文字状态，不仅靠颜色表达。条件未满足时列实际缺口，不把“不合法”和“风险很高”混在一起。

## 画面占用与不遮挡区

固定 1280×720，屏幕空间挂 `GameRoot/Presentation/CanvasLayer/OverlayRoot`，等比缩放留边。功能层使用一个边缘全局栏、一个列表区、一个当前决策详情区及固定动作区；具体间距由 Art 最简 Theme 核对。本作没有实时战场与角色周围避让区，卡牌决策可占画面中心。

禁止覆盖当前目标、代价、四档分布和主要执行／退出动作；长文字仅在说明区域滚动，动作固定可达。二次确认出现时保留对象名和损失，不叠第二个可操作的背景层。对象详情／历史打开后返回原列表位置，不能让全屏历史或菜单吞掉未结事件。超过逻辑画布的物理窗口尺寸只做缩放，不增加响应式布局与新玩法槽位。

## 玩家已知投影与来源

Session 是呈现唯一数据入口（知情与当前入口规则通过下述共享纯查询复用）：输出脱离权威状态的已知对象、可见事实、候选与预览；控件不接收 `World.state`、规则参与者的 `StateView.participant` 或全档案。`StateView` 只限制规则读取规模，没有玩家保密语义，不能因其为只读就直接显示。

1. 开局只公开初始重点星球域的身份和机构职责。固定祈求／事件实际指名的人物与已公开的处境、我方已绑定成员、我方操作结果、已知域明确公开事实成为可查内容。关注不自动使所有居民、机构代表、私有事实或邻域属性公开。
2. 一个域存在通路，不等于已掌握另一域详情。后续发现必须来自实际已公开的异域线索／人物经历／圣物来源或已执行的探知，不靠遍历世界字典扩展列表。资格存在不等于资格内容已向玩家公开。
3. 屏障、污染、察觉、稳定分别投影；没有精确情报就显示“未掌握”。初见档位必须有正式映射来源，缺映射时不凭空分类。可展示规则返回的本次准确综合成功率，而不展开隐藏状态的数值与修正分解。
4. 知道结果不递归得知前因。未知前因仅显示“尚未知晓原因”，不得在标题、筛选、对象计数、错误消息、候选理由或内部字典中旁路泄漏。已知事实的内部授权／隐藏人物字段也不能整段 JSON 输出。失效历史保留，当前资格失效另显示。
5. Session 的已知账本随保存／继续恢复，不能因重开面板或重建控件扩大知情范围。历史分页只读已知事实索引，向前因导航仍逐项过滤；未知条目的总数和页数不公开。
6. 选择器仅列已知且满足该字段类型的真实 ID；普通玩家不输入 `source`、`qualification`、issuer 或任意 JSON。内部来源只由会话依据已存在规则结果选择，存在多个不同合法来源时给出可读来源供选择；不得用域初始事实冒充万能资格。

### 当前扎根依据的来源选择（TASK-ANCHOR-ROUTES）

沿现有“权能→目标机构→来源→预览”路径消费schema2当前anchor_basis，支持创建与修复选择，不增加新屏幕、布局、按键或通信界面。载体、三个具名结构参考和OverlayRoot沿本文件既有合同；正式打开仍通过原Godot Session，组件投影检查不能记作当前完整新局已打开。视觉规格部分由Art agent在后续视觉阶段补充。

来源必须对应该目标的真实当前依据；Session只有在必要人物、结构和材料已获合法知情时才提供该来源，不因basis存在自动授予其parents或未知参与者。失效历史可在原已知历史中保留，但不可作为当前合法来源。内部issuer、能力版本、carrier明细、未知材料ID/数量及未来路线缺口不直接交给控件。选择、打开预览、取消或刷新都不发行basis、不授知识、不扣费或抽签。

P0沿原当前来源、实际目标和费用；P1说明当前合法条件及可公开的失效原因；P2只展开玩家已经知道的材料与因果。来源标签和数字继续分开展示。单一合法来源沿原选择习惯，不添加无收益的二次抉择；多个来源只能对应机制中确有不同依托的分支。来源在提交前失效时保留所选对象并说明缺口，重新核验，不静默换路或免费修复。

本项的结构检查为U1/U5/U6/U7/U8/U9/U12：沿既有载体/术语/层级/键鼠状态，投影不扩大知情、预览无写入、代价与规则一致。无新视觉或真人验收声明；实际材料转交由对应任务独立核验，完整Session启动及各路线到active仍分别由原后继任务交付。

### 集成缺口登记与完成判据

TASK-UI 开始时静态核查发现：`Powers._proof` 要求的 `power_qualification`（listen、dream、weakness、spread、evidence、tenure、witness、milestone）只有消费／验证，既有专项由 `cult-fixture` 注入；整轮敛息缺少正式 Turn 操作入口。本次集成已接入规则侧 `PlayerSources` 的版本化发行者、安装及 `available` 查询，类别由 `data/player_source_rules.csv` 管理；Session 只列原事实已知的实际资格。敛息已接入上述正式 rest 事务。这里记录的是接口接入，实际分支与可达性仍须运行验证，不能以灰按钮即“可完整操作”结案。

资格补齐必须在所属规则侧依据真实已发生事实生成，并列明 issuer/version、对象和前因，沿原消费与失效合同。背景墙接触必须识别原 BG_ESCAPE 固定卡，不能要求其具有不存在的 barrier_contact 字段；传播证据的真实派生收益从当前依赖事实／索引取出，不能要求原 prayer_fact 具有从未声明的 benefits／cult 字段。实现须满足权能 spec 的来源映射及即时重查合同。经济传教已有 Events 真实传播授权生产者，献身已有 PRAYER08 生产者，不把它们误判为全部缺失。

## 预览与输入约定

- 最低实现是选择卡项、选择目标、查看预览、执行四步。可点击与键盘焦点一致；悬停不是唯一信息入口。
- 执行前显示低语、信仰、媒介/人物消耗、成功率分段、始终代价与可能额外后果。献祭、物件分解、放弃本局等不可逆动作使用明确二次确认。
- 取消只退出当前预览，保留列表滚动位置和当前对象。资源未支付、随机序列未推进。
- 一次执行提交后临时阻止重复输入；结算完成才恢复，避免双击重复扣费。动画不控制结算时点。
- 结束回合前展示教团收入、计划供奉和不足项。不得静默挑选玩家放弃哪一个锚点；可明确确认全部或逐个改变选择。
- 新触发的事件不会在玩家选目标过程中插入改变对象；对象已因前一行动失效时重新校验并清楚说明。
- 提供继续、手动保存与轮次安全点自动保存；保存语义及跨版本限制服从架构与进度规则。

### 四档与结果表达

综合概率 P 必须来自同次纯预览；由正式 `check_critical_divisor` 得到深成上界 `d=floor(P/divisor)`、灾变点数 `c=ceil((100-P)/divisor)`。显示四条独立结果：深成 1…d，概率 d%；成功 d+1…P，概率 (P-d)%；失败 P+1…100-c，概率 (100-c-P)%；灾变 101-c…100，概率 c%。它们覆盖 1…100，无重叠与遗漏，零长度显示 0%／无区间。现参数 divisor=5，P=60 时分别为 12%、48%、32%、8%，不能把包含深成的60%再次当“成功”一档。

确定性事件、聆听和任命显示“确定结算／不投骰”，不伪造100%四档。降临前两轮显示已付和本轮持续条件；第三轮继续预览显示准确四档，提交后标“概率已锁定；轮末仍可能因主体、锚点、苏醒或供奉失效中断”。结果依次显示真实支付、骰点与所属区间、所得／损伤和已发生来源；无终极骰时不显示占位骰点。

### 二次确认、取消和焦点

- 献祭、永久解离／销毁、主动解绑的失锚、自弃、覆盖现有保存槽和放弃未保存当前局使用同一确认层：明确对象、永久损失、当前所选收益和“返回”。默认焦点在返回，打开确认的同一 Enter／Space 必须先释放，不能穿透执行。普通祈求／权能的预览已为执行前阅读，不再无差别增加第二弹窗。
- Tab／Shift+Tab 遍历，方向键浏览同级条目，Enter／Space 激活，Esc 先取消确认／预览，再关闭详情，最后开菜单；菜单中 Esc 返回。不能把同一 Esc 同时触发多层。输入控件编辑时按键由控件处理，种子输入不触发全局动作。
- 鼠标和键盘共享唯一 selected ID。悬停不改变选择，不重建列表；键盘移动才将当前项滚入视野。点击后更新详情与动作，不将列表强制滚回顶部。
- 取消预览不产生请求、不消费准备、不推进随机流，保留对象与每个滚动区位置。提交后锁定本次请求直至结果，稳定请求 ID 支持重读，自动重复键／双击不能生成第二次扣费。失败结果仍恢复可操作状态和清楚的当前缺口。
- 已选对象失效时保留其原身份及失效原因；执行关闭并提供返回或重新选择，不静默换一个人。正常页面刷新／字体更改后焦点回到同一稳定 ID；条目消失才移到最近合法项，动作结果返回原列表位置。

### 长内容、文字大小与存档反馈

- 列表和详情分开滚动，动作与退出在独立固定区；历史用实际索引分页，换页才重置该页滚动。页游标过期就提示资料已变化并重取，不能把旧游标接到另一对象。长标题、完整中文段落及多前因不得靠截断隐藏必要代价。
- 文字大小为当前界面的可用设置，至少提供标准与放大两个明确档；只改变 Theme／Control 最小尺寸和换行，不修改世界、候选数或随机序列。逻辑分辨率仍固定。放大时列表可少见几行，详情增加滚动，主要执行和退出不得被挤出。具体字号与字体 fallback 归 Art 共享 Theme，必须用中文真内容检查，不用缺字方框冒充可读。
- 保存中阻止重复存取，完成后明确显示已保存的回合／阶段；失败说明可操作原因，原会话继续有效。读入坏档／版本不兼容不替换当前局。轮末自动保存只在成功安全点发生；结束档仍保留，新局不静默覆盖其回顾。
- 初次打开不自动执行默认事件、不选不可逆动作。没有祈求、没有圣物、资源为零都有可读空态；仍可看历史、改合法计划、承受默认或结束回合。
