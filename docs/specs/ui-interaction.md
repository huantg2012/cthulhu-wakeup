# 全局信息架构与表现层规划（2026-11-01）

依据：制作人本轮指令，[DEC-027](../progress/decisions-log.md#dec-027--全局信息架构优先与邪神角色立场)与后续接受专业评审的开工授权（DEC-028）。本节优先于本文旧的最简界面布局与推广顺序。现有支付、资格、知情、输入和结算规则继续由各自系统负责。frontmatter 的 implemented 状态仅指旧功能界面；新结构由 `TASK-UI-STRUCTURE` 承接，当前 in-progress，以下结构稿供审阅，尚未获得人类理解/操作验证。

## 1. 已确定的输入与推导边界

**制作人明确要求：**

- 本作系统复杂且仍将增长。先由游戏流程、系统规则和数据建立全局信息清单、层级与关系，再决定场景划分、布局和交互；不以单个祈求样板推定全局架构。
- 默认注意力以祈求处理、权能行使为中心；中后期增加教团管理。事件低频但处理优先级高；整体进度和域状态重要，通常承担辅助判断。
- 玩家角色是邪神，疯狂与混乱是持续主题；凡人与教团在角色立场上渺小、可利用，可能因其特殊性而有趣。不把保护凡人、同情祈求人设为默认动机。
- 近期交付应能表达全游戏场景和界面结构，可玩样板、风格选择及正式视觉制作后置。
- 自行从已定玩法推导设计，不逐项索取确认。所有关键输入、判断及变更持续留档；专业化转述，不将口语比喻自动扩成机制或设计规范。
- 本轮不使用旧美术文档、skill 或 agent 中的视觉经验作为新结构的前提。既有界面只用于后续核查当前功能入口，不作为目标设计。

**本轮专业推导（设计判断，非制作人逐项裁决）：**

1. 使用频率、后果重要性、紧迫性和当前行动关联度分别判断。高优先事件应在合法处理时点优先呈现；不能据此让每个事件随时打断选择。域状态或进度触及当下资格、期限或存亡时，应从辅助信息提升为当前决策信息。
2. 人物的辨识度服务于能力、稀缺资格、关系、可利用性和行为后果；冷漠立场不消除身份连续性，也不强迫现实玩家只能产生一种情绪。疯狂与混乱不推出随机按钮、模糊费用或不可读的布局。
3. 数据存在、玩家知晓、当前决策需要，是三道不同筛选。内部标识、证明字段、后台候选和隐藏关系不因对设计者可读就获得玩家展示资格。
4. 场景指玩家的稳定活动空间与操作上下文，不预设为独立引擎场景、地图或每个系统一页。先确定必须同时看见、比较和操作的信息，再决定何时换场景、展开详情或暂时覆盖。
5. 全局先行要求覆盖当前已设计的全生命周期、主要跨系统关系和信息规模；不要求穷尽未来内容。给对象、关系和操作模式留下扩展方式，不为未知系统预造入口。
6. 风格、材质、插画、配色和装饰后置；信息密度、阅读顺序、比较距离、操作可达性须在结构线框中验证。可用结构材料修订架构，不把首次纸面设计永久冻结。

这里的“注意力”指玩家认知资源；游戏机制中的 F/N/P 容量、关注或低语另按原规则，不能相互替换。

## 2. 信息架构的分析坐标

同时分析三条时间轴：**整局发展阶段 × 回合阶段 × 单次操作状态**。前中后期按已存在的能力与管理规模区分，不擅自规定第几回合进入某期。跨域与扩张可以与其他阶段并存。

下表是已读规则支持的初步覆盖框架，不是完整信息清单或已定页面：

| 局势/阶段 | 主要决策与必要信息 | 关联/辅助信息 | 必须覆盖的变化 |
| --- | --- | --- | --- |
| 新局与继续 | 已知世界、可接触对象、当前预算、合法行动；继续时恢复未结事项 | 已有进度、原局身份与近期变化 | 未知信息不全知展开；继续不重置上下文语义 |
| 建立现实联系 | 祈求比较、浅/深回应、权能目标、成本、资格、期限 | 相关人物/机构、已知域状态、现有联系与来源 | 无教团、资源不足、对象失效、回应机会已用 |
| 教团形成与经营 | 人员/职责、策略、实际可用预算、供奉次序和缺口 | 成员资格、圣物、锚点依赖、暴露与收益 | 新团尚无收入、任命待生效、多人/多团比较 |
| 跨域发展 | 不同域的行动机会、关键依托、可分配主体/媒介和容量 | 通路、已知文明差异、后台变化摘要 | 查询/切换与实际关注操作区分；后台仍演化 |
| 反制与局部危机 | 受威胁对象、后果、剩余期限、当前可行处置 | 受影响的锚点、人物、资源和进度 | 多项风险同时存在；原计划失效或暂失能力 |
| 持续降临与临近终局 | 当前持续条件、已付与待付、机会/主体占用、中断风险 | 有效锚点、苏醒来源、信仰和断联情况 | 持续条件失去；高阶能力回退；结局优先级 |
| 结局与回顾 | 结局原因、关键已知后果、本局回顾、新局/退出 | 对象关联与已知历史 | 只读封存，不把回顾当新行动或补发隐藏知识 |

每行还须横向穿过轮初整理、事件处理、自由行动、计划锁定/演化、收入/期限、终局判断；并检查浏览、选择、预览、执行、结果、取消/返回等操作状态。系统结算阶段不自动等于独立画面。

## 3. 工作顺序与交付物

### A. 全局决策与信息盘点：先回答玩家如何形成和修订计划

先由五个机制 spec 建立目标、可选行动/暂缓、共同机会成本、持续后果和改计划条件，再以正式 CSV 与当前公开接口核信息。建立“阶段—决策—信息—对象—来源”矩阵。规则定义、实际实现、当前玩家可得信息分开登记；数据装载状态、旧文矛盾或接口缺口标明，不用界面文案补造能力。A/B/C 双向修订，不以全字段审计结束作为第一张结构图的前置。

信息条目至少记录：稳定条目 ID、玩家问题/决策、所属对象及关系、机制/数据来源、出现阶段、知情条件及精确程度、时效/更新触发、默认阅读层级、关联操作、需要共同查看的信息、空/多/失效状态。对不应展示的内部数据说明排除理由，不逐字段照搬数据库。

产物：**全阶段信息矩阵 + 对象/依赖关系图 + 明确缺口表**。关系区分归属、控制/持有、行动资格、资源依赖、因果、知情与时限；有关系不等于玩家已知，有依赖不等于需要画整张网络图。

### B. 场景与导航：由信息和任务确定空间

在 A 的覆盖基础上，划分稳定活动空间、主次任务、共享上下文和进入/返回路径。逐一判断哪些内容常驻、随选择更新、按需展开或仅在特定时点出现；跨系统比较与操作链优先于按代码模块分菜单。

产物：**全局场景/导航图 + 每个场景的信息职责表**。必须能沿祈求、权能、经营、危机、轮末与终局完整走查；人物/圣物/机构/历史的关联查询要能返回原任务。此时不预定左栏、右栏、卡牌桌或地图布局。

### C. 全局结构线框与交互合同：让结构可以审阅

为 B 的所有主要场景提供低保真结构线框，并以早期低规模、中后期高规模、危机并发等内容实例检查。线框标明信息区域、阅读顺序、主要动作、关联详情和覆盖层；共用结构可复用，但须展示各阶段实际承载差异。

同时规定选择/比较、目标与媒介选择、展开/返回、事件处理时点、轮末预览、临界提示、结果阅读、不可用解释、保存继续的上下文恢复。键盘/鼠标及选中/焦点模型在此阶段定义；不把拖拽预定为必要输入。

产物：**全场景结构线框组 + 关键操作流程图 + 显示/切换/返回规则**。材料使用一致的编号互相引用，优先汇集在本文；必要的导出图是本文的派生产物，不另建第二套有效 UI spec。当前不接运行时、不制作可玩样板。

### D. 全局走查与交接：覆盖成立后再进入实现和视觉

以信息矩阵逐项反查场景和操作路径：每项玩家任务有入口/后果/返回；每项必要信息有可达位置和来源；同一资源、人物、圣物和期限在不同表面语义一致。用少量有代表性的纸面情境查空/满、未知、失效、多域、多团、多个到期事项以及持续仪式，不跑全组合游戏模拟。

产物：**覆盖对照表 + 结构问题清单 + 实现/视觉交接边界**。结构审阅证明信息可承载和流程可推演，不冒充实际操作、性能、审美或乐趣通过。之后可分批实现与验证，但不再由一个局部样板倒推整局架构。

## 全局结构稿：先形成意图，再选择干预

2026-11-01 · `TASK-UI-STRUCTURE` · 首稿。以下“结构判断”为本轮设计提案；系统事实来自列出的规则与数据；源码状态只经只读核对，未启动游戏。制作人已认可的是方法和开工，不代表逐页布局已获认可。

### 设计判断与玩家的世界模型

玩家理解的是**自己已知的现实联系、能够动用的媒介，以及正在累积或流失的立足点**。时空域是局势背景；人物、教团、圣物和机构是作用对象；祈求/事件提供机会和压力；权能与主动活动允许玩家选择自己的干预方向。

由此选择三个并列的主要活动空间：**干预、经营、诸域**。它们共享同一局势与对象上下文，不是三个互相隔绝的功能模块。干预默认进入，经营承担跨团配置，诸域用于寻找目标与查明依赖；编年史按需要进入。这个选择来自操作与比较需求，不由后台模块数量决定。

- 采用“已知域—现实依托”的世界表征，不绘制带距离/地理位置暗示的宇宙地图；当前规则没有这些可操作的空间量。域间连线只表示已知通路，其他边须标明归属、绑定或已知因果，不能混成一种线。
- 干预同时支持“看见祈求→判断价值”和“选择已知对象/权能→查看合法行动”。主动促成进展是既有能力入口，不另造任务系统、最优行动推荐或十八个常驻新按钮。
- 关注一个对象的详情、切换页面和比较域都只读。游戏里的关注 F 是明确的有容量约束的操作，绝不由浏览动作暗中取得。
- 不新增自动执行队列、资金冻结、跨轮预约或自定义任务奖励。本稿的“计划”仅指原规则允许修改的经营/供奉计划；已执行的行为和持续工程另列。
- 稳定事实保持低干扰；必须处理、即将到期、已失效和与当前选择直接相关的信息提升。提升指显示解释与入口，不意味着自动换页或抢走选中对象。
- 凡人的身份可辨认，表达其用途、欲望与后果；不把救助、仁慈或关怀评分作为通用评价。未知仍未知，混乱主题不掩盖操作规则。

### 时间、知情和显示规则

| 语义 | 应如何表达 | 禁止的混淆 |
| --- | --- | --- |
| T0 当前事实 | 当前资源/资格；最近获知的信息附获知回合与来源 | 旧情报冒实时值，未知冒0 |

### 层级与共同交互

- L0：固定游玩壳提供回合/阶段、信仰/低语/回应、苏醒摘要、主要活动入口、会话菜单与当前阶段合法的结束回合。临界断联/持续降临出现时明确提升，不永久占据中心。
- L1：当前活动空间承担一个主要比较/决策；S1中同时可进入祈求与主动权能，二者使用同一动作预览。
- L2：关联对象详情在当前任务旁展开，保持选中对象和比较依据。只保留一层可交互详情；查看更深历史时带返回路径，不堆无限窗口。数字说明与概念解释可按需展开，键盘可访问。
- L3：提交前的行动预览固定展示所选对象、真正成本、互斥结果/确定性、永久损失、确定的预算变化及已知依赖。预览只读；修改选择后重新预览，不继承旧资格。
- L4：仅对原规则指定的不可逆/覆盖/放弃动作增加确认，默认返回。释放进入确认的同一按键后才能执行；不把普通祈求全都加第二层确认。
- 鼠标/键盘共享稳定选中ID；悬停不改选择；Esc先退出当前子层，最后才开菜单。当前对象失效保留身份与原因，禁止自动换人。正式提交防重复，失败后恢复操作；显示动画不决定结算时点。
- 结果分为“本次付出→实际结算→直接变化→尚待兑现”。已知相关后果可关联查询；只对当前已公开的真实待办提示，不推演全知未来。
- 大规模经营提供同类可比的摘要列和已知缺口筛选；不能把每团全部资料常驻。列表折叠/筛选不会停止后台演化。摘要优先变化与风险，但稳定资产始终可达。

此前作者明确“前期不考虑美术风格，最简单最简单的可交互界面即可”，据此制作下述功能表达。旧批次使用过项目 in-game-ux 方法和 U1–U12 清单；它们不是本轮新结构的设计前提。

载体为邪神对时空与信徒的认知操作面，叙事上没有强制制造一台电脑。初期实际用 Godot 默认控件、文字与简单矩形卡项实现；它是功能表达，允许朴素工具感，不能被误写成最终美术验收通过。正式载体与视觉语言留待美术阶段确认。

暂不要求锁定两至三款视觉参考，也不以美术样板阻塞系统推进。交互研究候选可包含 Cultist Simulator 的对象关联、Into the Breach 的行动前后果表达、Slay the Spire 的代价与状态辨认；这些只是后续功能研究方向，不代表已研究画面或作者已选定参考风格。

## 屏幕流

新局或继续 → 轮初事件（可能没有） → 时空总览 → 选择祈求或权能 → 指定合法对象/媒介 → 阅读预览 → 执行 → 查看直接变化 → 调整教团策略与供奉 → 轮末预览 → 结束回合 → 新一轮。

任意时刻可查看已知人物、机构、圣物和历史，但打开信息不会推进时间、消耗低语或触发判定。无法行动时仍能查看原因、承受后果与结束回合。

打开方式：运行正式 Godot 工程进入主菜单，由“新局”或“继续”进入同一会话呈现。功能验证工具、制作工作台和调试夹具不是玩家入口。主菜单允许直接说明种子、保存、继续与文字大小；不显示不存在的音量功能。

## TASK-UI 分批执行合同

每批完成自己的规则连接和输入检查后再接下一批，共享 Session／Theme 可以先铺设。批次不是新增玩法；完整操作范围不能以“有按钮”或静态展示替代。全部表面通过前不把 TASK-UI 标为完整交付。

| 批次 | 最小表面与可观察操作 | 依赖与边界 |
| --- | --- | --- |
| B1 会话与回合 | 新局、继续；零至两张事件及其 A/B／默认；本轮祈求浅触／深干预；轮末预览、推进、结果；保存；只读结局与重开 | 使用正式混合世界和全部规则模块；无资源仍能承受默认并推进；不能调用测试初始化 |
| B2 权能与圣物 | 从已知对象进入权能，逐项选择真实主体／媒介／资格；预览与执行；圣物携带、收回、解绑、解离；机构遗物机会；降临开始／继续／中断 | 十二权能加持续状态均有入口；无资格显示真实缺口；世界抵抗的扣押／封存／销毁不是玩家任意权能 |
| B3 经营与注意力 | 教团成员／任职；传教、敛藏、守持；供奉次序及拒付；敛息；关注及释放、持续工程占用、成员申请／离团 | 入团必须有献身与容量，离团必须有真实授权；释放工程不能消除已经承诺的后果；敛息由规则结算 |
| B4 对象、历史与输入复核 | 已知文明／机构／人物／圣物／锚点；分页编年史和已知前因；长列表、长说明、文字缩放、全部键鼠路径和覆盖确认 | 页面折叠不改变模拟；不扫描并展示全知世界；结局历史沿原局身份只读 |

B1 的主菜单、全局读数和唯一决策详情为其余批次复用骨架，B2/B3 不再各造一套确认或结果页。只有当前批次的直接字段和必要详情进入 Code 上下文，不能一次把所有表面作为一个执行单元。

## 最小表面

1. **全局栏**：当前回合、苏醒及其来源、信仰/容量、剩余低语、进行中的终局仪式或断联倒计时。
2. **时空列表与详情**：已知文明、屏障/污染/察觉/稳定的已知值、机构和锚点、重大抵抗的目标与到期。折叠只改变展示。
3. **行动区**：本轮祈求、可用权能、正在选择的目标。矩形条目即可；不要求拖拽或自由堆叠卡牌。先用点击选择、按钮执行保证完整键鼠路径。
4. **人物与物件详情**：属性、状态、任职、持有/绑定、重要关系和关联事实。圣物在哪、谁在护持必须直接可查。
5. **结果与历史**：一次结算的成本、骰子区间、结果、状态差量和后续线索；链接至来源事件。
6. **菜单与结局**：保存/继续、音量及文字设置入口、放弃本局、编年史回看、新局。实际音频和最终呈现后置，不能让空设置项假装已有功能。

## 信息优先级

P0：当前要处理的选择、可用行动、资源成本、重大不可逆后果、回合是否可结束。

P1：相关文明/人物/物件、成功率及四档概率、锚点供奉、为什么不能执行、正在倒计时的抵抗。

P2：公式分解、全部历史、被压缩的过去事实、深层文明情报。它们可展开，不让所有数据常驻抢占主要决策。

表名、数值、档位分开显示。未知是未知，不能显示假数字；数字以外再提供文字状态，不仅靠颜色表达。条件未满足时列实际缺口，不把“不合法”和“风险很高”混在一起。

| 表面 | P0 当前决策 | P1 相关上下文 | P2 主动展开 |
| --- | --- | --- | --- |
| 全局 | 回合／阶段、信仰／容量、低语、苏醒、结束回合入口 | 断联计数及上限、仪式轮次与待续／已付、已知抵抗到期 | 苏醒四项来源、容量来源 |
| 事件／祈求 | 当前诉求、固定对象、期限、当前选项、费用与主要不可逆后果 | 原危机期限与请求期限分别列；四档风险或确定性；缺口 | 真实来源及已知前因、准备分解 |
| 权能／圣物 | 行动名、主体、目标、选中媒介、实际费用、执行／返回 | 可选资格、执行机会、冷却、必失物件与锚点影响 | 精确规则说明、已知效果明细 |
| 经营 | 当前教团策略、供奉次序／拒付、预计先付余额 | 本轮信众资格、有效／休眠原因、预计收入与风险 | 条件性收入公式、来源 |
| 历史／结局 | 实际所得／损失、结果或结局原因、原人物身份 | 支付／检定／差量分开，已知相关事实 | 已知因果分页、种子与本局回顾 |

## 画面占用与不遮挡区

固定 1280×720，屏幕空间挂 `GameRoot/Presentation/CanvasLayer/OverlayRoot`，等比缩放留边。功能层使用一个边缘全局栏、一个列表区、一个当前决策详情区及固定动作区；具体间距由 Art 最简 Theme 核对。本作没有实时战场与角色周围避让区，卡牌决策可占画面中心。

禁止覆盖当前目标、代价、四档分布和主要执行／退出动作；长文字仅在说明区域滚动，动作固定可达。二次确认出现时保留对象名和损失，不叠第二个可操作的背景层。对象详情／历史打开后返回原列表位置，不能让全屏历史或菜单吞掉未结事件。超过逻辑画布的物理窗口尺寸只做缩放，不增加响应式布局与新玩法槽位。

## 玩家已知投影与来源

Session 是呈现唯一数据入口（知情与当前入口规则通过下述共享纯查询复用）：输出脱离权威状态的已知对象、可见事实、候选与预览；控件不接收 `World.state`、规则参与者的 `StateView.participant` 或全档案。`StateView` 只限制规则读取规模，没有玩家保密语义，不能因其为只读就直接显示。

1. 开局只公开初始重点星球域的身份和机构职责。固定祈求／事件实际指名的人物与已公开的处境、我方已绑定成员、我方操作结果、已知域明确公开事实成为可查内容。关注不自动使所有居民、机构代表、私有事实或邻域属性公开。
2. 一个域存在通路，不等于已掌握另一域详情。后续发现必须来自实际已公开的异域线索／人物经历／圣物来源或已执行的探知，不靠遍历世界字典扩展列表。资格存在不等于资格内容已向玩家公开。
3. 屏障、污染、察觉、稳定分别投影；没有精确情报就显示“未掌握”。初见档位必须有正式映射来源，缺映射时不凭空分类。可展示规则返回的本次准确综合成功率，而不展开隐藏状态的数值与修正分解。
4. 知道结果不递归得知前因。未知前因仅显示“尚未知晓原因”，不得在标题、筛选、对象计数、错误消息、候选理由或内部字典中旁路泄漏。已知事实的内部授权／隐藏人物字段也不能整段 JSON 输出。失效历史保留，当前资格失效另显示。
5. Session 的已知账本随保存／继续恢复，不能因重开面板或重建控件扩大知情范围。历史分页只读已知事实索引，向前因导航仍逐项过滤；未知条目的总数和页数不公开。
6. 选择器仅列已知且满足该字段类型的真实 ID；普通玩家不输入 `source`、`qualification`、issuer 或任意 JSON。内部来源只由会话依据已存在规则结果选择，存在多个不同合法来源时给出可读来源供选择；不得用域初始事实冒充万能资格。

### 当前扎根依据的来源选择（TASK-ANCHOR-ROUTES）

沿现有“权能→目标机构→来源→预览”路径消费schema2当前anchor_basis，支持创建与修复选择，不增加新屏幕、布局、按键或通信界面。载体、三个具名结构参考和OverlayRoot沿本文件既有合同；正式打开仍通过原Godot Session，组件投影检查不能记作当前完整新局已打开。视觉规格部分由Art agent在后续视觉阶段补充。

来源必须对应该目标的真实当前依据；Session只有在必要人物、结构和材料已获合法知情时才提供该来源，不因basis存在自动授予其parents或未知参与者。失效历史可在原已知历史中保留，但不可作为当前合法来源。内部issuer、能力版本、carrier明细、未知材料ID/数量及未来路线缺口不直接交给控件。选择、打开预览、取消或刷新都不发行basis、不授知识、不扣费或抽签。

P0沿原当前来源、实际目标和费用；P1说明当前合法条件及可公开的失效原因；P2只展开玩家已经知道的材料与因果。来源标签和数字继续分开展示。单一合法来源沿原选择习惯，不添加无收益的二次抉择；多个来源只能对应机制中确有不同依托的分支。来源在提交前失效时保留所选对象并说明缺口，重新核验，不静默换路或免费修复。

本项的结构检查为U1/U5/U6/U7/U8/U9/U12：沿既有载体/术语/层级/键鼠状态，投影不扩大知情、预览无写入、代价与规则一致。无新视觉或真人验收声明；实际材料转交由对应任务独立核验，完整Session启动及各路线到active仍分别由原后继任务交付。

## 实际规则入口与字段责任

### 两类祈求的最小知情交接（TASK-PRAYER-INTEGRATION）

已固定但未到原可见轮的请求不授线索；实际展示后只公开本请求的指定域、求告人、方向、诉求与原窗口/危机期限。域和人物线索不升级其完整档案，不能揭示文明蓝本、层级、机构网络、人物范式/隶属/能力或私有知情；既有完整知识保留。线索域可进入原显式关注选项，关注仍由原准入核F；请求本身不授F。原深应准入在F空位足够时也可随实际行动取得关注，不能把当前未重点误写成必然拒绝；纯预览不授F。

实际作用对象按原类型给有限身份线索：01亲属、02对手、03追查者、04实际第二见证者、06契约另一方、07按原顺序的记忆对象、10争端另一方、11原圣物实例、12实际其他接收机构。05/08/09无额外对象线索。不得按actors或facts无条件展开。PR11的扣押机构和PR10待揭示关系仍是回应收益，回应前隐藏；这里的有限机构/圣物线索也不授完整结构或物件档案。

PR08标题和求告文字读取本次addressing对应的现行CSV行；身份已知也可无向，不能用目录标题代替方向。公开数据隐藏内部call、knowledge、record_knowledge、admission_token及采样/授权依据，涵盖嵌套事件请求、选择器、预览、结果、幂等缓存、历史和局部续存重建。终局内部未来联系预测不向玩家公布，不能通过断联评估记录提前揭示未可见请求。成功接纳成员可公开成员自身资料，不顺带公开其整域。

Session外壳schema2区分本版知情粒度；该INTEGRATION原批次未以跳模块或放宽来源解除当时CULT启动保护。当前启动由TASK-CULT-SPREAD另给正式模块运行证据，完整会话恢复仍由TASK-CULT-SAVE-COMPAT验收。实际检查和明确夹具边界另见本项报告，不能据规则文本宣称完整Session或自然新局通过。本批只修已有数据交接，载体、布局、样式、输入节点保持原合同；U1–U12未变化部分不因此新增美术或人工通过声明。

## 预览与输入约定

- 最低实现是选择卡项、选择目标、查看预览、执行四步。可点击与键盘焦点一致；悬停不是唯一信息入口。
- 执行前显示低语、信仰、媒介/人物消耗、成功率分段、始终代价与可能额外后果。献祭、物件分解、放弃本局等不可逆动作使用明确二次确认。
- 取消只退出当前预览，保留列表滚动位置和当前对象。资源未支付、随机序列未推进。
- 一次执行提交后临时阻止重复输入；结算完成才恢复，避免双击重复扣费。动画不控制结算时点。
- 结束回合前展示教团收入、计划供奉和不足项。不得静默挑选玩家放弃哪一个锚点；可明确确认全部或逐个改变选择。
- 新触发的事件不会在玩家选目标过程中插入改变对象；对象已因前一行动失效时重新校验并清楚说明。
- 提供继续、手动保存与轮次安全点自动保存；保存语义及跨版本限制服从架构与进度规则。

### 四档与结果表达

综合概率 P 必须来自同次纯预览；由正式 `check_critical_divisor` 得到深成上界 `d=floor(P/divisor)`、灾变点数 `c=ceil((100-P)/divisor)`。显示四条独立结果：深成 1…d，概率 d%；成功 d+1…P，概率 (P-d)%；失败 P+1…100-c，概率 (100-c-P)%；灾变 101-c…100，概率 c%。它们覆盖 1…100，无重叠与遗漏，零长度显示 0%／无区间。现参数 divisor=5，P=60 时分别为 12%、48%、32%、8%，不能把包含深成的60%再次当“成功”一档。

确定性事件、聆听和任命显示“确定结算／不投骰”，不伪造100%四档。降临前两轮显示已付和本轮持续条件；第三轮继续预览显示准确四档，提交后标“概率已锁定；轮末仍可能因主体、锚点、苏醒或供奉失效中断”。结果依次显示真实支付、骰点与所属区间、所得／损伤和已发生来源；无终极骰时不显示占位骰点。

### 二次确认、取消和焦点

- 献祭、永久解离／销毁、主动解绑的失锚、自弃、覆盖现有保存槽和放弃未保存当前局使用同一确认层：明确对象、永久损失、当前所选收益和“返回”。默认焦点在返回，打开确认的同一 Enter／Space 必须先释放，不能穿透执行。普通祈求／权能的预览已为执行前阅读，不再无差别增加第二弹窗。
- Tab／Shift+Tab 遍历，方向键浏览同级条目，Enter／Space 激活，Esc 先取消确认／预览，再关闭详情，最后开菜单；菜单中 Esc 返回。不能把同一 Esc 同时触发多层。输入控件编辑时按键由控件处理，种子输入不触发全局动作。
- 鼠标和键盘共享唯一 selected ID。悬停不改变选择，不重建列表；键盘移动才将当前项滚入视野。点击后更新详情与动作，不将列表强制滚回顶部。
- 取消预览不产生请求、不消费准备、不推进随机流，保留对象与每个滚动区位置。提交后锁定本次请求直至结果，稳定请求 ID 支持重读，自动重复键／双击不能生成第二次扣费。失败结果仍恢复可操作状态和清楚的当前缺口。
- 已选对象失效时保留其原身份及失效原因；执行关闭并提供返回或重新选择，不静默换一个人。正常页面刷新／字体更改后焦点回到同一稳定 ID；条目消失才移到最近合法项，动作结果返回原列表位置。

### 长内容、文字大小与存档反馈

- 列表和详情分开滚动，动作与退出在独立固定区；历史用实际索引分页，换页才重置该页滚动。页游标过期就提示资料已变化并重取，不能把旧游标接到另一对象。长标题、完整中文段落及多前因不得靠截断隐藏必要代价。
- 文字大小为当前界面的可用设置，至少提供标准与放大两个明确档；只改变 Theme／Control 最小尺寸和换行，不修改世界、候选数或随机序列。逻辑分辨率仍固定。放大时列表可少见几行，详情增加滚动，主要执行和退出不得被挤出。具体字号与字体 fallback 归 Art 共享 Theme，必须用中文真内容检查，不用缺字方框冒充可读。
- 保存中阻止重复存取，完成后明确显示已保存的回合／阶段；失败说明可操作原因，原会话继续有效。读入坏档／版本不兼容不替换当前局。轮末自动保存只在成功安全点发生；结束档仍保留，新局不静默覆盖其回顾。
- 初次打开不自动执行默认事件、不选不可逆动作。没有祈求、没有圣物、资源为零都有可读空态；仍可看历史、改合法计划、承受默认或结束回合。
