# 游戏策划案：邪神苏醒（工作代称）

版本：人物知晓与本次求告接入 · 2026-10-28。

**核心体验：从神的一侧回应祈求，并观看神迹怎样改变人和文明。**

本案把 [原始构思](ori/design-prototype.md)与 [作者已确认决策](progress/decisions-log.md)扩展为可指导实施的完整规则方案。它面向创作者和后续 AI 协作者，不是引擎类图或接口开发文档。具体机制与初始数值是本轮可评审提案，尚未经作者逐项终审或完整玩法验证。

## 2. 产品定位

单人、离线、回合制的邪神叙事策略经营游戏，主要对象用卡牌承载。玩家通过有限注意力和资源，回应凡人的愿望、培养代理人、发展密教、留下不可忽视的异常，直至文明足以容纳邪神的完全苏醒，或者将其抹除。

最优先面向愿意阅读、规划、接受损失并关心人物后果的玩家。卡牌不预设随机抽手牌、构筑战斗牌组或动作战斗；它首先是一种组织人物、机会、媒介和行为的方式。

商业形态以完整买断单人作品为工作假设，不设计微交易、抽卡付费或在线服务依赖。桌面端为第一目标；具体发行平台、售价、销量预估、本地化量和发布日期不在证据不足时作承诺。

“扮演邪神”已有相邻作品，不以市场空白立项。辨识度集中在祈求的神侧回应、持续的人物身份、多种文明的侵入逻辑与可追溯的反作用。搜打撤作为作者提出的反面题材参考保留，尚不据此移植战利品撤离结构。

## 3. 玩家幻想与实际工作

玩家拥有改变命运的力量，但不能随意从混沌跨入现实。每次施力需要联系、见证、信徒或圣物。凡人的理解并不等于神的意图，因此强大与受限同时存在。

一次行动，玩家判断“我回应谁、借助谁、付出什么、把什么后果留给世界”。一轮，玩家协调祈求、教团与正在逼近的反制。一局，玩家在多个文明之间分配有限干预，争取维持足以苏醒的现实锚点。

胜利不意味着宇宙和玩家个体继续存在。完成苏醒使一切归于混沌，是目标完成；寂灭是被文明与自身损耗吞没，是失败。两者都结束本局，保留历史回顾与重新开始入口。

## 4. 体验支柱如何落到规则

**所有选择都有得失。** 浅触保留资源但机会有限；深度干预产生更强收益和暴露；培养信徒获得长期能力，献祭兑现即时收益并永久失去其身份与职务；扎根增加进度，也绑定护持者、圣物和维护支出。不得用不同按钮包装同一条无条件优越路径。

**邪神湮灭是常态。** 允许苏醒倒退、教团覆灭、圣物被夺、代理人死亡与整局失败。风险必须有世界中的原因和适当信息，不用隐藏无条件惩罚冒充残酷。

**世界记得玩家。** 后果记录参与者与原因；事件从真实历史中找对象。保存继续、人物死亡与文明变动不能把身份重置成随机剧情。

**文明差异改变行动。** 不同文明依赖独立见证、持续仪式、共享记忆、契约或例外等不同事实。密教可以秘密发展；公开收录与机构合作是可能的局势，不是普遍许可证。屏障高低不是唯一差别，进入、强化传播、实际扎根与反制要形成不同计划。

**机制先行，美术可替换。** 初期只需看清条件、对象、代价、结果和历史。规则状态不住在按钮或卡面里，后续画风和视听表现不影响同一局的结算。

## 5. 完整游戏流程

### 开始一局

选择新局，获得一个种子与有限世界。工作基线为十二个时空域，开局只认识一个低阶文明；不会把整个宇宙的属性表一次扔给玩家。首轮给出合法祈求与可接触人物，目标是开始建立现实联系；这只保证有行动，不保证成功或保底胜利。

### 每轮

轮初处理到期事实和对象失效，可能出现零至两张主要事件；随后进入自由行动阶段。玩家至多回应一张祈求，可在回应前后行使满足条件的权能，安排教团策略和供奉。结束回合后统一推进文明、人物与教团，结算经济、到期请求与进度，最后检查终局。

玩家可以跳过回应或接受负面事件结果，不能因资源为零卡在强制付费弹窗。已预告的抵抗照常到期，界面容量不足不能让世界停止。

### 前期：获得现实立足点

从陌生祈求人建立具名信徒，聚集无名追随者，满足条件自发形成教团。学习一个文明的实际矛盾，形成真实见证和依赖，取得有来源的最初圣物。第一座锚点之前也能污染，屏障不是全有全无的开关。

### 中期：让神迹成为持续依赖

密教提供收入和执行者；扎根取决于现实中的组织、记录、仪式或关系实际依赖神迹，不要求文明赞同邪神。官方敌对与局部实际依赖可以同时成立；只有口头认可而没有相应事实不能扎根。不同文明的推进方式和反制逐渐交织。玩家开始在培养、传播、隐蔽、维护、牺牲与迁移之间分配行动，苏醒的增长伴随更多暴露与更高层级接触。

### 后期：在反制中维持苏醒条件

维持足够的有效锚点、跨层级资格与信仰储备，发起持续多轮的终极降临。仪式不是进度条满后的免费确认按钮；期间条件丢失可能中断并造成创伤。失败后可能重整，也可能寂灭，取决于仍然存在的局势。

一局暂以六十至一百二十回合作为内容与节奏规划范围，并非强制时间上限或已经测得的游玩时长。实际时长和难度需要完整机制与玩家行为证据后再定。

## 6. 资源与进度的分工

**低语**限制当轮注意力；**信仰**承担跨轮积累与支出；**信众**承担组织规模、供奉和部分牺牲代价；**具名人物**承担属性、职位、关系和不可替代的历史；**圣物**承担媒介资格与一次性转化。

**苏醒**取决于当前有效锚点、有限的洞见与已有创伤。洞见/创伤是进度的来源记录和损失记录，不再各自创造一种日常交易货币。失去一个关键人物或媒介可能让锚点失效，进而真实降低当前苏醒。

信仰增长采用有限人口、递减收入、扩张支出与暴露成本，避免单纯“人口翻倍 → 收入翻倍 → 再翻倍”。历史容量、开支顺序、缺资处理、停供与恢复严格以经济和进度章节为准。

没有宣称这套初始数值已无通解。有限模拟不能证明所有可能策略都平衡；设计通过显式机会成本和实际依赖条件避免明显支配关系，后续用不同局势下的策略表现寻找反例，再单线调整。

## 7. 叙事生成与内容规模

生产目标是可组合的世界规律与有记忆的事件，而不是无限随机段落。

文明由蓝本和有界变化生成；人物先有身份、处境、关系，再产生祈求；成功或失败的回应写入世界状态；事件从这些状态与历史中选择；文本只表达已成立的事实。

作者已确定祈求的两类来源：不知道邪神的人，其无明确指向的求告可由底层联系承接；实际知晓邪神的人可向它定向求告，但知晓不等于信仰，也不表示每次都定向。F关注只管干预与推演分配，取得/撤去关注不增加或抹除知识。TASK-PRAYER-DESIGN将其落实为有限人物知识与求告记录、处境规则及两模式调度方案；这不等于社会传播网络模拟。TASK-PRAYER-KNOWLEDGE已接身份取得、受管理指定告知、本次call及局部保存审计；自动调度、完整来源生产和自然发展仍待下游验收。正式规则唯一见事件、人物与文明spec。

本次给出八个文明蓝本、六个人物原型、十二种权能、六种圣物类型、十二个祈求标杆、十二个后果事件及其二十四个选项，另列六种文明抵抗计划。这些用于明确内容生产标准，完整发行内容量见内容手册的预算提案，不能把模板组合数当作独特玩法数量。

AI 用于制作阶段提出候选、补充变体与检查覆盖；人保有语义、节奏和创作判断。运行时使用经过编辑的内容和确定规则，不依赖在线模型响应，也不让随机文字改写人物生死或资源账本。

## 8. 最简交互与后续表现

首个完整机制版本只需全局读数、文明列表、行动卡项、对象详情、结果历史和菜单/结局六类表面。点击与键盘即可，不把自由拖拽、复杂卡牌物理、动态场景或高级特效作为机制实现前提。

执行前展示资格、全部支出、四档概率和主要后果；执行后展示实际变化和来源。神秘感可以存在于世界的未知部分，不能靠隐藏按钮规则与账目制造。

后续美术阶段可以改变视觉载体、卡面、空间组织、动画与声音，但它们消费同一状态和结算结果。当前不选择画风，不制作概念图，也不把功能界面算作美术验收。

## 9. 技术重难点与历史技术夹具证据

采用 Godot + GDScript。完整技术解释见 [架构](architecture.md)，可复现证据见 [技术报告](qa/technical-feasibility.md)。

**受约束生成：已做技术截面验证。** 一千个种子生成六千文明、十二万 NPC，验证相容条件、ID 与引用，非法组合在有界重试后明确失败。正式八蓝本的全部叙事相容性仍需内容检查，不能由结构校验替代。

**状态演化与因果：已验证基础能力。** 事件前置、冷却、互斥、优先级、到期、人物死亡及后继因果通过；有回合完全没有事件。尚未实现本案全部人物关系、文明策略和终局规则。

**保存与复现：已验证限定环境。** 同种子、同内容、同命令在同引擎下重现；保存后续跑一致，含随机流的大整数状态、死亡人物、物件归属和排队后果；十五类坏存档被拒绝。版本迁移、断电恢复和跨平台逐位一致尚未实现或实测。

**规模与性能：有实测，也有风险。** 两档千回合测试保持全部 NPC 存活。百文明、两千 NPC 的压力样本单回合 p95 约 2.58 毫秒，但完整历史存档约 30.84 MB、序列化约 599 毫秒；生产阶段必须处理历史保留与保存停顿，不能用平均回合很快掩盖保存峰值。

**AI 内容与表现替换：边界明确，品质未证明。** 已验证代表性内容结构拒绝能力；未验证生成模型的文学质量、长篇一致性和人工编辑成本。纯数据模拟不依赖呈现节点，但尚未用正式两个界面视图验证替换效果。

这份历史夹具报告的二十八项技术检查通过，证明相应能力在所测规模可执行；不等于整款游戏技术、经济、叙事和美术全部通过。

另有 [策划结构检查](qa/planning-check-results.json)通过，覆盖数据引用、人物属性范围、事件默认分支、系统依赖与本地链接。可用 `python3 tools/planning-check/check.py` 重跑，不能用它代替对自然语言效果的正式实施。

## 10. 内容与制作范围

第一版机制目标包括：完整开局与结局、单局保存继续、有限世界生成、统一人物与教团、全部资源循环、祈求与十二类权能、文明侵入与抵抗、事件调度、可追溯历史、基础交互。

后置内容包括：正式美术与音频、更多文明及事件族、人物肖像与卡牌动效、长局体验打磨、本地化与各平台导出发布。

本版不承诺：多人、账号服务、运行时自由对话、无限宇宙、完整行星人口逐人模拟、动作战斗、移动端布局、模组工具和云存档。未来加入时需要单独评估对规则、内容与维护成本的影响。

## 11. AI 协作的实施约束

每项工作说明目标体验、归属规则、CSV 来源、跨系统影响和可观察验收。一个逻辑系统只维护一个规则文件；若设计变化，先改规则和数据再让代码跟随，不能由 UI 或测试自行改玩法。

这项约束已落到 [实施追踪](implementation/README.md)：关键行为 REQ、结算约定 SET、开发任务 TASK 与验收 ACC 使用稳定编号连接，工作台新增“实施追踪”视图。正式来源改变会使报告证据过期；缺任务、缺实现、缺证据分别显示。基础任务责任见 [Slice 01](tasks/slice-01.md)，完整回合编排见 [Slice 02](tasks/slice-02.md)，正式经济接入见 [Slice 03](tasks/slice-03.md)，跨系统结算以回合与各归属 spec 为准。

区分四种状态：**设计提案、作者确认、实现完成、验证完成**。测试证明条件/引用正确，不证明故事好、玩家喜欢或不存在全局最优策略。技术夹具与正式数据分开，不把夹具的少数事件伪装成正式内容池。

不设短因果体验、短试玩或灰盒为设计/实施前置阶段。后续直接按 [制作路线](progress/roadmap.md)建立完整机制，同时做必要的技术与规则测试。真人体验属于完整实现后的验证工作，不反向阻止本次策划交付。

正式 NPC／文明推演本轮扩展为基于需要、关系、已知事实与四属性的有限自主行动，以及机构证据驱动的反应；数值来自正式行为与参数 CSV。新的 [正式推演记录](qa/formal-simulation.md)独立报告实际覆盖、对照与负载，不能与前文旧夹具的 28 项检查混算，也不宣称已具备完整人生模拟或已证明叙事品质。

统一六阶段回合已接入上述正式核心，29 组实际检查覆盖事件后果驱动人物行为、共享机会、先付后收、到期死亡／失锚先于终局、阶段回滚及保存续接；原有 32 组核心检查继续独立回归。详见 [完整回合记录](qa/turn-cycle.md)。该套的经济适配只证明编排合同，正式经济由独立规则与套件承担；事件、全部权能和最终胜负仍需后续业务接入。
